# archive: 对话档案

## 意图

将本机可读取的 Codex 与 Claude Code 对话保存为不依赖源文件的知识库记录。

## 外部行为

### archive-1

当同步本机 Codex 会话时，系统应从配置目录及其同级归档目录 `archived_sessions` 中的 `.jsonl` 和 `.jsonl.zst` 文件保存用户和 Agent 可见文本、消息顺序、来源会话 ID、来源路径、时间与工作目录。

### archive-2

当已有会话追加完整记录并再次同步时，系统应只加入尚未导入的消息。

### archive-3

当相同来源被重复同步时，系统应避免重复会话和消息。
来源从普通 JSONL 转为 Zstandard 压缩或迁入归档目录后，会话及消息身份保持不变。

### archive-4

当已导入来源文件被删除时，系统应保留已导入对话和索引。

### archive-5

当来源文件出现无效或未写完的 JSONL 行时，系统应记录错误并保留已成功导入的数据，以便后续重试。

### archive-6

如果服务正在运行且自动同步未暂停，系统应在启动时及此后周期性同步已配置且可读取的来源。

### archive-9

给定本机已安装登录服务，当用户登录时，系统应自动启动本地服务并按已保存的暂停设置决定是否同步 [[archive-6](#archive-6)] [[archive-14](#archive-14)]。

### archive-10

当同步本机 Claude Code JSONL 会话时，系统应把可见用户与助手文本、来源会话 ID、工作目录、时间和顺序保存到同一档案，并标明 Claude Code 来源。

### archive-11

当来源记录包含工具结果、思考、压缩摘要或内部注入上下文时，系统应跳过这些内容，不把它们作为可检索的人机对话 [[archive-10](#archive-10)]。

### archive-12

当某个 Agent 的来源目录不存在时，系统应继续处理其他可用来源并报告该来源不可用，而非中断整个同步。

### archive-14

当用户暂停自动同步时，系统应持久保存暂停状态，使已开始的同步可完成，后续自动同步保持暂停，直到用户明确恢复。

### archive-15

当用户恢复自动同步时，系统应清除暂停状态并启动或复用一轮同步，随后继续周期性同步 [[archive-6](#archive-6)]。

### archive-16

当用户请求立即同步时，系统应执行或复用正在运行的一轮同步并报告结果或进度，保持原有的自动同步设置。

### archive-17

当用户查看同步状态时，系统应提供自动同步是否暂停、当前是否在同步、最近一次已完成同步结果以及各来源的可用性与导入计数。

## 验证

### archive-7

在隔离端到端流程中，首次、追加和重复同步应分别验证 [[archive-1](#archive-1)]、[[archive-2](#archive-2)] 与 [[archive-3](#archive-3)]。
样本应包含普通及压缩文件，并验证压缩后重复导入、归档迁移和压缩文件更新仍保留原文及消息身份 [[archive-1](#archive-1)] [[archive-2](#archive-2)] [[archive-3](#archive-3)]。

### archive-8

在删除来源文件后重新检索、注入未完成行后重试、运行服务和手动同步、安装登录服务时，应分别验证 [[archive-4](#archive-4)]、[[archive-5](#archive-5)]、[[archive-6](#archive-6)] 与 [[archive-9](#archive-9)]。

### archive-13

在隔离样本中同时导入两种 Agent 对话、工具结果和不存在的来源目录时，应分别验证 [[archive-10](#archive-10)]、[[archive-11](#archive-11)] 与 [[archive-12](#archive-12)]。

### archive-18

在已暂停且有待导入记录的档案上重启服务时，验收应检查暂停仍生效 [[archive-14](#archive-14)]，手动同步只执行一轮 [[archive-16](#archive-16)]，状态显示实际结果 [[archive-17](#archive-17)]，以及明确恢复后继续自动同步 [[archive-15](#archive-15)]。
