## 2. 需要处理的问题

### P2：VibeInsight 项目路径变化后，原关联不能跟随，偏离项目身份约定

**依据：** `spec.md:18、33` 要求项目改名后仍识别同一项目及其关联，并以可持续标识识别项目。`vibeinsight.py` 的 `PostgresSource._repo()` 将主机、端口和仓库路径拼成项目身份；`VibeInsightSync._commit()` 又将其作为 `HubProjects.upsert()` 的 `source_key`。验收记录明确说明“VibeInsight 仓库路径变化按新来源身份处理”。

**影响：** 已将设备项目 A 与 VibeInsight 项目 C 关联时，C 的仓库路径改变会产生新 Hub 项目。后续消息进入新项目，A 的旧关联不会自动覆盖这些消息，当前项目检索可能遗漏后续历史。

**已有路径：** 维护者可以重新列出项目，再手工关联新项目；全局检索仍可作为查找入口。这不等于满足关联随改名保持的约定。

**建议与通过条件：** 使用上游稳定项目标识；若上游无法提供，则由维护者确认缩小规格，明确路径变化的身份及关联迁移行为。验收应覆盖“建立关联→仓库路径变化→追加消息→从原关联起点搜索”，确认结果符合重新确认后的约定。

### P2：Skill 同时给出相互冲突的 Hub 检索范围说明

**位置：** `skills/smm-search/SKILL.md:39、46`。

第39行正确说明 Hub 项目检索采用 Hub 的直接关联及返回的有效范围；第46行仍写：

> If `archive_scope` is `hub`, search covered all devices in the hub. Local project IDs do not filter the hub.

实际 `federation.py` 的 `search_archive()` 会将本机项目映射为远程项目键，并传入 Hub 过滤。Hub 返回 `archive_scope="hub"` 并不代表搜索了所有设备的全部项目。

**影响：** Agent 即使成功完成检索，也可能错误报告覆盖范围，或把项目范围内的未命中解释为整个 Hub 没有相关记录。读取和查询入口可用，缺口主要在结果解释。

**建议与通过条件：** 更新第46行，分别说明 Hub 项目检索、全局检索和旧 Hub 的实际行为。给出一个含未关联项目的响应，Agent 应依据 `scope`、`effective_projects` 和回退字段准确描述覆盖范围。

### P2：试用指南将本机 Web 关联入口用于未区分的项目检索说明

**位置：** `TRIAL_GUIDE.md:38、99–107`。

第38行建议“在 Web『项目』中建立关联”，没有限定本机检索；新增第107行则明确在线项目检索使用 Hub 保存的关联。实际 diff 仅提供 Hub CLI 管理关系，没有展示本机 Web 会修改 Hub 关系。

**影响：** 已接入 Hub 的使用者沿“实际提问”进入第38行，可能在本机 Web 建立关系后，仍无法在在线项目检索中找到目标项目。这是局部指引冲突，不能仅归为导航未提供。

**已有路径：** 第97–107行提供了可用的 Hub CLI 管理路径；维护者沿该路径可以建立正确关系，因此并非整体操作被阻断。

**建议与通过条件：** 第38行区分本机与 Hub 关系，并指向 Hub 管理小节。使用者应能判断当前采用哪套关联，并找到修改该关联的实际入口。

### P2：VibeInsight 配置入口没有充分说明连接参数对应的目标及取得方式

**位置：** `TRIAL_GUIDE.md:88–95`；`hub_admin.py` 的 `vibeinsight configure` 参数定义；`vibeinsight.py` 的 `validate()`、`_events_sql()`。

指南要求使用“VibeInsight 数据库的只读账户”，随后给出 host、database、user 示例，但没有说明：

- 需要连接提供特定 `fact_events` 表及字段的 PostgreSQL 数据库，而非 VibeInsight 网站或一般服务地址；
- 这些连接值和只读账户应向谁取得、如何确认对应所需数据范围；
- “全部可读取项目”的授权范围如何在源端确认。

CLI 为这些必填参数提供了名称，但没有补充目标数据库约定。实际查询使用未限定 schema 的 `fact_events`，因此连接成功本身也不足以解释适配要求。

**影响：** 对已有正确数据库连接信息的维护者，配置路径可用；对只有 VibeInsight 产品访问权限的 Hub 管理员，材料不足以支持其独立取得前置条件。验证命令能拒绝错误配置，但不能替代配置前的说明。

**性质：** SPEC 未明确规定这些说明内容，属于使用路径缺口，不宜直接判为同步实现违反规格。

**建议与通过条件：** 补充最小的上游数据库适配要求、连接信息取得途径和权限范围确认方式。维护者应能判断自己持有的信息是否适用，缺少时知道向上游管理员索取什么。
