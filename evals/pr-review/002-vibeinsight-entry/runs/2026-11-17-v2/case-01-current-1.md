### 3. 需要修改或确认的问题

**[P1] VibeInsight 项目改名后可能丢失原关联，违反当前 SPEC。**

位置：`src/smm_hub/vibeinsight.py` 的 `PostgresSource._repo()`、`VibeInsightSync._commit()`；`src/smm_hub/projects.py:66–78`。

项目身份直接使用规范化仓库路径，随后以 `(kind, owner, source_key)` 查找项目。路径改变会创建新项目；关联仍留在旧项目 ID。验收记录也明确采用这一行为，而 `spec.md:18、47` 要求改名后关联有效。

需要二选一：

- 实现稳定项目身份及改名后的关联保持，并验证旧关联仍能命中新内容。
- 明确区分“显示名修改”和“仓库路径变化”，更新 SPEC 并重新确认，文档说明后者如何迁移关联。

当前仅验证设备显示名修改，不能据此将整项改名验收记为通过。

**[P2] Skill 对 Hub 检索范围的说明相互冲突。**

位置：`skills/smm-search/SKILL.md:39、46`。

第 39 行要求采用 Hub 返回的有效项目范围；第 46 行仍写“`archive_scope` 为 `hub` 就覆盖所有设备，本地项目 ID 不过滤 Hub”。当前 `federation.py` 会把本地项目 ID 转换成稳定 key，Hub 据此过滤项目。

这会让 Agent 将项目检索误报为全局覆盖。应修改第 46 行：`archive_scope` 说明执行档案，实际项目范围以返回的 `scope` 和 `effective_projects` 为准。

**[P2] 指南仍把建立关联指向本机 Web，容易让用户配置错位置。**

位置：`TRIAL_GUIDE.md:38` 与新增的 `97–107` 行。

第 38 行建议到 Web“项目”建立关联；新行为则从 Hub 读取关联。材料中的 diff 没有把 Web 关系同步到 Hub 的实现。

应明确：显式本机检索使用本机关系；Hub 检索需由维护者使用 Hub CLI 管理关系。现有后文虽介绍了 CLI，但没有消除前文入口的歧义。
