### 1. 发现的问题

**① 应修正：Skill 对 Hub 检索范围的说明前后冲突。**

位置：`skills/smm-search/SKILL.md:39、46`。

第 39 行新增说明：Hub 使用当前项目及 Hub 中的直接关联，并要求依据返回的实际范围报告。第 46 行却仍明确指示：

> If `archive_scope` is `hub`, search covered all devices in the hub. Local project IDs do not filter the hub.

当前实现已经将本机项目 ID 转换为稳定项目标识，发送到 Hub，并返回实际项目集合，见 `src/smm_local/federation.py::_remote_project_key、search_archive` 和 `src/smm_hub/hub.py::search`。

受影响的是通过 Agent 搜索项目历史的用户。检索本身可以正确过滤，但 Agent 可能把项目范围结果解释为整个 Hub 的搜索结果，误导用户判断“其他项目是否存在相关历史”。这不阻断查询，但直接影响范围解释的可信度，与 SPEC 第 24 行要求标明实际检索项目的目标冲突。

建议通过条件：Skill 对 Hub 范围只保留一致规则，依据返回的 `scope`、`effective_projects` 和回退信息解释结果；项目检索不得被描述成全局检索。

**② SPEC 未覆盖的路径缺口：普通用户可能被引向不生效的关联配置入口。**

位置：`TRIAL_GUIDE.md:38`。

这里告诉用户“也可以在 Web『项目』中建立关联”，没有区分本机关系与 Hub 关系。对于 Intent 中已接入 Hub、希望搜索其他电脑或 VibeInsight 项目的用户，这会形成如下路径：

自然语言搜索 → 发现范围不足 → 阅读“实际提问” → 在本机 Web 建立关联 → 再次查询 Hub。

但当前实现使用 Hub 保存的关系；本机关系用于显式本机检索，见 SPEC 第 24、26 行及 Skill 第 39 行。因此，这条可见指引不能完成用户预期的 Hub 关联配置。

已有可用路径是 `TRIAL_GUIDE.md:97–107` 的 Hub CLI 管理说明。操作能力并未缺失，但用户需要自行发现两种关联的区别，可能重复配置或误判功能无效。

建议在第 38 行附近区分本机与 Hub，并链接到“管理汇总端的项目关联”。通过条件：已接入 Hub 的用户从“实际提问”出发，能找到管理员应执行的 Hub 操作，知道本机 Web 关联不会改变 Hub 查询范围。

**③ SPEC 未覆盖的发现难度：主入口没有介绍 VibeInsight 能力及适用对象。**

位置：`README.md:33–50`。

README 的多机章节介绍部署、凭证和断线回退，但没有说明 Hub 可同步 VibeInsight，也没有说明跨设备项目关联由管理员配置。第 50 行确实提供了可达的“安装与使用指南”，因此不能认定详细指南不可达；用户进入指南并继续阅读，可以找到第 86、97 行的两个新增章节。

问题在于链接的引导文字只列举“证书信任、各平台服务配置、升级和卸载”。目标用户在 README 上没有足够线索判断，该指南还包含自己需要的 VibeInsight 接入和关联配置。

这增加发现难度，不构成操作阻断，也不是“README 必须修改”的规格要求。

建议通过条件：在 README 或其他清晰可达的主要入口中，简短介绍能力、适用对象，并提供能辨认目的的指南链接；无需重复详细命令。
