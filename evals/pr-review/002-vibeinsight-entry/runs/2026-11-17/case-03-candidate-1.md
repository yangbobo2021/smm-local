## 3. 发现的问题

**① Skill 对 Hub 搜索范围的旧说明与新增行为冲突，应修正。**

位置：`skills/smm-search/SKILL.md:46`：

> “search covered all devices in the hub. Local project IDs do not filter the hub.”

同一文件 `:39` 已要求按当前项目查询，并说明 Hub 采用自己的项目关联；实现中 `federation.py` 的 `search_archive()` 将本机项目 ID 转换为稳定远端标识，Hub 再按有效项目范围过滤。

受影响的是通过 Agent 搜索的日常用户：Agent 可能正确执行项目查询，却将结果解释为覆盖整个 Hub，降低用户对“没有找到”的判断准确性。已有可用路径是 `:39` 的指引和响应中的 `effective_projects`，所以这是**说明矛盾与范围解释风险，不是搜索阻断**。

该问题属于计划要求更新 Skill 指引时留下的不一致；材料未证明实际回答已违反 SPEC。建议改为：Hub 项目查询按返回的有效项目集合执行；全局查询覆盖 Hub 可检索档案。通过条件是 Skill 不再笼统宣称 Hub 查询不受项目限制，Agent 能分别准确解释项目、全局和断线回退响应。

**② 普通提问指南仍可能把 Hub 用户引向本机项目关联，属于 SPEC 未覆盖的路径缺口。**

位置：`TRIAL_GUIDE.md:38` 写着“也可以在 Web『项目』中建立关联”，没有说明其适用档案；而 `:107` 和 Skill `:39` 明确在线项目检索使用 Hub 关联，Hub 关系由管理 CLI 配置。

受影响的是沿“实际提问”章节操作的 Hub 用户：可能在本机建立关系后，仍无法改变在线检索范围。已有清晰路径是文档首页 `:8` → Hub 项目关联章节，因此不能认定关联功能不可发现。

建议仅在 `:38` 补充分流：本机检索使用本机关系；Hub 检索请维护者按关联章节配置。通过条件是用户从“实际提问”章节能判断关系应配置在哪里，并能直接到达适用指南。是否纳入本次变更由维护者决定。
