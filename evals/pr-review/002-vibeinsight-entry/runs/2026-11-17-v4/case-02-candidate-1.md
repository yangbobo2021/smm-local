结论：实现与更新后的 PLAN 总体一致，已有较强的功能验收记录；但用户指引中存在两处明确冲突，VibeInsight 配置的前置条件也不够完整。建议修正后再合并。以下仅依据提供材料，未重跑测试。

## 审查发现

### 1. Skill 仍要求把所有 Hub 搜索解释为跨全部设备，可能误报实际检索范围

**性质：与 SPEC 明确冲突。**

位置：`skills/smm-search/SKILL.md:39、46`。

第 39 行已经要求按 Hub 返回的有效项目范围报告；第 46 行仍写：

> If `archive_scope` is `hub`, search covered all devices in the hub. Local project IDs do not filter the hub.

本次实现恰好改变了这一行为：`src/smm_local/federation.py` 的 `search_archive()` 将本地项目转换为稳定远端键，传给 Hub；Hub 据此限制当前项目和直接关联项目。SPEC 第 24 行要求 CLI/MCP 标明实际检索项目。

受影响的是通过 Skill 搜索的用户及执行指引的 Agent。搜索本身可以成功，但 Agent 可能把一次限定项目的查询说成覆盖全部设备，使用户错误判断遗漏范围。

**建议：**更新第 46 行，分别解释 Hub 项目搜索、Hub 全局搜索和本机回退；统一以返回的 `scope`、`effective_projects` 和 `fallback_reason` 为准。

**通过条件：**按 A 查询且返回 A、B、C 时，Skill 指引只能支持报告该范围；全局查询才报告汇总档案全局范围。

### 2. 使用指南仍把 Web 项目关联作为通用操作入口，未区分本机关联与 Hub 关联

**性质：SPEC 未覆盖完整用户导航，但现有指引与本次行为产生冲突。**

位置：`TRIAL_GUIDE.md:38、97–107`；`README.md:91`。

用户从 README 快速开始进入指南“实际提问”，第 38 行告诉用户：

> 也可以在 Web「项目」中建立关联。

但本次 Hub 搜索使用的是 **Hub 保存的关联**，新增指南第 99–105 行提供的实际管理入口是 Hub CLI。材料未展示 Web 项目页能够管理 Hub 关联。

受影响的是已经连接 Hub、希望扩大当前项目检索范围的用户。其按通用指南进入 Web 建立本机关联后，不能据此确认 Hub 搜索范围会扩大。已有可用路径是 README 第 52–57 行直接链接的“管理汇总端的项目关联”，因此不是所有用户都无法完成操作。

**建议：**在通用检索说明中区分本机与 Hub 关联，并就近链接已有 Hub 管理章节；README 第 91 行也可作同样限定。

**通过条件：**已连接 Hub 的用户从“实际提问”出发，能够判断应由谁、在哪管理关联，并通过查询返回的有效项目集合确认生效。

### 3. VibeInsight 配置入口可达，但只读账户和连接参数的准备说明不足

**性质：规格未覆盖的前置条件说明缺口，交维护者决定是否纳入本次。**

位置：`README.md:56`；`TRIAL_GUIDE.md:88–95`；`src/smm_hub/vibeinsight.py` 的 `validate()`、`_command()`。

README 明确承诺链接可用于“准备数据库只读账户和 PostgreSQL 客户端”。目标章节说明了 `psql` 的执行账户、密码输入和绝对路径，信息有用；但对数据库一侧只要求“用只读账户配置连接”，随后给出示例主机、数据库和用户名。

实际实现要求账户能读取 `fact_events` 的指定字段，包括事件、会话、正文和仓库字段。指南没有说明：

- 应向谁取得或确认实际连接参数；
- 应连接哪类 VibeInsight 数据库及所需表、字段权限；
- 如何确认账户可见项目正是获准汇总的范围。

这会影响首次接入的 Hub 维护者。已有正确账户和连接参数的人可以继续配置，命令也会验证读取权限；缺少这些条件的人则可能停在配置前，或失败后仍不知道应申请什么权限。不能据此认定功能实现失败。

**建议：**补充简短的数据库侧准备清单，注明账户申请或确认对象、所需表字段权限，以及“全部可读取项目都会同步”的范围确认要求，无需扩展成完整数据库运维教程。

**通过条件：**首次接入维护者能据指南向数据库管理员提出明确申请；配置成功后，再以状态、项目列表及一条原文读取确认接入结果。
