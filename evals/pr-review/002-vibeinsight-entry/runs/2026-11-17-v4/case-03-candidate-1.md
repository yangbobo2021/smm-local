### 审查发现

**1. Skill 对 Hub 检索范围的说明互相冲突，可能让 Agent 错报实际搜索范围。**

- 位置：`skills/smm-search/SKILL.md:39、46`。
- 性质：交付指引与 SPEC 24 要求不一致。
- 受影响对象：调用 MCP/CLI 的 Agent，以及依赖其回答的日常用户。
- 第 39 行正确说明 Hub 项目检索使用 Hub 的直接关联，并要求按返回的有效范围报告；第 46 行却仍断言 `archive_scope=hub` 就覆盖全部设备，且本机项目 ID 不过滤 Hub。
- 实际实现中，`src/smm_local/federation.py` 的 `search_archive` 会把本机项目转换成稳定标识传给 Hub；`src/smm_hub/hub.py` 的 `search` 返回实际项目集合。因此，第 46 行已经不能作为统一规则。

这不会阻断搜索，但可能使 Agent 将项目范围结果描述成覆盖整个 Hub，影响用户对“没有找到”的理解。已有可用路径是第 39 行及返回的 `effective_projects`。

建议改为：Hub 实际范围以响应中的 `scope` 和 `effective_projects` 为准；全局请求才覆盖整个汇总档案。通过条件是项目检索、全局检索及断线回退三种响应都能得到一致、准确的范围描述。

**2. VibeInsight 配置指南没有交代连接参数和只读账户的取得、确认方式。**

- 位置：`TRIAL_GUIDE.md:88–95`；对应局部 CLI 参数定义位于 `src/smm_hub/hub_admin.py` 的 `add_arguments`。
- 性质：SPEC 未明确覆盖的操作路径缺口。
- 受影响对象：负责首次接入的 Hub 维护者。
- 指南提供了 `db.example.net`、`vibeinsight`、`reader` 示例，并要求使用只读账户，但没有明确这些值应向谁取得、如何确认数据库名和账户，以及需要读取哪些源数据。
- 实现的 `PostgresSource.validate` 实际查询 `fact_events` 的指定列。普通 PostgreSQL 只读账户或任意 VibeInsight 数据库连接，并不因此必然满足该要求。

维护者若已取得兼容连接，可以按现有命令完成配置，命令也会验证读取权限；因此不能认定所有用户都被阻断。但仅依靠本指南准备环境的维护者，无法完成前置条件获取，遇到权限错误时也缺少明确的核对目标。

建议补充最小接入说明：示例参数须替换成源数据库管理员提供的实际值，账户需要可读取当前适配的 `fact_events` 数据及所需字段，并说明可读取项目即自动同步范围。交维护者决定是否纳入本次。通过条件是首次接入者能据此向管理员提出明确请求，并用配置命令确认连接与权限。

**3. 新增文档入口没有同步记入实施计划及调整原因。**

- 位置：`plan.md:7–13`；diff 中的 `README.md:50` 和新增 `docs/index.md`。
- 性质：计划记录偏差，违反 `AGENTS.md:30–31` 对修改位置变化的记录要求。
- 计划仅列出更新 `TRIAL_GUIDE.md`，实际还调整了 README 的导航并新增统一文档首页，没有在计划中说明这项扩展及原因。

这项扩展改善了用户发现能力的路径，不构成运行阻断。建议在计划中补记两处文档及建立统一入口的目的，无需撤回现有导航。
