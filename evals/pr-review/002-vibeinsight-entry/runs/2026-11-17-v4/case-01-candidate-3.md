## 3. 审查发现

### P1：Skill 对 Hub 检索范围给出相互冲突的指令

**位置：** `skills/smm-search/SKILL.md` 第39、46行。

第39行已要求 Hub 项目检索采用 Hub 的关联，并按返回的实际范围报告；第46行仍说：

> If `archive_scope` is `hub`, search covered all devices in the hub. Local project IDs do not filter the hub.

新实现会将本地项目映射为远端项目标识，并发送项目范围，见 `src/smm_local/federation.py` 的 `search_archive` 修改；Hub 返回实际项目集合。

**影响：** Agent 可能把成功的项目检索解释为覆盖整个 Hub，使用户误判回答或“没有结果”的覆盖范围。搜索和读取本身仍可完成，问题在结果解释。

**性质：** 明确的行为说明冲突，涉及 SPEC 第24行要求的实际范围展示，以及 PLAN 第11行的 Skill 更新。

**建议及通过条件：** 将第46行改为根据返回的 `scope`、`effective_projects` 判断范围，保留本机回退说明。对项目、全局及回退三种响应，Skill 均应指导 Agent 报告正确范围。

### P2：既有“建立关联”指引未区分本机与 Hub，可能引导用户配置无效范围

**位置：** `TRIAL_GUIDE.md` 第38行与第97–107行。

用户从“实际提问”进入时，第38行告诉用户可以在 Web「项目」中建立关联；新增第107行则说明在线查询使用 **Hub 保存的关联**，管理操作位于 Hub CLI。

**影响：** 已接入 Hub 的用户可能在本机 Web 建立关系后，期待远端查询随之扩大。该路径不能完成 Hub 关联配置，但维护者仍可通过第99–105行的 CLI 正确完成，并非能力整体不可用。

**性质：** 规格未明确规定导航文案，但这是已展示局部入口中的范围指引缺口。

**建议及通过条件：** 在第38行区分本机搜索与 Hub 搜索，并链接到 Hub 项目关联章节。用户应能从实际提问说明判断关系应配置在哪里，以及需要由谁操作。

### P2：主入口未介绍 VibeInsight 同步及 Hub 关联能力，详细指南的入口语义不足

**位置：** `README.md` 第33–50行；`TRIAL_GUIDE.md` 第86–107行。

README 的多机章节只介绍设备共用档案。第50行虽然能进入包含新内容的指南，但链接上下文仅列举“证书信任、各平台服务配置、升级和卸载”。目标维护者无法从这里知道指南还包含 VibeInsight 来源接入和跨来源项目关联。

Skill 第39行提供了另一条发现 VibeInsight 的线索，但没有提供维护配置说明的下一跳。

**影响：** 详细说明实际可达，愿意继续浏览整份指南的维护者能够找到；缺口增加发现难度，不能据此判定操作被阻断。

**性质：** 规格未覆盖的能力发现缺口；PLAN 要求的指南更新已经完成。

**建议及通过条件：** 在现有多机入口简要说明适用对象及新能力，并提供有明确文字的章节链接即可，无需重写 README。维护者应能从主入口识别能力并进入对应操作说明。

### P2：来源配置章节未说明如何确认真实连接参数与获准同步范围

**位置：** `TRIAL_GUIDE.md` 第88–95行；`src/smm_hub/hub_admin.py` 新增 `configure` 参数。

局部说明要求只读账户，并提供 `db.example.net`、`vibeinsight`、`reader` 示例，但未说明真实数据库地址、数据库名、账户及密码应向谁取得或确认。参数帮助也未补充这些信息。

更关键的是，第95行明确会同步连接可读的**全部项目**，但未说明维护者如何确认该账户的可读项目就是获准纳入的范围。连接验证只证明能够读取所需字段，不能代替范围确认。

**影响：** 已掌握数据库信息且已确认授权范围的维护者可以操作；其他维护者无法仅凭本节完成前置条件准备。材料不能证明实际发生了越权同步。

**性质：** 规格未覆盖的前置条件说明缺口，与 Intent 第24行“只同步获准纳入的项目”有关。

**建议及通过条件：** 补充向 VibeInsight 数据库管理员取得连接信息及专用只读凭据，并在配置前确认可读范围等于获准范围。无需加入凭据原值或额外管理系统；读者应能判断示例值需要替换，以及由谁确认范围。
