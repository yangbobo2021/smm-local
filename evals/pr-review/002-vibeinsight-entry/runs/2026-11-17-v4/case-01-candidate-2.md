**审查发现**

1. **中：Skill 对 Hub 检索范围的说明自相矛盾，可能导致调用方错误报告范围。**

   `skills/smm-search/SKILL.md:39` 新增说明要求使用 Hub 的直接关联及返回的实际范围；但第 46 行仍断言“`archive_scope` 为 `hub` 就覆盖全部设备”“本机项目 ID 不过滤 Hub”。

   实现已经在 `src/smm_local/federation.py::_remote_project_key/search_archive` 中将本机项目映射为稳定标识，传给 Hub 过滤。Agent 按第 39 行执行后，仍可能按第 46 行把项目查询解释为全局查询，影响用户判断搜索覆盖和遗漏。实际搜索和精确读取路径仍可用，不能据此认定检索功能失效。

   建议统一说明：`archive_scope` 表示档案位置，`scope`、`effective_projects` 表示实际范围，并注明旧 Hub 的兼容行为。通过条件：面对项目 Hub、全局 Hub、断线回退三种响应，指引能让 Agent 分别准确报告范围。此项直接影响 SPEC 第 24、26 行的范围告知。

2. **中：用户可达的通用指南把关联配置引向本机 Web，未在决策处区分 Hub 关联。**

   用户从 README 的自然语言搜索入口进入，经 README:50 的链接可到 `TRIAL_GUIDE.md`。其第 38 行告诉项目搜索用户“也可以在 Web『项目』中建立关联”；本次新增第 107 行和 Skill:39 则明确，在线项目搜索使用 Hub 保存的关联。

   因此，希望加入另一台电脑或 VibeInsight 项目的用户，在实际提问章节会得到不适用于该查询的配置方向。已有可用路径是指南第 97–107 行的 Hub CLI，但第 38 行未告知应改走此路径。影响是配置错误位置及排障成本，不能断言所有用户都无法完成关联。

   建议在第 38 行区分本机与 Hub，并直接链接 Hub 关联章节。通过条件：已接入 Hub 的用户从“实际提问”章节能判断由谁、在哪里配置关联，并找到对应命令。属于 SPEC 未明确覆盖的用户路径缺口，建议维护者纳入本次修订。

3. **中：VibeInsight 配置局部说明未交代连接参数及只读权限的取得方式。**

   `TRIAL_GUIDE.md:88–95` 已说明安装 `psql`、服务账户可执行、密码输入、同步周期及状态查看，但第 91 行要求填写的数据库主机、数据库名、用户名只有示例，没有说明向谁取得、如何确认这些是 VibeInsight 源数据库参数，也未说明实际读取所需的数据接口和权限。

   实现 `src/smm_hub/vibeinsight.py::PostgresSource.validate` 直接读取 `fact_events` 及指定字段；查询使用未限定 schema 的表名。这意味着“有一个只读账户”未必足以完成配置。现有权限验证会拒绝不合适的连接，已经掌握正确数据库信息的维护者仍有完整操作路径。

   建议补充由 VibeInsight 数据库维护者提供的参数清单、`fact_events` 的可见性及必要读取权限，并说明默认同步该账户可读的全部项目。通过条件：获授权的 Hub 维护者能据说明向源端管理员索取完整配置，并判断验证失败需要补充什么。属于规格未覆盖的前置条件交接缺口；不应扩大为所有部署均被阻断。

4. **低：主入口能到详细指南，但没有介绍新增能力及目标使用者，增加发现难度。**

   README:33–50 介绍多机共用档案，第 50 行以“证书信任、各平台服务配置、升级和卸载”链接指南。该链接确实能到达新增章节，因此不存在完全不可达的问题；但 README 未介绍 VibeInsight 同步或 Hub 跨来源关联，链接文字也未提示相关内容。README:100–104 的“其他本机 Agent”是另一条本机适配路径，不能替代本次 Hub 同步入口。

   已知功能名称的维护者可沿指南找到第 86、97 行；只从 README 了解产品的目标用户则较难发现本次能力。

   建议在现有多机章节用简短说明介绍能力、适用对象，并链接两个现有章节。通过条件：用户无需预先知道命令或文档标题，就能从 README 识别该能力及下一步入口。属于规格未覆盖的发现性补充建议，不是固定要求修改 README。
