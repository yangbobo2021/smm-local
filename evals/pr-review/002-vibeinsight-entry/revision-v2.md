# 候选 Prompt v2 的调整范围

v1 强调从项目主入口开始回放，但旧 CLI 帮助样本只提供局部命令帮助。
Reviewer 因整体导航不完整，将局部帮助已经暴露的信息缺口一并归为材料不足。
v2 增加了在已有证据范围内检查局部入口的要求，并将整体路径的不确定性单独记录。

v2 按变更影响选择审查路径。使用者、调用方及维护者都是可能的受影响对象，
入口可以来自界面、命令、接口、配置、帮助或文档。
需要发现能力或调整用法时，再向外检查项目提供的发现入口。
因此内部实现、修复、配置和文档变更也可以沿各自相关路径审查。

对必要输入的说明，统一检查含义、适用取值以及取得或确认方式。
候选没有写入 VibeInsight、README、来源 ID、批次 ID 或某条具体命令。
也没有规定所有变更必须更新某个文件或补齐整个项目的文档。

实现、计划、规格和验收证据仍须核对。局部信息缺口、明确违反规格和未获证据的推测，
各自保留适用范围。已有可用入口及替代路径须如实记录。

本轮继续使用原四个样本及原评分规则，真实样本每版重复三次，其他样本每版一次。
当前 Prompt 也重新执行，总计 12 次审查，并进行匿名评分。
原始样本、规则和运行器的哈希均保持原值，复跑清单只替换候选 Prompt 的哈希。
旧轮结果保留，新轮输出位于 `runs/2026-11-17-v2/`。

文本的适用范围覆盖本项目各种变更。当前 EVAL 主要验证文档发现、导航和 CLI 帮助，
对其他变更类型的审查表现仍需各自样本检验。
