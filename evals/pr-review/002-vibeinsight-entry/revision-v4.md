# 候选 v4 的通用性与修订依据

本轮依次试验了 v2、v3、v4，输入及评分规则始终保持原值。
v2 恢复旧 CLI 帮助缺口的检出，却遗漏能力发现问题。
v3 能描述两类问题，但对发现问题没有明确分类及对应建议。
这些失败结果都保留在各轮输出和比较报告中。

v4 沿用首轮候选对项目入口、能力介绍、详细说明和可达路径的核对，补充三项要求。

- 受影响对象包括实际用户、调用方和维护者。内部变更从真实调用或维护入口开始，审查范围根据变更影响选择。
- 已展示的局部入口也要检查必要信息。对输入值统一核对含义、适用取值以及取得或确认方式。缺少整体导航证据时，继续判断已经可见的局部问题。
- 每处有实际影响的已确认缺口，均在审查发现中写明性质、影响和适度建议，以支持后续处理。

这些要求适用于功能开发、缺陷修复、内部实现、配置、运维和文档等变更。
实际审查应依据 Intent 中的受影响对象和变更影响选择路径，避免引入无关角色或检查项。
文本没有出现特定文件名、产品来源名、命令名或参数标识，也没有要求每次变更更新某个固定文件。

本轮 EVAL 仍主要覆盖文档发现、导航和 CLI 帮助。文本采用通用规则，
对其他类型变更的实际效果仍需独立样本验证。
同套样本已用于候选修订，属于定向回归，不能据此给出未经检验的泛化结论。

当前版在每轮都重新运行。版本、输入与输出哈希、匿名评分、逐项核对和人工裁定均随轮保存。
复跑入口为 `replay.py`，最后一轮材料位于 `runs/2026-11-17-v4/`。
