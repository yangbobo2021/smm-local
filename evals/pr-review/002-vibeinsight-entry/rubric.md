# PR Review 评分规则

本文件只提供给评分者。待测 Reviewer 仅收到一版 Prompt 和一个 case 的 input。
每项 0 或 1 分，接受语义等价表述。每项保留 Reviewer 的原文摘录和证据位置。
评分依据最终回答，过程中的猜测须进入最终结论才能得分。

## Case 01

PR #21 的真实固定样本。五项全部通过才算通过。

| 项目 | 1 分条件 |
| --- | --- |
| P1 发现入口缺口 | 指出 README 没有介绍 VibeInsight 同步或 Hub 跨来源项目关联，也没有明确的该功能入口，影响用户发现及开始使用。只要求 README 改动而没有用户影响不得分。 |
| P2 准确还原现状 | 承认 TRIAL_GUIDE 已有配置和关联说明，同时承认 README 有通用的指南链接。不能声称完全没有文档或不存在可到达路径。 |
| P3 可复核依据 | 引用 README 的多机说明或通用指南链接位置，以及 TRIAL_GUIDE 的新增功能位置。接受准确摘录或行号。 |
| P4 适度修复 | 建议在主入口介绍新能力并直接指向详细指南，允许详细步骤保留在指南中。强制重复全部说明或规定所有功能 PR 都要改 README 不得分。 |
| P5 缺口性质与影响 | 识别为 PLAN/SPEC 明文验收之外的用户发现或上手路径缺口，说明发现成本或误解风险。若声称功能必然不可用或原 SPEC 明文要求修改 README，不得分。 |

## Case 02

受控对照。在 Case 01 的首页加入能力介绍、适用对象和直达指南链接，其余相同。

| 项目 | 1 分条件 |
| --- | --- |
| C1 导航判断 | 明确指出首页已经介绍新能力并有具体入口，或完整回放该路径后判定此项可用。 |
| C2 详细指南 | 确认指南含连接依赖、配置、状态和项目关联操作。 |
| C3 路径依据 | 引用本对照中新加的首页入口与实际指南。 |
| C4 控制误报 | 不报告“首页未介绍新能力”或“缺少该功能入口”，不把仍需优化的措辞夸大为缺失。 |
| C5 结论范围 | 承认该导航路径完整，其他功能缺陷须有独立依据，不要求机械更新固定文件或复制指南。 |

## Case 03

受控对照。公开入口使用文档站首页，README 清楚指向该入口。
文档站首页介绍能力并直接链接现有详细指南，其余相同。

| 项目 | 1 分条件 |
| --- | --- |
| D1 入口识别 | 识别文档站首页为声明的使用入口。 |
| D2 路径判断 | 确认 README → 文档站首页 → VibeInsight/项目关联指南的路径可达。 |
| D3 证据 | 引用 README 的文档站链接、文档首页能力说明和指南操作。 |
| D4 控制误报 | 不因 README 未重复能力介绍而判定新功能入口缺失。 |
| D5 适度建议 | 接受现有路径，不强制 README 重复详细说明，不虚构不可用或缺失文档。 |

## Case 04

沿用 `../001-source-cli-help/rubric.md` 的原有五项标准，检查候选 Prompt 是否保留旧样本中发现参数信息缺口的能力。两个版本均获得同一份旧样本材料。

## 比较方法

执行前冻结 Prompt、输入、评分规则及运行顺序的 SHA-256。Case 01 每版执行三次，
Case 02、03、04 每版各一次，总计 12 次。每次使用全新上下文，无聊天历史，
不向 Reviewer 提供本规则、样本结论、其他 Prompt 或既有审查结论。
同一运行配置、材料和输出约束下，只替换待测 Prompt。

分别报告 Case 01 的通过次数及每项得分、Case 02/03 的误报、Case 04 回归结果。
技术失败单独报告，不算审查失败。运行成功表示返回审查结果，结果是否通过由规则判定。
独立评分时隐藏 Prompt 版本及运行次序，评分后核对原文摘录。
本轮样本量用于比较这组固定材料上的表现，不据此推断总体准确率或因果结论。
Case 02/03 是本轮人工构造的对照，须与真实历史样本分清。
