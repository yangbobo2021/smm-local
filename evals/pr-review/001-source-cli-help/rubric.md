# PR Review 评分：来源管理命令帮助

每次在独立上下文中仅提供 `input.md` 和一版待测 Prompt。按下表逐项评分，
摘录 Reviewer 的判断和依据。回放使用历史 PR 的输出和测试记录。

| 检查项 | 通过标准 |
|---|---|
| 1. 对照 PLAN | 判断代码和验证符合原 PLAN。引用 diff 中的 CLI 帮助改动及测试，或结合实际输出与测试记录说明依据。 |
| 2. 对照 SPEC 与证据 | 判断原 SPEC 的三项验收均有对应证据。核对总帮助的 8 条用途、两处停用提示、子命令的两个位置参数及成功退出，区分历史记录和本次实际执行。 |
| 3. 发现来源参数缺口 | 引用子命令帮助里只有 `source_id` 参数名的事实，并指出用户无法从这里确认要填哪个来源 ID、如何取得该值。 |
| 4. 发现批次参数缺口 | 引用子命令帮助里只有 `batch` 参数名的事实，并指出用户无法从这里确认要填哪个批次 ID、如何取得该值。 |
| 5. 判定缺口的性质 | 将第 3、4 项识别为超出旧 SPEC 明文验收的用户路径缺口，指出需要维护者确认是否扩展规格。无需从历史材料推断具体查询命令。 |

五项均通过才算本次 Review 通过。接受语义等价的表述。笼统建议「增强帮助」或
只确认参数名存在，无法通过第 3、4 项。
