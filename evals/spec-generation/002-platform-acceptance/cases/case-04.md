# SPEC 生成输入

## 生成指令

使用单独提供的 SPEC 模板，根据以下已确认意图和项目资料，起草供维护者审阅的规格。
直接输出规格正文，以材料为准，不执行测试或修改文件。缺少决定所需信息时在草稿中标明。

## 已确认意图

维护者希望在机器重启后，Hub 自动拉取已配置来源的新对话，不再手动运行一次同步命令。
服务启动时沿用已有来源凭据和数据库进度；启动同步失败时报告失败原因，已有归档仍可检索。
重试不能重复导入消息。

## 项目资料

- 本样本的 Hub 交付范围明确只有 Linux systemd 用户服务。Hub 在 Windows/macOS 的运行方式不受支持，
  也没有将其纳入本次交付的需求。
- Windows、macOS、Linux 都有本机客户端，通过既有 HTTPS 协议访问 Hub。
- 此次仅把 Hub 已有的一次同步操作接入 systemd 服务启动后的生命周期。
  同步算法、API、CLI/MCP、客户端程序及配置格式不变。
- 已有凭据位于 Hub 用户状态目录，只有相应 Linux 服务账号能读取。服务环境与交互式登录环境可能不同。
- 当前开发电脑为 macOS，可以运行共用逻辑测试，但不能运行 Linux systemd。
  没有本次 Linux 服务启动或重启后的执行记录。
