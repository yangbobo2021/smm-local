# SPEC 生成输入

## 生成指令

使用单独提供的 SPEC 模板，根据以下已确认意图和项目资料，起草供维护者审阅的规格。
直接输出规格正文，以材料为准，不执行测试或修改文件。缺少决定所需信息时在草稿中标明。

## 已确认意图

SMM 的 Hub 接收多台电脑上传的对话。目前 VibeInsight 中另有历史，用户仍需分别查找。
本次让 Hub 自动同步 VibeInsight 可读取的全部项目历史，持续同步新会话和旧会话追加的轮次，
让用户通过现有 CLI/MCP 检索并读取原文。项目关联由 Hub 维护者统一管理，可连接设备项目与
VibeInsight 项目，也可连接不同设备项目。关系双向、只扩展一层。解除关联不删除归档。

维护者通过 Hub CLI 验证并保存来源连接和凭据。Hub 重启后自动继续，无需重新输入密码；
无效凭据不能覆盖原有效配置。来源失败后已有归档仍可查，恢复后重试未成功的数据，重复读取去重。
来源后来新增可读项目时，早于已有进度的历史仍需补齐。CLI/MCP 返回来源、项目、原会话和消息位置，
可精确读取对应原文。Hub 不可用时沿用本机全局回退，兼容旧客户端全局查询。

首版单用户，仅支持新增会话事件与追加轮次，不发现没有新增事件的历史正文原地改写。
本次没有要求改变已支持的部署平台或服务运行方式。

## 项目资料与设计输入

- Hub 和本机端现有发行包都支持 Windows、Linux、macOS；维护者没有授权缩减该范围。
- Hub 在 Windows 作为系统服务运行，使用 LocalService；Linux 使用 systemd 用户服务；
  macOS 使用 launchd 系统服务。CLI 配置操作与长期运行服务可能不是同一账号或同一环境。
- 本次来源读取选用外部 PostgreSQL 客户端 `psql`，由 Hub 服务调用。安装路径和可执行环境可能不同；
  不更改上述既有服务类型。对 VibeInsight 仅执行只读查询。
- 已选设计是：连接参数保存在 Hub 配置文件，密码写入服务状态目录的专用秘密文件。
  运行账号需能读取，其他未授权普通账号不能读取；CLI 输出、日志及对话数据库不含密码原值。
  验证新配置成功后才替换有效配置。
- 同步进度保存在 Hub 数据库，批次归档与进度一同提交；重启后按已提交位置继续，回查近期事件去重。
- 本机端会补传项目归属，CLI/MCP 发项目查询时携带当前项目身份；同名项目和旧原文引用保持可区分、可用。
- 当前开发电脑是 macOS，可以运行 Python 测试、创建独立 Hub 和安装两个 wheel。
  Windows/Linux 的本次执行记录尚不存在。未来默认回归可用合成事件替代来源；无需要求在真实服务器造数。
