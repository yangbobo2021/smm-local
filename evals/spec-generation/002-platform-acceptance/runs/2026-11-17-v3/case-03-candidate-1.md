# 规格：SMM 同分检索结果按数值会话 ID 稳定排序

依据：[已确认意图](./intent.md)。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列。例如，同分会话 ID 为 `10`、`2` 时，结果顺序为 `2`、`10`。
2. 对包含相同结果项的输入列表，无论输入顺序如何变化，不同会话 ID 的同分结果均保持上述顺序。
3. 不同分数之间沿用现有排序规则；本次仅增加同分时的会话 ID 排序规则。
4. CLI、MCP 和 Web 通过现有调用方式获得相同的排序语义，无需用户增加输入或配置。
5. 结果字段及其值、项目过滤规则和 `limit` 语义保持不变。`limit` 截断涉及同分结果时，返回项应符合新增的会话 ID 升序规则。

## 边界与约束

- 现有客户端对 Windows、Linux、macOS 的支持范围不变，三平台承诺相同的稳定排序语义。
- 改动限于三平台共用的纯排序函数。输入为已解码的 Python 数值分数和整数会话 ID，不新增解析、类型转换或输入校验要求。
- 会话 ID 按数值比较，不按字符串字典序比较。
- 函数不访问系统、文件、数据库、网络、时间或区域设置，不引入平台分支。
- 不更改运行时范围、依赖、安装方式或服务；不为 CLI、MCP、Web 增加独立排序层。
- 分数与会话 ID 均相同的结果项之间，本次不新增顺序承诺，沿用现有行为。

## 设计决策

采用现有分数排序规则作为主排序规则，仅在分数相同时，以整数会话 ID 升序决定先后，统一由共用纯函数实现。

本次排序结果仅取决于 Python 数值比较。三平台使用相同受支持的比较语义，且函数不存在外部依赖、环境访问或平台分支，因此可在当前 macOS 环境中使用合成输入验证共用逻辑，无需在 Windows、Linux 重复完整测试。

CLI、MCP、Web 的调用方式未变，且不存在额外排序层，因此不要求分别执行三入口的端到端测试；验收须确认这些前提仍成立。该覆盖依据仅适用于本次排序改动，不代表 Windows、Linux 或各入口已实际运行通过。

若实施引入平台差异、外部依赖或入口独立排序，须重新审阅本规格的验收覆盖，不能继续沿用上述充分性判断。

## 验收条件

以下行为用例均在 macOS 上直接调用共用纯函数，以已解码的数值分数和整数会话 ID 作为合成输入。该组判据覆盖三平台共用的排序逻辑。

1. **同分数值升序**：输入多个同分结果，至少包含会话 ID `2` 和 `10`；输出会话 ID 按数值升序排列。
2. **输入顺序无关**：对同一组结果进行多种输入顺序打乱，包含多个分数组及各组内不同会话 ID；每次输出中各同分组的会话 ID 顺序一致且为升序。
3. **不同分数兼容**：输入包含不同分数的结果；输出各分数组之间的顺序与现有规则一致，同分组内部按会话 ID 升序排列。
4. **结果完整性**：未触发截断时，输出保留全部输入结果，结果字段及其值不变，不新增、丢失或重复结果。
5. **项目过滤兼容**：使用不同项目的合成结果及现有过滤条件，沿用现有过滤与排序调用路径；返回项目范围与现有规则一致，范围内的同分结果按会话 ID 升序排列。
6. **`limit` 兼容**：覆盖现有语义下未截断、发生截断及截断边界落在同分组内的情形；返回数量、默认值和边界处理沿用现有规则，截断结果符合完整排序后的对应范围，同分边界按会话 ID 升序取舍。
7. **基本边界**：空列表仍返回空列表；单项列表保留原项；分数和会话 ID 均相同的结果不丢失、不重复，不新增其相对顺序要求。
8. **入口与平台覆盖依据**：审阅确认 CLI、MCP、Web 继续调用同一纯函数，未增加额外排序层；函数仍无平台分支或环境访问，三平台运行时比较语义和支持范围未变。此前提与上述行为用例全部满足，构成本次交付的充分验收证据；记录须明确实际执行环境为 macOS。
