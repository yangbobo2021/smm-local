# 规格：Hub 自动同步 VibeInsight 历史与项目关联检索

依据：[已确认意图](./intent.md)。

## 预期行为

### 来源配置与恢复

- 维护者通过 Hub CLI 提交 VibeInsight 来源连接参数及凭据。Hub 验证连接成功后保存配置；验证失败时报告原因，保留原有效配置及凭据。
- 保存成功后，长期运行的 Hub 服务能够使用该配置调用 `psql`，无需依赖 CLI 进程的账号、环境变量或交互式输入。
- Hub 重启后自动恢复来源同步，无需重新输入密码。
- 来源连接、认证或读取失败时，已有归档仍可通过现有 CLI/MCP 检索和读取。来源恢复后，Hub 重试尚未成功归档的数据。

### 历史同步

- Hub 自动发现并归档 VibeInsight 当前可读取的全部项目历史，随后持续同步新增会话事件及已有会话追加的轮次。
- 来源后来新增可读取项目时，即使其历史事件早于其他项目的已提交同步进度，也应补齐该项目历史。
- 重复读取、近期事件回查和失败重试不会产生重复归档。
- 每批归档数据与对应同步进度一同提交。中断或重启后，从已提交位置继续，不跳过未成功归档的数据。

### 项目关联与查询

- Hub 维护者统一管理项目关联，可以建立或解除设备项目与 VibeInsight 项目的关联，也可以关联不同设备上的项目。
- CLI/MCP 发起项目查询时携带当前项目身份。查询范围包含当前项目和与其直接关联的项目；关系双向生效，只扩展一层。
- 若 A 关联 B、B 关联 C，而 A 未直接关联 C，则 A 的项目查询不因上述关系包含 C。
- 解除关联后，后续项目查询不再通过该关系扩展范围；已归档内容不删除，仍可通过其所属项目、全局查询或已有原文引用访问。
- 同名项目保持可区分，不因名称相同自动合并或建立关联。
- 本机端补传项目归属后，既有归档获得对应项目身份，已有原文引用继续可用。

### 检索与原文读取

- 用户通过现有 CLI/MCP 检索 Hub 归档，无需分别查询 VibeInsight。
- CLI/MCP 返回足以区分来源、项目、原会话和消息位置的信息，并支持据此精确读取对应归档原文。
- 既有原文引用在同步、重复读取、项目归属补传及关联变更后仍指向原内容。
- 旧客户端继续使用既有全局查询行为；Hub 不可用时沿用本机全局回退。

## 边界与约束

- 首版仅面向单用户。
- 来源同步支持新增会话事件和追加轮次；不要求发现没有新增事件的历史正文原地改写。
- 对 VibeInsight 仅执行只读查询，不修改来源数据。
- Hub 和本机端继续支持 Windows、Linux、macOS，不缩减现有发行平台。
- 保持现有服务运行方式：Windows 使用 LocalService 系统服务，Linux 使用 systemd 用户服务，macOS 使用 launchd 系统服务。
- 来源读取由 Hub 服务调用外部 `psql`。安装位置、可执行环境和配置文件访问不能仅以当前 macOS 开发环境或 CLI 操作账号为前提。
- 密码不出现在 CLI 输出、日志或对话数据库中。专用秘密文件允许 Hub 运行账号读取，其他未授权普通账号不能读取。
- 来源故障不影响已有归档的可用性；Hub 整体不可用时按既有本机回退行为处理。
- 当前只有 macOS 开发验证条件，尚无本次 Windows/Linux 执行记录；不能据此认定跨平台验收已经通过。回归可使用合成事件，无需在真实服务器造数。

## 设计决策

- 连接参数保存在 Hub 配置文件，密码保存在服务状态目录的专用秘密文件。配置写入和权限设置须适配 CLI 与服务可能由不同账号、不同环境运行的情况。
- 新配置验证成功后才替换有效配置；连接参数与密码作为同一次配置切换处理，避免失败后留下不匹配的有效状态。
- 同步进度保存在 Hub 数据库中，与批次归档在同一事务中提交；恢复时回查近期事件并去重。
- 项目身份和原文定位不得仅依赖项目名称；来源身份、项目身份、原会话及消息位置应足以消除歧义。
- 项目关联作为查询范围扩展关系维护，解除关联不触发归档删除。

以下事项仍需维护者确认：

- Hub CLI 的来源配置、状态查看及项目关联管理命令，以及 CLI/MCP 返回来源与原文定位信息的字段契约。
- 各平台服务可用的 `psql` 路径确定方式、配置与秘密文件的具体位置，以及所需的权限配置流程。
- 来源验证成功的判定范围，须覆盖服务实际运行环境中的可执行性、连接认证及必要只读查询。
- 同步轮询、失败重试及近期事件回查的具体策略。
- 新增可读项目的发现方式与独立补齐进度的表示方式，须避免被已有全局进度跳过。

## 验收条件

1. 提交有效来源配置后，Hub 服务可读取来源并保存归档；重启后无需重新输入密码即可继续同步。
2. 提交无效连接参数或凭据后，CLI 报告失败，原有效配置仍可使用，未发生部分替换。
3. CLI 操作账号与服务账号或环境不同时，保存的配置仍可供既有服务读取并调用 `psql`；该能力分别适用于 Windows、Linux、macOS 的既有服务类型。
4. Hub 运行账号可读取秘密文件，未授权普通账号无法读取；CLI 输出、日志和对话数据库均不含密码原值。
5. 初次同步后，来源当前全部可读项目的历史均可通过现有 CLI/MCP 检索并读取。
6. 来源新增会话或向旧会话追加轮次后，相应内容自动进入归档；重复读取同一事件不会增加重复内容。
7. 新增一个可读项目，其历史早于已有同步进度时，该项目历史仍被完整补齐。
8. 同步在批次提交前中断时，恢复后补齐该批数据；提交后中断时，恢复后不重复归档。归档与进度不存在部分提交状态。
9. 来源故障期间已有归档仍可查询和读取；恢复后，故障期间未成功同步的数据被补齐。
10. 设备项目与 VibeInsight 项目、不同设备项目之间均可建立关联，且两端查询均包含直接关联项目的内容。
11. 对 A—B—C 关联链，A 的查询包含 B，且不会仅因该链包含 C。
12. 解除关联后，项目查询范围相应收缩；归档仍存在，已有原文引用仍可读取。
13. 两个同名项目保持独立；本机端补传项目归属后，项目查询归属正确，旧原文引用保持有效。
14. CLI/MCP 返回可区分来源、项目、原会话及消息位置的信息；使用该信息能够读取准确的对应原文。
15. 旧客户端全局查询继续可用；Hub 不可用时触发现有本机全局回退。
16. 仅原地修改历史正文且未新增事件的样本，不作为本版必须发现的变更；新增事件及追加轮次仍须满足同步条件。
