# 规格：明确来源管理命令帮助

依据同目录下已确认的 [intent.md](intent.md)。无待维护者决定的事项。

## 预期行为

1. 用户执行 `smm source --help` 时，帮助以简体中文说明全部现有子命令的用途：

   | 子命令 | 帮助须表达的用途 |
   |---|---|
   | `list` | 查看本机来源状态。 |
   | `validate` | 使用来源清单和测试样本验收候选适配器。 |
   | `register` | 使用来源清单和测试样本验收候选适配器，通过后注册来源。 |
   | `enable` | 启用指定来源的导入。 |
   | `disable` | 停用指定来源的导入，保留已导入记录。 |
   | `rollback` | 将指定插件来源的适配器切回上一版。 |
   | `batches` | 查看指定插件来源的导入批次列表，其中每条记录的 `id` 为批次 ID。 |
   | `purge-batch` | 从 SMM 本机档案删除指定来源、指定批次已导入的记录；清理前须先停用对应的插件来源。 |

2. 用户只阅读 `smm source --help`，即可区分以下操作的影响：
   - `disable` 停止来源继续导入，保留已导入记录。
   - `rollback` 将插件来源的适配器切回上一版。
   - `purge-batch` 删除指定批次已导入到 SMM 本机档案的记录。

3. 用户执行 `smm source purge-batch --help` 时，帮助以简体中文说明：
   - `source_id` 是来源 ID。
   - `batch` 是整数批次 ID，对应 `smm source batches` 输出中批次记录的 `id`。
   - 清理会从 SMM 本机档案删除该批次已导入的记录。
   - 清理前须先停用对应的插件来源；该来源仍启用时，清理会被拒绝。

4. 两条帮助命令均打印帮助并以状态码 `0` 退出，不创建档案对象、不执行来源操作、不写入档案。

## 边界与约束

- 变更仅涉及 `smm source` 的 CLI 帮助文案，沿用现有命令名、参数、参数类型、必填要求和操作行为。
- `validate` 和 `register` 保持接收位置参数 `manifest` 及必填选项 `--fixture`。
- `enable`、`disable`、`rollback`、`batches` 和 `purge-batch` 保持接收位置参数 `source_id`；`purge-batch` 另接收整数位置参数 `batch`。
- 帮助中的清理范围限定为 SMM 本机档案中指定批次已导入的记录，不得表述为删除来源、适配器或原始对话文件。
- “先停用再清理”是对现有前置条件的说明，不新增自动停用行为。
- 文案可调整措辞，但须完整保留上述用途、操作影响和前置条件。

## 验收条件

1. `smm source --help` 展示全部八个现有子命令，每个子命令均有简体中文用途说明，语义符合“预期行为”中的对应条目。
2. 仅凭来源主帮助，即可分别确认：停用保留已导入记录、回退切换至上一版适配器、清理删除指定批次已导入记录。
3. 来源主帮助和批次清理帮助均明确提示：清理批次前须先停用对应的插件来源。
4. `smm source purge-batch --help` 明确说明两个位置参数的含义、`batch` 的整数类型及其与批次列表记录 `id` 的对应关系。
5. 批次清理帮助明确说明删除范围为 SMM 本机档案中该批次已导入的记录，并说明对应插件来源仍启用时拒绝清理。
6. 两条帮助命令均以状态码 `0` 退出，且不创建档案对象、不执行来源操作、不写入档案。
7. 现有命令名、参数名、参数类型、必填要求及来源操作行为保持兼容；清理命令不会因本次变更自动停用来源。
