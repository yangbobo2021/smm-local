# 规格：Hub 在 systemd 用户服务启动后自动同步

依据：[已确认意图](./intent.md)。

## 预期行为

1. Linux systemd 用户服务启动后，Hub 自动执行已有的一次同步操作，拉取已配置来源的新对话，无需维护者另行运行同步命令。机器重启后，该行为须在用户服务自动启动时生效。
2. 启动同步沿用 Hub 用户状态目录中的已有来源凭据及数据库同步进度，不要求重新登录、重新配置来源或重置进度。配置格式及凭据获取方式沿用现有流程。
3. 启动同步成功后，新拉取的对话可通过现有检索能力访问，已有归档继续可检索。
4. 启动同步失败时，报告可定位问题的失败原因；同步失败不得使已有归档失去检索能力，也不得因恢复同步而要求清空数据库。
5. 失败后的同步重试沿用已保存的进度，已导入消息不得重复导入。现有手动同步入口保持兼容；本次不新增自动重试策略。

## 边界与约束

- 本次 Hub 交付仅支持 Linux systemd 用户服务，不支持 Windows/macOS Hub 运行方式。
- Windows、macOS、Linux 本机客户端继续通过既有 HTTPS 协议访问 Hub。本次不修改客户端，也不将客户端各平台的完整回归纳入必验范围。
- 变更仅将 Hub 已有的一次同步操作接入服务启动后的生命周期。同步算法、API、CLI/MCP、客户端程序和配置格式保持不变。
- 服务必须以有权读取既有状态目录的 Linux 服务账号运行。不能依赖交互式登录会话中的环境变量、当前目录或临时凭据，使既有配置在服务环境中失效。
- 当前 macOS 开发环境只能提供共用逻辑验证，不能提供 Linux systemd 用户服务实际启动或机器重启后的通过证据。必要 Linux 证据缺失时，本次交付不能判定完成。

## 设计决策

- 启动同步复用现有同步操作及进度持久化机制，不另建同步算法或独立进度。生命周期接入须保留现有去重与重试语义。
- 同步失败不得阻断归档检索服务的可用性。失败原因至少应能从服务运行日志中查看，并避免泄露凭据。
- 验收必须覆盖真实 systemd 用户服务环境。交互式执行成功不能证明服务账号、状态目录访问及服务环境下的同步成立。

以下事项仍需维护者确认，确认结果须在实施前补入本规格：

1. **机器重启后的启动条件**：用户服务是否必须在无人登录时自动启动，还是允许在相应用户登录后启动。该决定影响用户服务的启动配置及重启验收的会话状态。
2. **Linux 支持基线**：适用的 Linux 发行版及 systemd 版本范围尚未提供。该决定影响实际运行证据的代表性与所需覆盖范围，不默认任意 Linux 环境均足够。

## 验收条件

以下服务运行验收均须在维护者确认的 Linux/systemd 支持范围内，以实际服务账号及其已有用户状态目录执行；所用凭据和数据库进度均须在操作前存在。共用判据可复用，但证据必须明确对应运行环境与服务状态。

1. **用户服务启动**
   
   在来源存在尚未归档的新对话、数据库已有同步进度的状态下启动 systemd 用户服务。无需执行手动同步命令，Hub 自动拉取新对话；新旧归档均可经现有检索入口访问，凭据及进度被正确沿用。

2. **机器重启**
   
   在相同配置和持久化数据保留的情况下重启 Linux 机器，并满足已确认的登录或无人登录条件。用户服务自动启动并执行同步，重启前后新增的待同步对话可被检索，已有归档仍可检索，无需手动同步或重新提供凭据。

3. **服务环境中的凭据与状态访问**
   
   在不依赖交互式登录环境的 systemd 用户服务中，合法服务账号能读取既有凭据并使用数据库进度完成同步。凭据不可读取时，日志能说明访问失败原因且不泄露凭据，已有归档仍可检索。

4. **同步失败与恢复**
   
   在已有归档的 Linux 服务环境中，使启动同步因来源不可访问等条件失败。日志记录可定位的失败原因，现有 HTTPS 检索路径仍能返回已有归档。解除故障后，通过现有同步入口或再次启动服务重试，新对话成功导入，已有消息不重复。

5. **部分完成后的重试**
   
   在 Linux 服务环境中，使启动同步在部分消息已持久化后中断，再次启动服务执行同步。同步沿用持久化进度完成剩余导入；已导入消息无重复，原有及新增归档均可检索。

6. **兼容性与证据边界**
   
   共用逻辑测试及接口、配置对照须证明本次接入未改变同步算法、API、CLI/MCP 和配置格式的既有约定。此类检查可在 macOS 完成；由于客户端程序及 HTTPS 协议不变，无需三个客户端平台重复完整测试。上述 Linux 验收仍须通过现有 HTTPS 路径确认检索结果，共用测试或包构建不能替代实际 systemd 启动、失败恢复和机器重启证据。

两项待确认决定尚未解决，或必要 Linux 实际运行证据尚未取得时，均不得判定本规格交付通过。
