# 规格：Hub 自动同步 VibeInsight 历史与项目关联检索

本规格依据同目录下已确认的 [intent.md](intent.md) 及项目现有承诺起草。尚缺少依据、需维护者决定的事项在下文标明。

## 预期行为

### 来源配置与凭据保存

1. 维护者通过 Hub CLI 提供 VibeInsight PostgreSQL 来源连接信息并验证保存。连接信息须足以确定数据库地址、端口、数据库名、读取账号、密码，以及服务所用 `psql` 的定位方式。账号应具有读取目标历史所需的权限；可读取项目的范围以该账号实际权限为准。
2. CLI 验证须覆盖连接、必要数据读取以及长期运行服务使用该配置的条件。验证失败时返回可定位的原因，不替换原有效配置或密码；首次配置失败不得留下可被服务误认为有效的配置。
3. 验证成功后，连接参数保存到 Hub 配置文件，密码保存到服务状态目录的专用秘密文件。Hub 服务重启后自动使用已保存配置，无需再次输入密码。
4. CLI 应使维护者能够确认有效来源、配置和秘密文件的实际位置、服务运行账号及 `psql` 定位结果，不显示密码原值。所需输入的准确格式、获取或确认方式应随 CLI 帮助提供，不能要求维护者依赖开发电脑的环境猜测。
5. CLI 进程能够连接来源，不单独构成保存成功的充分依据：保存的配置及秘密必须能供既有运行方式下的 Hub 服务使用。

### 自动同步与故障恢复

1. 配置生效后，Hub 自动发现并同步来源账号可读取的全部项目历史，无需维护者逐项目登记，也不以项目关联作为同步前提。
2. 完成初始同步后，Hub 持续同步新会话及已有会话追加的轮次。来源后来新增可读项目时，Hub 应补齐该项目全部可读历史，包括事件位置早于其他项目已有同步进度的数据。
3. 每批归档与对应同步进度一同提交。Hub 重启后从已提交状态继续，并回查近期事件；重复读取不得生成重复会话或消息。
4. 来源不可连接、凭据失效、`psql` 不可执行或查询失败时，Hub 保留已有归档及有效进度，已有归档仍可检索和读取。失败原因应可诊断，且不得泄露密码。
5. 来源恢复后，Hub 自动重试未成功归档的数据，最终补齐失败期间新增的会话和追加轮次，不因失败或重启跳过数据。

### 项目归属与关联

1. 本机端补传对话的项目归属；CLI/MCP 发起项目查询时携带当前项目身份。同名项目不能仅凭显示名称合并。
2. Hub 维护者统一管理项目关联，能够建立、查看和解除设备项目与 VibeInsight 项目之间、以及不同设备项目之间的关联。
3. 建立关联时，维护者须能从 Hub 已知项目中确认双方身份及来源；同名项目必须可区分。关联管理入口及项目选择格式待维护者确认。
4. 项目查询包含当前项目及其直接关联项目，关系双向且仅扩展一层。例如 A 与 B、B 与 C 关联时，查询 A 包含 A、B，不因 B 与 C 的关系包含 C；查询 B 包含 A、B、C。
5. 解除关联后，后续项目查询不再通过该关系扩展范围；已归档会话、消息及原文引用不被删除，仍可通过全局查询或直接引用访问。

### CLI/MCP 检索与原文读取

1. 用户通过现有 CLI/MCP 入口检索 Hub 归档时，可以找到同步的 VibeInsight 历史及本机端上传历史。
2. 项目查询按当前项目身份及一层关联限定范围；旧客户端的全局查询继续保持全局语义，不要求携带新增项目身份。
3. CLI/MCP 检索结果返回可区分来源、项目、原会话及消息位置的信息，并提供足以精确读取对应原文的引用。不同来源或同名项目中的同名会话不得发生引用碰撞。
4. 用户使用结果引用读取原文时，得到对应会话或消息位置的已归档内容。既有原文引用继续可用。
5. Hub 不可用时，CLI/MCP 沿用既有本机全局回退行为；不得将本机结果表述为完整 Hub 归档。

## 边界与约束

- 首版为单用户范围，不新增多用户授权或隔离承诺。
- 来源仅执行只读查询，不修改 VibeInsight 数据。来源账号不可读取的项目不在同步范围内。
- 首版发现新增会话事件及追加轮次，不承诺发现没有新增事件的历史正文原地改写。
- Hub 和本机端继续支持 Windows、Linux、macOS。本次不改变既有发行范围或服务类型：
  - Windows Hub：LocalService 账号下的系统服务。
  - Linux Hub：systemd 用户服务。
  - macOS Hub：launchd 系统服务。
- `psql` 是 Hub 服务的外部运行依赖。不能以配置 CLI 所在账号的 PATH、文件权限或连接成功，推断服务账号具备相同条件。
- 秘密文件必须允许实际服务账号读取，并拒绝其他未授权普通账号读取。CLI 输出、日志及对话数据库不得包含密码原值。
- 不要求在真实 VibeInsight 服务器造数；回归可以使用能表达来源事件、项目可读范围变化及失败状态的合成数据。
- 当前 macOS 开发环境的 Python 测试、独立 Hub 和两个 wheel 的安装能力，不构成 Windows/Linux 或既有服务运行方式的通过证据。

## 设计决策

1. **凭据与服务环境分离处理。** 连接参数保存在 Hub 配置文件，密码保存在服务状态目录的专用秘密文件。配置验证必须涉及服务账号的读取权限和 `psql` 执行条件，避免交互式 CLI 验证成功而服务无法同步。
2. **归档与进度原子提交。** 批次归档和进度共同提交；恢复时回查近期事件并去重。验收须覆盖提交前后中断，证明不会出现进度已前移但内容未归档的缺口。
3. **新增可读项目不能受全局进度截断。** 同步状态须能区分项目历史补齐与持续事件消费，或采用具有同等结果保证的方式。
4. **项目身份与展示名称分离。** 关联、去重及原文引用使用可稳定区分来源和项目的身份；显示名称相同不能导致合并或误读。

以下事项须在实施前由维护者确认，不能留到验收时临时解释：

- 来源连接输入的准确格式、TLS 要求、必要查询权限及 VibeInsight 数据结构兼容范围；这些决定配置帮助内容及验证通过标准。
- 三个平台上配置文件、服务状态目录及秘密文件的位置、所有权和权限建立方式，以及 CLI 如何完成跨账号配置和验证。
- `psql` 支持版本、安装责任、定位或显式路径配置方式；这些决定安装前提和服务启动后的可用性。
- 配置保存后运行中服务如何生效，以及自动同步、失败重试和新增可读项目发现的周期或最大延迟；这些决定“持续同步”和“恢复后补齐”的可判定时限。
- 项目关联管理入口，以及 CLI/MCP 项目身份和原文位置的具体接口表达；须保持旧客户端全局查询和旧原文引用兼容。

## 验收条件

### 来源与同步的实际服务环境证据

以下共同判据必须分别在 Windows LocalService 系统服务、Linux systemd 用户服务、macOS launchd 系统服务下取得实际通过证据。各环境使用相同判据，不要求重复编写测试。交互式独立 Hub、共用单测及 wheel 构建不能替代这些服务环境证据。

1. 在服务尚未配置来源时，通过 CLI 完成有效配置；服务能调用其可用的 `psql`，读取秘密并同步来源数据。重启服务后，无需重新输入密码即可继续同步。
2. 已存在有效配置和归档时，提交无效凭据或不可用连接；保存被拒绝，原配置和密码继续有效，归档可查询。随后重启，服务仍能使用原配置同步。
3. 分别覆盖服务账号无法执行 `psql`、无法读取秘密文件的状态：配置验证或服务诊断准确指出原因，不误报同步成功；修复后可以恢复同步。
4. 实际服务账号能读取秘密文件，未授权普通账号不能读取；配置成功、验证失败、同步失败及重启相关的 CLI 输出、日志和对话数据库中均无密码原值。
5. 来源包含多个可读项目、既有会话及多轮消息时，服务自动完整归档。随后新增会话和追加旧会话轮次，在确认的同步时限内均可检索并精确读取。
6. 在已有进度后新增一个可读项目，该项目包含早于已有进度的历史；在确认的发现和补齐时限内，该项目全部可读历史进入归档。
7. 同步期间来源失败时，已有内容仍可查询；恢复来源后，在确认的重试时限内补齐未成功数据。服务重启和近期事件重复读取后，会话与消息不重复、不缺失。

批次提交边界的中断、回滚和去重组合可通过共用逻辑测试充分覆盖；三个实际服务环境仍须分别证明上述重启续传、依赖执行及文件权限行为成立。

### 本机端、CLI 与 MCP

以下行为须在 Windows、Linux、macOS 上分别通过本次发行的本机端及 CLI/MCP 实际入口验证。可复用同一组输入与结果判据，不必穷举全部关联图。

1. 本机端上传或补传项目归属后，Hub 能区分不同设备上的同名项目；CLI 和 MCP 项目查询均携带并使用当前项目身份。
2. 准备 A—B、B—C 关系，其中包含设备项目与 VibeInsight 项目；CLI 和 MCP 查询 A 时返回 A、B 范围内结果且不包含仅通过 B 关联的 C，查询 B 时包含 A、B、C。反向查询证明关系双向。
3. 解除 A—B 后，两类入口的后续项目查询不再通过该关系返回对方内容；全局查询和解除前取得的原文引用仍能访问归档。
4. CLI 和 MCP 均可检索 VibeInsight 归档，并返回来源、项目、原会话及消息位置。使用返回引用读取时，内容与指定位置一致；同名项目及跨来源同名会话不混淆。
5. 旧原文引用继续可用；旧客户端不携带项目身份的全局查询仍返回全局范围结果。
6. Hub 不可用时，两类入口均按既有规则返回本机全局查询结果；Hub 恢复后可再次访问 Hub 归档。

关联管理入口确认后，须在其适用环境中验证建立、查看、解除、同名项目选择及结果生效；若为跨平台交付的 Hub CLI，则三个平台均须覆盖该入口。

### 共用逻辑与交付判定

- 使用合成来源验证只读查询、全部可读项目发现、旧项目追加、新增可读项目历史补齐、批次原子提交和重复事件去重；无需在真实服务器造数。
- 一层关系计算、身份区分及引用编解码等平台无关逻辑可共用测试，但不得据此宣称其他平台的服务或入口已实际运行通过。
- 没有新增事件的正文原地改写不作为必须同步的验收项。
- 上述必要平台、服务方式和入口的证据缺失时，交付仍未完成。当前 Windows/Linux 尚无执行记录；macOS 开发能力也不等于已取得所需证据。
- 具体机器、实现位置、实施顺序、测试步骤、命令和 CI 配置写入 `plan.md`。
