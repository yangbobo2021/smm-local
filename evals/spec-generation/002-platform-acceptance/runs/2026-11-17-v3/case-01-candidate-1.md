# 规格：Hub 自动同步 VibeInsight 历史与统一项目检索

本规格依据同目录下已确认的 [intent.md](intent.md) 及项目现有支持承诺起草。尚缺的接口、来源结构和配置约定在下文标为待维护者确认。

## 预期行为

### 来源配置与持续运行

1. Hub 维护者通过 Hub CLI 提交 VibeInsight 来源连接信息和凭据。CLI 必须在保存前验证连接、认证和同步所需数据的只读访问能力；验证成功后才替换有效配置。验证失败时返回可定位问题且不含密码的错误，保留原有效配置及其继续同步的能力。

2. 配置入口须明确说明以下必要输入及确认途径：
   - PostgreSQL 服务地址、端口和数据库名，由 VibeInsight 部署维护者提供并确认。
   - 来源数据库账号及密码，由来源维护者提供；账号须能读取本次同步所需的项目、会话、消息和事件数据。
   - Hub 服务使用的 `psql` 可执行文件及其定位方式；维护者须能确认长期运行服务实际使用的路径，而非仅确认交互式终端可执行。
   - 配置对应的 Hub 实例、配置文件和服务状态目录，使 CLI 操作作用于目标长期运行服务。

   具体命令、参数名称、默认值、来源数据结构及最低读取权限尚待维护者确认；这些约定必须在实施前补齐，不能依赖用户猜测。

3. 连接参数保存在 Hub 配置文件，密码保存在服务状态目录的专用秘密文件。Hub 长期运行账号能够读取密码，其他未授权普通账号不能读取。CLI 输出、日志和对话数据库均不包含密码原值。

4. Hub 服务自动使用已保存的配置同步。服务重启后无需重新输入密码，按已提交进度继续运行。配置验证成功必须能支撑目标服务实际读取来源，不能仅表示 CLI 所在账号能连接。

### 历史归档与故障恢复

1. 配置生效后，Hub 自动归档该来源账号可读取的全部 VibeInsight 项目历史，包括会话和消息原文；随后持续同步新会话事件及旧会话追加的轮次。

2. 来源后来新增可读项目时，Hub 自动发现并补齐其历史，包括事件位置早于现有同步进度的数据，不能仅跟随全局最新位置。

3. 批次归档与对应进度在同一事务中提交。中断或重启后，不跳过未成功归档的数据；近期事件回查、重试或重复读取不会产生重复归档消息。

4. 来源连接、认证或查询失败时，已归档内容继续可检索、可读取。来源恢复后自动重试未成功的数据，无需重新建立有效配置或清空归档。

5. 对 VibeInsight 只执行读取操作。首版同步新增会话事件和追加轮次；没有新增事件的历史正文原地改写不在发现范围内。

### 项目归属与关联管理

1. 本机端上传时补传项目归属；CLI/MCP 发起项目查询时携带当前项目身份。同名但身份不同的项目保持可区分，不能仅凭显示名称合并。

2. Hub 维护者统一管理项目关联，支持设备项目与 VibeInsight 项目关联，以及不同设备项目之间关联。

3. 关联双向且仅扩展一层。例如 A 与 B、B 与 C 关联后，从 A 查询包含 A 与 B，不因 B 与 C 的关系自动包含 C；从 B 查询包含 B、A、C。关联查询结果去重。

4. 解除关联后，后续项目查询不再经该关系扩展；已归档内容和既有原文引用继续可用。

5. 关联管理入口须提供项目身份的查询或选择方式，并展示足以区分来源、设备及同名项目的信息。具体管理命令、项目身份格式及重复关联、自关联、无效身份的处理约定待维护者确认。

### CLI/MCP 检索、原文读取与兼容

1. 用户通过现有 CLI/MCP 检索 Hub 归档时，可检索到 VibeInsight 历史及后续同步内容；项目查询按当前项目身份和一层关联限制范围。

2. CLI/MCP 检索结果返回来源、项目、原会话和消息位置。调用方能使用返回的定位信息精确读取对应原文，不因跨来源同名项目或会话标识相同而读错内容。

3. 引入来源和项目身份后，旧原文引用仍可解析并读取原内容。

4. Hub 不可用时，CLI/MCP 沿用本机全局回退语义。旧客户端未携带项目身份的全局查询继续可用，不能被静默收窄为当前项目查询。

## 边界与约束

- 首版为单用户，不引入多用户权限隔离或多租户行为。
- 自动同步范围限于来源账号当前可读取的数据，不绕过来源权限。
- Hub 和本机端继续支持 Windows、Linux、macOS，不缩减现有发行范围。
- Hub 继续沿用既有运行方式：
  
  | 平台 | Hub 长期运行方式 |
  |---|---|
  | Windows | 系统服务，运行账号为 LocalService |
  | Linux | systemd 用户服务 |
  | macOS | launchd 系统服务 |

- 外部 `psql` 由 Hub 服务调用。交互式 CLI 与服务可能使用不同账号、环境变量、文件权限和可执行路径；终端配置成功或 wheel 构建成功不能证明服务可持续同步。
- 本次不改变既有服务类型，不新增来源写入行为，也不要求在真实 VibeInsight 服务器造数。
- 来源暂时失败不使已有归档失效；解除项目关联不删除归档。
- 当前 macOS 开发环境可用于共用逻辑和本机验证，但不能代替 Windows/Linux 实际运行证据。

## 设计决策

1. **配置与秘密分离。** 沿用连接参数写配置文件、密码写服务状态目录专用文件的设计。配置更新须保证验证失败不损坏旧配置，更新中断不留下连接参数与密码不匹配的有效状态。各平台的文件访问控制须分别验证。

2. **验证面向服务实际运行条件。** 来源验证必须覆盖目标服务的 `psql` 可执行环境、秘密文件读取和数据库访问能力。具体由服务执行验证还是采用其他等效机制，待维护者确认；仅以 CLI 账号验证不能满足要求。

3. **归档与进度共同提交。** 沿用 Hub 数据库保存进度及批次事务设计。去重身份必须区分来源、原会话和消息位置，既能抵御事件重读，也不误合并不同来源的数据。

4. **项目发现独立于已有事件进度。** 必须具备发现新增可读项目并补齐较早历史的机制。来源项目枚举、事件排序与分页规则、稳定消息定位字段尚待确认；若来源结构无法支持这些能力，须在实施前提交维护者决定，不能降低已确认行为。

5. **接口兼容。** 新来源定位和项目身份须与旧全局查询、旧原文引用共存。具体字段格式、关联管理接口和同步周期、重试间隔及可判定的完成时限待维护者确认。完成时限须使自动同步和恢复重试可验收。

## 验收条件

以下覆盖是本次交付的必要条件。具体机器、命令、执行顺序和 CI 配置写入 `plan.md`，不得由其另行决定是否覆盖。

### 共用归档与项目逻辑

可在当前 macOS 环境使用独立 Hub、受控来源或合成事件验证以下共用逻辑。其充分性仅限于数据归档、进度、去重、关联及接口语义，不证明其他平台的服务环境已通过。

1. 来源含多个可读项目、已有会话和多轮历史时，初次同步归档全部预期内容；新增会话及旧会话追加轮次后，均在约定时限内归档，原文和位置一致。
2. 已有同步进度后增加一个可读项目，其历史早于该进度，仍能完整补齐。
3. 重复提供事件、回查近期事件及重试批次后，无重复消息，也无不同来源数据被误合并。
4. 在批次提交前后分别中断并重启，归档与进度保持一致；未提交数据最终补齐，已提交数据不重复。
5. 来源失败期间，CLI/MCP 仍能检索并读取既有归档；恢复后，故障期间遗漏的新会话和追加轮次自动补齐。
6. 用不同来源的同名项目及相同原会话标识验证，返回身份可区分，逐条定位读取均得到正确原文。
7. 按 A—B、B—C 建立关系，分别从 A、B、C 查询，满足双向一层规则；解除 A—B 后范围立即按新关系变化，归档及旧引用仍可读取。
8. 无新增事件的历史正文原地改写不要求被发现；不得据此宣称已支持历史修改同步。

### 各平台 Hub 服务

下列判据必须分别在 Windows LocalService 系统服务、Linux systemd 用户服务、macOS launchd 系统服务取得实际通过证据。各平台可复用同一组受控来源数据和判据，无需重复全部共用逻辑测试。

1. 通过 Hub CLI 配置有效来源后，目标服务实际调用外部 `psql`，完成初始归档；随后新增会话及追加轮次均自动归档，并能检索、定位读取正确原文。
2. 在 CLI 与服务账号或执行环境不同的条件下，服务仍能定位 `psql` 并读取秘密文件。缺少可执行文件、执行权限或秘密读取权限时，验证失败或明确报告服务不可用原因，不将该状态判作配置成功。
3. 运行账号可读取秘密，未授权普通账号不能读取；配置、CLI 输出、日志和对话数据库不含密码原值。
4. 原有效配置存在时提交无效凭据，操作失败且原配置继续完成后续同步。
5. 重启长期运行服务，无需输入密码即可继续同步；重读事件不重复，未提交数据不丢失。
6. 来源中断期间已有归档可查、可读；来源恢复后未成功数据自动补齐。该恢复结果须归属于各平台服务的实际执行记录。

可使用受控 PostgreSQL 来源替代生产服务器，但上述服务验收必须实际经过 `psql`、服务账号和文件权限路径，合成事件单测不能替代。

### 各平台本机端与 CLI/MCP

Windows、Linux、macOS 本机端均须取得以下实际通过证据；可连接共用的已验证 Hub，无需为客户端测试重复部署所有 Hub 平台组合。

1. 本机端上传项目归属后，Hub 保存正确项目身份；同名设备项目保持可区分。
2. CLI 和 MCP 分别携带当前项目身份查询，得到当前项目及一层关联项目的结果；返回的来源、项目、原会话和消息位置均可用于精确读取原文。
3. Hub 不可用时，CLI 和 MCP 分别完成既有本机全局回退，返回符合原语义的本机内容。
4. 当前客户端仍能读取旧原文引用；兼容旧客户端的全局请求取得预期全局结果。旧协议兼容逻辑可共用验证，但不能代替各平台新增客户端路径的实际运行证据。

配置输入、来源结构、接口约定及同步完成时限等待确认项未落实，或任何必需平台与入口缺少上述通过证据时，本次交付仍未完成。
