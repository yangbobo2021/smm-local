# 规格：明确来源管理命令的帮助说明

依据同目录已确认的 [intent.md](intent.md)。本次仅调整 CLI 帮助文案，无待维护者决定事项。

## 预期行为

1. 用户执行 `smm source --help`，看到简体中文的来源管理用途说明及全部八条子命令的简短用途，无须执行子命令即可区分：

   | 子命令 | 帮助须表达的用途 |
   |---|---|
   | `list` | 查看以来源 ID 为键的本机来源状态。 |
   | `validate` | 使用来源清单和测试样本验收候选适配器。 |
   | `register` | 验收候选适配器，通过后注册来源。 |
   | `enable` | 启用指定来源的导入。 |
   | `disable` | 停用指定来源的导入，保留已导入记录。 |
   | `rollback` | 将指定插件来源的适配器切回上一版。 |
   | `batches` | 查看指定插件来源的导入批次及批次 ID。 |
   | `purge-batch` | 从 SMM 本机档案删除指定批次已导入的记录；须先停用对应插件来源。 |

2. `smm source --help` 明确区分停用、回退和清理：停用针对后续导入且保留已导入记录；回退针对适配器版本；清理针对本机档案中指定批次已导入的记录。

3. 用户执行 `smm source purge-batch --help`，除现有调用格式外，还能看到：
   - `source_id` 是待清理批次所属插件来源的 ID，可从 `smm source list` 输出的键取得。
   - `batch` 是整数批次 ID，可通过 `smm source batches <source_id>` 查询，取批次记录的 `id`，不是批次列表中的序号。
   - 清理会从 SMM 本机档案删除该批次已导入的记录。
   - 清理前须执行 `smm source disable <source_id>` 停用对应插件来源；来源仍启用时清理会被拒绝。停用本身保留已导入记录。

4. 两条帮助命令均打印帮助并以状态码 `0` 退出，不创建或写入档案，也不执行来源管理操作。

## 边界与约束

- 范围限于 `smm source` 的 CLI 帮助文案，沿用简体中文用途说明。
- 保留全部现有命令名、参数名、参数类型、必填要求和操作行为，包括：
  - `validate`、`register` 的位置参数 `manifest` 及必填选项 `--fixture`。
  - `enable`、`disable`、`rollback`、`batches`、`purge-batch` 的位置参数 `source_id`。
  - `purge-batch` 的整数位置参数 `batch`。
- 不改变启用来源时拒绝清理批次的既有约束，不新增确认流程或操作能力。
- 受影响组件仅为 CLI 帮助。资料未列出操作系统支持清单，本次不新增或缩减平台承诺，也不从当前开发环境推断支持范围。

## 设计决策

- 在父级帮助的子命令列表中直接提供用途说明；清理前先停用来源的提示同时出现在父级帮助和清理子命令帮助中，使两种查阅入口都能获得必要前提。
- 帮助继续在创建档案对象和执行子命令前完成解析并退出，不依赖来源是否已注册、启用或存在导入批次。
- 本次变化是共用 CLI 定义中的静态文案，不涉及平台分支、文件路径规则、外部服务或进程生命周期。一个项目可运行的实际 CLI 环境中的内容验证和帮助退出验证足以覆盖本次变化；不要求所有操作系统重复测试，也不据此声称其他平台已实际运行通过。

## 验收条件

以下条件均适用于同一个项目可运行的实际 CLI 环境。该环境应记录在验收证据中；具体机器、命令和测试步骤写入 `plan.md`。

1. 执行 `smm source --help`，输出包含全部八条现有子命令及对应简体中文用途，语义符合“预期行为”中的表格，无命令遗漏。
2. 父级帮助明确表达以下三项区别：`disable` 停用导入并保留记录；`rollback` 将插件适配器切回上一版；`purge-batch` 删除本机档案中的指定批次记录。
3. 父级帮助明确提示清理批次前须先停用对应插件来源。
4. 执行 `smm source purge-batch --help`，输出保留 `source_id` 和 `batch` 两个位置参数，并完整说明来源 ID 的取得方式、整数批次 ID 的查询方式及其对应批次记录的 `id`。
5. 清理子命令帮助明确说明删除范围、先停用的前提、停用命令及来源仍启用时拒绝清理的行为，不将停用描述为删除记录。
6. 在未初始化档案的状态下，两条帮助命令均能输出上述完整帮助、以状态码 `0` 退出，且不创建档案；在已有档案的状态下，两条帮助命令同样通过上述判据，且不写入档案、不调用来源管理操作。
7. 对照固定项目资料检查 CLI 定义，确认命令名、参数名、类型、必填要求及操作处理行为均未改变。本次无须实际执行注册、停用、回退或删除来验收文案。
8. 上述内容、入口及无副作用条件全部取得通过证据后，方可判定本次交付通过。共用逻辑验证的结论仅覆盖本次静态帮助变更，不扩大为其他平台或来源管理功能的运行验证。
