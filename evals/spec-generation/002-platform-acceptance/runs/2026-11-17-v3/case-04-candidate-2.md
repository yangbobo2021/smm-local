# 规格：Hub 在 systemd 用户服务启动后自动同步

依据同目录已确认的 [intent.md](intent.md) 及项目现有承诺起草。

## 预期行为

1. Linux systemd 用户服务每次启动后，Hub 自动执行已有的一次同步操作，拉取已配置来源的新对话，无需用户手动运行同步命令。机器重启后服务自动启动时，同样触发同步。
2. 启动同步沿用 Hub 用户状态目录中的既有来源凭据与数据库进度。用户不需要重新提供凭据、重建进度或更改配置格式。来源及凭据继续通过项目既有配置方式管理。
3. 启动同步成功后，新导入的对话可通过既有检索入口检索；原有归档继续可检索。
4. 启动同步失败时，Hub 报告可用于定位问题的失败原因，不泄露凭据。同步失败不阻止 Hub 提供既有归档的检索服务。
5. 失败后再次执行已有同步操作，或再次启动服务触发同步时，继续使用已持久化的进度，不重复导入已归档消息。

## 边界与约束

- 本次 Hub 交付范围仅为 Linux systemd 用户服务，不承诺 Windows 或 macOS 上的 Hub 运行方式。
- Windows、macOS、Linux 本机客户端继续通过既有 HTTPS 协议访问 Hub。客户端程序及其交互路径不变。
- 此次仅将已有一次同步操作接入服务启动后的生命周期；同步算法、API、CLI/MCP 和配置格式均不变。
- 凭据仅由相应 Linux 服务账号读取。服务必须在其实际运行环境中定位既有用户状态目录，不得依赖交互式登录 shell 才具备的环境。
- 不新增定时同步或自动重试策略。重试通过既有同步入口或再次启动服务完成。
- 当前 macOS 开发环境只能验证共用逻辑，不能提供 Linux systemd 服务启动、重启或机器重启后的实际运行证据。

## 设计决策

- 启动同步复用已有同步操作及其进度持久化、去重语义，不建立独立同步实现。
- 同步失败与归档检索服务可用性隔离。失败原因须能在实际 systemd 用户服务运行环境中获取。
- 服务账号、用户状态目录、凭据访问权限及服务环境与交互式环境的差异，会直接影响启动同步能否成立，因此必须使用实际 Linux systemd 用户服务验证，不能以手动运行同步命令代替。

待维护者确认：

- systemd 用户服务在机器重启后自动启动所需的启用条件，以及是否要求用户未交互登录时即可启动。该决定影响用户需要完成的配置、运行前提和机器重启验收场景；不能仅凭用户服务已安装推定重启后会自动运行。
- 失败原因的具体查看入口。该入口须适用于服务启动阶段，并能让维护者定位凭据、来源访问或同步执行失败。

## 验收条件

以下 Linux 验收均须使用实际 systemd 用户服务、实际服务账号及其用户状态目录。启动前已按既有方式配置来源凭据，并存在数据库进度和可检索的历史归档；除故障用例外，来源可访问且包含尚未归档的新对话。

1. **服务启动自动同步**：启动用户服务，不手动执行同步命令，确认已有同步操作被自动触发，新对话完成导入并可检索，历史归档仍可检索。
2. **服务重启自动同步**：在来源增加新对话后重启服务，确认自动拉取新增内容，沿用重启前的数据库进度，既有消息不重复导入，新增及历史内容均可检索。
3. **机器重启后自动同步**：维护者确认自动启动条件后，在满足该条件的 Linux 环境中重启机器。无需手动启动服务或运行同步命令，服务自动启动并完成新增对话导入；新增及历史内容均可通过既有 HTTPS 检索入口访问。若确认要求未交互登录即可启动，须在该状态下取得通过证据。
4. **服务环境下读取既有状态**：上述启动与重启场景须在实际服务环境中成功读取原有凭据及数据库进度，不依赖交互式 shell 额外注入配置，不要求重新录入凭据或重建归档。
5. **启动同步失败后仍可检索**：在实际用户服务环境中分别制造凭据不可读取和来源不可访问的条件，再启动服务。确认启动同步报告对应失败原因且不泄露凭据；通过既有 HTTPS 检索入口仍能检索历史归档。
6. **失败后重试不重复导入**：在实际用户服务环境中，使一次启动同步在已有部分消息持久化后失败。恢复故障后，分别验证通过既有同步入口重试及通过服务重启重试：剩余消息被导入，已归档消息无重复，完整结果可检索。
7. **验证覆盖边界**：macOS 上的共用逻辑测试可支撑同步调用、错误处理及去重逻辑的验证，但不能替代上述 Linux 生命周期、账号权限和服务环境证据。客户端未发生变更，无需在三个客户端平台重复完整测试；使用既有 HTTPS 入口验证服务结果即可。
8. **交付完成判定**：待确认事项须形成明确决定，并取得上述必需 Linux 场景的通过证据。当前尚无此类执行记录，不能据共用测试或包构建结果判定本次交付通过。具体机器、步骤、命令及执行顺序写入 plan.md。
