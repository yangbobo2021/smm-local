# 规格：检索同分结果按会话 ID 稳定排序

已确认意图见同目录 [intent.md](intent.md)。本次仅调整同分检索结果的排序规则，沿用项目现有支持范围及其他检索行为。

## 预期行为

1. 检索结果分数相同时，按数值会话 ID 升序排列。例如，会话 ID 为 `2` 和 `10` 的同分结果，`2` 排在 `10` 前。
2. 对同一组结果，无论输入列表如何排列，同分且会话 ID 不同的结果均得到相同顺序。
3. 不同分数之间维持原有排序规则；结果字段及其值、项目过滤语义均不变。
4. `limit` 的含义和边界行为保持不变。需要截取结果时，返回既有分数排序及新增同分排序规则确定的前若干项；截取边界落在同分结果中时，较小会话 ID 优先进入结果。
5. CLI、MCP 和 Web 均通过现有调用方式获得上述排序，不需要用户提供新增参数或配置。

## 边界与约束

- Windows、Linux、macOS 客户端均承诺相同的稳定排序语义，本次不缩减或扩大支持范围。
- 改动限于三平台共用的排序纯函数。其输入为已解码的 Python 数值分数和整数会话 ID，输出为排序后的列表。
- 会话 ID 使用数值比较，不能转换为字符串后按字典序排列。分数是否相同沿用现有数值比较语义，不引入近似相等或舍入规则。
- 不增加输入校验、类型转换或新的异常处理约定。
- 分数及会话 ID 均相同的记录，本次不增加第三排序键，也不承诺其排列独立于输入顺序。
- 不更改运行时范围、依赖、安装方式或服务；不新增 CLI、MCP 或 Web 专属排序层。

## 设计决策

采用现有分数排序规则作为首要排序依据，仅在同分时使用整数会话 ID 升序作为次要依据。

本次排序函数没有平台分支，不访问系统、文件、数据库、网络、时间或区域设置。三平台采用相同受支持的 Python 数值比较语义，各入口共用此函数。因此，当前 macOS 环境下对共用纯函数的合成输入验证，足以验收本次排序逻辑；无需为该改动要求 Windows、Linux 重复执行同一组用例。

上述充分性仅适用于所述纯函数及其既有调用关系。验收还须确认各入口继续使用该函数，且没有新增排序层或环境依赖。若实施改变这些前提，须在交付前补充相应规格及必要环境证据，不能继续沿用此覆盖结论。

本次无需新增环境或产品行为决定。

## 验收条件

以下行为用例均须在 macOS 的项目受支持 Python 环境中，以已解码数值分数和整数会话 ID 的合成输入取得通过证据：

1. **同分数值排序**：输入包含同分、ID 为 `10`、`2`、`1` 的结果，输出顺序为 `1`、`2`、`10`。
2. **输入顺序无关**：对同一组同分且 ID 不同的结果改变输入排列，每次输出的会话 ID 顺序完全一致，且为数值升序。
3. **混合分数排序**：输入包含多个分数组，每组包含不同会话 ID；输出的分数组顺序符合既有规则，各同分组内部按会话 ID 升序。改变输入排列后仍满足这两项要求。
4. **结果内容保持**：排序前后结果记录数量、字段及字段值均保持不变，无丢失、重复或新增记录。
5. **项目过滤保持**：包含多个项目的输入，在既有项目过滤条件下返回的记录集合与原语义一致，集合内部符合新增排序规则。
6. **limit 保持**：沿用既有受支持的 `limit` 值及边界判据，返回数量和边界处理不变；当截取位置位于同分组内时，返回按会话 ID 升序排列后的前若干项。打乱输入不改变选中的会话及顺序。
7. **列表边界**：空列表仍返回空列表；单条结果保持原记录及字段值。

同时须通过实现及调用关系审阅确认：

8. CLI、MCP 和 Web 继续调用同一个共用排序函数，没有各自新增的排序逻辑；三入口因此适用上述全部排序判据。
9. 函数保持无平台分支、无外部环境依赖，运行时与依赖支持范围不变，Windows、Linux、macOS 的支持承诺保持不变。

交付通过须同时满足上述行为验证与结构审阅。验证记录应明确实际执行环境为 macOS，不得据此表述 Windows 或 Linux 已实际运行通过；三平台语义覆盖依据为共用纯函数及相同数值比较语义。
