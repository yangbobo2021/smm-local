# 规格：明确 source rollback 简体中文帮助含义

依据同目录下已确认的 [intent.md](intent.md)，本次仅澄清帮助文案，不改变真实回退行为。现有材料足以确定交付与验收范围，无待维护者决定事项。

## 预期行为

1. 用户执行 `smm source --help` 时，`rollback` 的简体中文用途显示为：“将该插件来源的适配器切回上一版，保留已导入对话”。
2. 用户执行 `smm source rollback --help` 时，用途说明显示同一文案，明确回退对象是该插件来源的适配器，已导入对话予以保留。
3. 两条帮助命令均无需提供来源、档案或服务配置；均在创建档案对象前打印帮助，以状态码 `0` 退出，不访问来源、不写档案、不启动服务。
4. 命令名、参数及其解析规则、退出行为和真实回退操作保持不变。

## 边界与约束

- 本机端继续支持 Windows、Linux、macOS，不缩减或扩大平台范围。
- 变更仅限同一 Python 模块中的静态 argparse 帮助字符串，三平台共用该定义，无平台分支。
- 不修改命令解析、终端编码、输出组件、依赖或打包配置。
- 本次不新增回退能力，也不调整适配器回退或已导入对话的处理逻辑。项目保留已有回退功能测试。

## 设计决策

两条帮助入口使用一致的简体中文用途说明，使用户在来源总帮助和回退子命令帮助中均能理解操作对象及数据保留含义。

本次采用共享定义检查与当前 macOS 环境下两条帮助命令的实际输出验证作为充分验收依据。理由是改动仅涉及三平台共用的静态文本，相关解析、编码、输出和打包路径均不变，且已支持平台原本均可显示中文帮助，没有相关渲染或编码缺陷报告。

因此，不要求 Windows、Linux 重复执行本次帮助验收；此覆盖结论不表示已在这两个平台实际运行验证。若实施超出上述静态文本边界，应重新确认验收范围。

## 验收条件

1. **变更范围**：审阅确认仅修改目标静态帮助文案；三平台仍共用同一定义，无新增平台分支，命令解析、编码、输出、依赖及打包配置均无变化。
2. **macOS 来源总帮助**：在无需提供来源、档案或服务配置的状态下，执行 `smm source --help`，输出中的 `rollback` 用途为“将该插件来源的适配器切回上一版，保留已导入对话”；既有命令与参数说明保持不变，退出状态码为 `0`。
3. **macOS 回退子命令帮助**：在同样状态下，执行 `smm source rollback --help`，用途说明为上述完整文案；既有参数、必填性及默认值说明保持不变，退出状态码为 `0`。
4. **两条帮助入口的无副作用行为**：上述两个 macOS 用例均在创建档案对象前完成帮助输出并退出，不访问来源、不写档案、不启动服务。
5. **兼容性与证据边界**：审阅确认真实回退实现及已有回退功能测试未被修改。结合共享静态定义检查和两条 macOS 帮助入口的通过证据，可判定本次文案变更完成；仅检查字符串或包构建成功，不能替代这两条实际帮助输出的验证。
