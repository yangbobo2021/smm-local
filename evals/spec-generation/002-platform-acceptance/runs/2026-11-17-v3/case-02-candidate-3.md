# 规格：明确来源回退命令的简体中文用途

意图依据：[已确认意图](./intent.md)。

## 预期行为

1. 用户执行 `smm source --help` 时，`rollback` 的用途说明显示为“将该插件来源的适配器切回上一版，保留已导入对话”，明确回退对象是该插件来源的适配器，已导入对话会保留。
2. 用户执行 `smm source rollback --help` 时，帮助正文显示同一用途说明。
3. 两条帮助命令均无需提供来源、创建档案或启动服务；打印帮助后以状态码 `0` 退出，不访问来源、不写档案。
4. 命令名、可用参数、参数解析、退出行为及真实回退操作保持不变。

## 边界与约束

- 本次仅修改同一 Python 模块中的静态 argparse 简体中文帮助字符串，不改变回退功能。
- 本机端继续支持 Windows、Linux、macOS，不缩减或扩大支持范围。
- 三平台共用同一帮助字符串定义，无平台分支。命令解析、终端编码、输出组件、依赖和打包配置均不变。
- 原版本在三平台均可显示中文帮助，且没有本说明文本的渲染或编码缺陷报告。本次不引入平台专属展示行为。
- 保留项目既有回退功能测试，不因本次文案修改调整其行为预期。

## 设计决策

两条帮助入口共用上述用途表述，避免对回退对象及对话保留行为产生不同解释。

本次使用 macOS 上两条实际帮助命令的输出和退出行为证据，结合静态定义及变更范围审查完成验收。该覆盖适用于本次共用静态文本修改：三平台没有相关分支，中文输出能力已有支持承诺，且输出链路没有变化。因此不要求 Windows、Linux 重复运行本次帮助用例；这不代表本次已在这两个平台实际运行验证。

若实施发现平台分支，或需要修改编码、输出链路、依赖或打包配置，则超出本规格范围，须重新确认变更范围及必要的平台验收覆盖。

## 验收条件

1. **变更范围审查通过**：仅修改目标静态帮助字符串；命令名、参数定义、解析逻辑、退出逻辑、真实回退操作及打包配置均无变化。两条帮助入口均使用已确认文案。
2. **macOS 总帮助通过**：在未提供来源、未启动服务的状态下，执行 `smm source --help`，输出中 `rollback` 的用途为“将该插件来源的适配器切回上一版，保留已导入对话”，中文可读，允许终端正常折行；打印后以状态码 `0` 退出。
3. **macOS 子命令帮助通过**：在与第 2 条相同的状态下，执行 `smm source rollback --help`，帮助正文显示同一完整用途说明，中文可读，允许终端正常折行；打印后以状态码 `0` 退出。
4. **两条帮助入口的兼容行为通过**：第 2、3 条各自的执行均在创建档案对象前结束，不访问来源、不写档案、不启动服务；各入口原有参数及其他帮助内容保持不变。
5. **覆盖边界明确**：交付须具备上述 macOS 实际运行证据和共用静态定义的审查结果。Windows、Linux 的支持承诺继续保留，本次不声明其已实际运行通过；无需以三平台重复完整回退测试作为本次文案变更的通过条件。
