# 规格：Hub 自动归档 VibeInsight 历史与项目关联检索

本规格依据同目录下已确认的 [intent.md](intent.md)。尚需维护者决定的事项在下文标明。

## 预期行为

### 来源配置与服务恢复

1. 维护者通过 Hub CLI 提交 VibeInsight 来源连接参数和凭据时，CLI 验证连接及只读查询能力；仅在验证成功后保存为有效配置。
2. 新配置验证失败时，CLI 返回可判断的失败结果，原有效配置和凭据继续生效；首次配置失败时，不产生有效来源配置。
3. 保存成功后，Hub 长期运行服务能够使用该配置调用 `psql` 读取来源。CLI 与服务使用不同账号或环境时，仍须保证服务能够找到并执行 `psql`、读取连接参数及秘密文件。
4. Hub 重启后自动恢复来源同步，无需维护者重新输入密码。

### 历史与增量同步

1. 来源配置生效后，Hub 自动归档 VibeInsight 中该凭据可读取的全部项目历史，无需逐项目建立关联后才同步。
2. 来源出现新会话事件或已有会话追加轮次时，Hub 持续同步新增内容，并保留其来源、项目、原会话及消息位置。
3. 来源后来新增可读项目时，Hub 补齐该项目的可读历史，包括早于现有同步进度的数据。
4. 来源暂时不可用、凭据失效或读取失败时，已提交归档仍可检索和读取。来源恢复后，Hub 自动重试尚未成功归档的数据。
5. 重复读取、失败重试、近期事件回查及重启恢复不产生重复归档，也不跳过尚未成功提交的数据。
6. 每批归档与对应同步进度共同提交；批次未提交成功时，不得仅推进进度。重启后从已提交位置继续。

### 项目关联与查询

1. Hub 维护者统一管理项目关联，可建立或解除设备项目与 VibeInsight 项目之间、不同设备项目之间的关联。
2. 关联关系双向生效。项目查询包含当前项目及其直接关联项目，不继续扩展直接关联项目的其他关联。
3. 建立关联后，双方项目查询均能检索对方已有归档及后续归档。
4. 解除关联后，双方查询不再因该关系扩展到对方；已归档数据不删除，原文引用继续可用。若双方仍通过其他有效查询范围被包含，其数据仍可返回。
5. 本机端补传项目归属；支持项目查询的 CLI/MCP 请求携带当前项目身份。项目身份不得仅依赖项目名称，同名项目须保持可区分。
6. 现有 CLI/MCP 能检索并读取 VibeInsight 归档。返回结果包含来源、项目、原会话和消息位置，并能据此精确读取对应原文。
7. 旧客户端不携带项目身份的全局查询继续可用。
8. Hub 不可用时，CLI/MCP 沿用现有本机全局回退行为。

## 边界与约束

- 首版为单用户，不引入多用户权限模型。
- 来源访问仅执行只读查询，不修改 VibeInsight 数据。
- 同步覆盖新增会话事件和追加轮次；不要求发现没有新增事件的历史正文原地改写。
- 项目关联只影响查询范围，不作为归档前提，不改变数据来源身份，也不因解除关联删除归档。
- 保持 Windows、Linux、macOS 支持，不得以当前仅有 macOS 执行条件为由缩减平台范围。
- 保持既有服务运行方式：Windows 使用 LocalService 系统服务，Linux 使用 systemd 用户服务，macOS 使用 launchd 系统服务。
- 密码原值不得出现在 CLI 输出、日志或对话数据库中。
- 同名项目不得混淆；既有原文引用在本次变更后继续可用。
- 不要求在真实 VibeInsight 服务器造数；未来默认回归可使用合成事件。
- 当前仅具备 macOS 执行条件，Windows/Linux 尚无本次执行记录，不能据此声明已通过三平台验收。

## 设计决策

1. **来源读取使用外部 `psql`。** 由 Hub 服务调用，须兼容三平台及既有服务账号环境，不得依赖仅在交互式 CLI 环境中可见的安装路径。
2. **连接参数与密码分开保存。** 连接参数保存在 Hub 配置文件，密码保存在服务状态目录的专用秘密文件。服务运行账号能够读取秘密文件，其他未授权普通账号不能读取。
3. **先验证，再替换有效配置。** 验证失败或保存失败均不得破坏原有效配置；成功保存后，配置与凭据应对应同一次验证。
4. **归档与进度使用同一提交边界。** 同步进度保存在 Hub 数据库，通过近期事件回查及去重支持恢复；全局已有进度不得阻止新增可读项目的历史补齐。
5. **项目身份与来源定位信息保持稳定。** 查询扩展依据项目身份而非名称，原文定位不依赖当前关联关系。

尚需维护者确认：

- 来源配置、`psql` 路径设置及项目关联管理的具体 CLI 命令和参数。
- 同步周期、失败重试间隔及近期事件回查窗口。
- CLI/MCP 中来源身份、项目身份及原文位置的具体字段和兼容表达方式。
- 三平台秘密文件权限设置及 CLI 向服务账号交付配置的具体方式；该决定须满足上述安全与服务可读性要求。

## 验收条件

1. 有效来源配置通过 CLI 验证并保存后，Hub 服务可自动读取来源；服务重启后无需重新输入密码即可继续同步。
2. 提交无效凭据或不可用连接时，配置操作明确失败，原有效配置仍能使用；首次失败不留下有效配置。
3. CLI 与服务账号或环境不同时，服务仍能执行已配置的 `psql` 并读取凭据。Windows、Linux、macOS 均须有对应验收证据。
4. 未授权普通账号无法读取密码文件；CLI 输出、日志及对话数据库均不含密码原值。
5. 首次同步后，所有可读项目的历史均可通过现有 CLI/MCP 检索并读取，无需先建立项目关联。
6. 新会话事件及旧会话追加轮次均能自动进入归档，返回结果可精确定位并读取对应原文。
7. 新增可读项目包含早于已有进度的历史时，该历史仍被完整补齐。
8. 来源失败期间已有归档仍可查询；来源恢复后，未成功归档的数据自动补齐。
9. 批次失败或 Hub 重启后，不存在仅推进进度导致的数据遗漏；重复读取及近期回查不产生重复归档。
10. 设备项目与 VibeInsight 项目、不同设备项目均可建立双向关联。若 A 关联 B、B 关联 C，A 的查询包含 A、B，但不因该路径包含 C。
11. 解除关联后，查询范围按剩余直接关联更新，归档仍保留，既有原文引用仍可读取。
12. 同名但身份不同的项目可独立查询；本机补传的项目归属能被项目查询使用。
13. 旧客户端全局查询继续可用；Hub 不可用时，CLI/MCP 按既有行为回退到本机全局查询。
14. 三平台既有服务类型保持不变；来源读取不产生写操作。
15. 没有新增事件的历史正文原地改写不作为同步完整性的验收要求。
