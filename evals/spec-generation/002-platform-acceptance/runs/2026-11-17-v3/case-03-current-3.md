# 规格：同分检索结果按会话 ID 稳定排序

以同目录下已确认的 [intent.md](intent.md) 为依据。本草稿无待维护者决定的事项。

## 预期行为

1. 检索结果分数相同时，按数值会话 ID 升序排列。例如，会话 ID 为 `10` 和 `2` 的同分结果，`2` 排在 `10` 之前，不受输入列表顺序影响。
2. 检索结果分数不同时，保持现有排序规则；会话 ID 仅用于同分结果的次级排序。
3. 对同一组结果打乱输入顺序后，同分且会话 ID 不同的结果仍得到相同的相对顺序。
4. CLI、MCP 和 Web 均沿用共用排序函数，呈现一致的排序语义；Windows、Linux、macOS 的排序语义一致。
5. 结果字段、项目过滤及 limit 语义保持不变。limit 截取到同分结果组内部时，保留结果的顺序及入选范围应符合会话 ID 升序规则。

## 边界与约束

- 适用范围为三平台共用的纯排序函数，输入为已解码的 Python 数值分数和整数会话 ID，输出为排序后的列表。
- 分数是否相同沿用受支持的 Python 数值比较语义，不引入近似相等或额外的分数转换。
- 会话 ID 按整数数值比较，不按字符串字典序比较。
- 空列表和单条结果列表保持原有输出行为。
- 分数和会话 ID 均相同的结果，本次不新增排序依据，保持现有处理行为。
- 不增加平台分支或各入口独立的排序逻辑，不改变运行时范围、依赖、安装或服务。
- 纯函数继续不访问系统、文件、数据库、网络、时间或区域设置。

## 验收条件

1. 给定两条同分结果，会话 ID 分别为 `10` 和 `2`，无论输入顺序如何，输出均为 `2` 在前、`10` 在后。
2. 给定多条同分且会话 ID 不同的结果，打乱输入顺序后，输出均按会话 ID 数值升序排列。
3. 给定不同分数的结果，即使会话 ID 顺序与现有分数排序方向冲突，仍保持现有分数排序规则。
4. 给定包含多个分数组的结果，各分数组之间保持现有排序，各组内部按会话 ID 升序排列。
5. limit 截取位置位于同分结果组内部时，入选结果符合新增排序规则；返回数量及其他 limit 行为与现有语义一致。
6. 排序后每条结果的字段和值保持不变；项目过滤的规则及符合过滤条件的结果集合保持不变。
7. 空列表、单条结果以及分数和会话 ID 均相同的结果，保持原有处理行为。
8. CLI、MCP 和 Web 继续使用共用函数，无额外排序层；三平台使用相同的排序规则，无平台分支。

跨平台验收要求为排序语义一致。当前材料仅说明 macOS 可用合成输入验证，未提供本次实际验证结果或 Windows、Linux 执行记录，不据此声称已完成三平台实测。
