# 规格：SMM 同分检索结果按会话 ID 稳定排序

已确认意图见同目录下的 [intent.md](intent.md)。

## 预期行为

1. 检索结果分数相同时，按数值会话 ID 升序排列，不受输入列表中这些结果的先后顺序影响。
2. 检索结果分数不同时，保持现有的分数排序规则。
3. CLI、MCP 和 Web 均沿用共用排序函数，呈现相同的排序语义。
4. Windows、Linux 和 macOS 上均采用上述排序语义。
5. 结果字段、项目过滤规则及 limit 语义保持不变。当 limit 的截断边界落在同分结果之间时，返回结果遵循会话 ID 升序规则。

## 边界与约束

- 变更范围限于三平台共用的排序纯函数；输入为已解码的 Python 数值分数和整数会话 ID，输出为排序后的列表。
- 会话 ID 按数值比较，例如 `2` 排在 `10` 前面。
- 不增加平台分支或 CLI、MCP、Web 各自的排序层。
- 不引入系统、文件、数据库、网络、时间或区域设置依赖；不变更运行时范围、依赖、安装或服务。
- 空列表和单条结果保持现有行为。
- 分数和会话 ID 均相同的结果，本次不新增第三排序键。
- 材料未说明特殊数值分数（如 NaN）的支持范围及既有行为；若当前输入契约允许此类值，需维护者在实施前确认其适用规则，本草稿不新增规则。

## 验收条件

1. 给定两条同分结果，会话 ID 分别为 `10` 和 `2`，无论输入顺序如何，输出均为 `2`、`10`。
2. 给定多条同分且会话 ID 不同的结果，打乱输入后，输出仍按会话 ID 数值升序排列。
3. 给定分数不同的结果，输出相对顺序与变更前的分数排序规则一致，不因会话 ID 改变。
4. 给定包含多个分数组的结果，各分数组之间保持原排序规则，每个同分组内部按会话 ID 升序排列。
5. 给定会在同分组内截断的 limit，返回数量符合现有 limit 语义，截断所保留的同分结果遵循会话 ID 升序规则；其他既有 limit 行为保持不变。
6. 排序前后结果字段及其值保持不变；项目过滤的纳入和排除规则保持不变。
7. 空列表和单条结果的输出与既有行为一致。
8. CLI、MCP、Web 以及 Windows、Linux、macOS 均适用上述条件，不存在入口或平台特有的排序差异。现有材料仅提供 macOS 可验证条件，不代表已完成其他平台的执行验收。
