# 规格：Hub 重启后自动恢复同步

依据：[已确认意图](./intent.md)。

## 预期行为

1. 已配置数据来源并完成后台运行配置后，机器重启，Hub 自动启动并继续同步这些来源，无需用户打开交互式终端、手动执行同步命令或重新输入凭据。自动启动发生于系统启动还是用户登录后，须由维护者确认，不能默认两者等价。

2. Hub 恢复运行时沿用已有归档及同步进度，不清空归档、不将已完成的同步重置为首次导入。恢复同步后，已有内容仍可检索，新内容按现有同步规则导入，已导入内容不重复导入。

3. 后台运行能够取得已持久化的凭据。凭据配置入口须说明凭据用于哪个来源、如何从当前配置迁移或首次录入、由哪个运行账号读取，以及如何更新。具体入口和必要配置值须在服务环境、运行账号和存储方案确认后确定，不能要求用户自行猜测服务如何继承交互式终端的环境变量。

4. 某个来源不可达时，Hub 保留已有归档和进度，已有归档仍可检索，并向用户报告受影响来源及同步失败状态。来源恢复后，Hub 无需人工重新配置即可自动重试，并从保留的进度继续同步，不重复导入。失败状态的查看入口及重试时机须在实施前确认。

5. 凭据缺失、失效或后台账号无权读取凭据、归档或进度时，Hub 报告相应配置或访问失败，保留已有数据，不以清空归档、重置进度或静默跳过来源作为恢复方式。用户修正配置后，应能够恢复同步。

## 边界与约束

- Python 3.11+ 是现有运行要求，不能据此推断操作系统、后台服务类型或部署账号。
- 当前仅有 macOS 交互式终端运行原前台命令的记录，不能作为后台运行、机器重启恢复或其他操作系统支持的证据。
- 本次后台组件的操作系统和部署范围尚未确认。不得默认仅支持 macOS，也不得声明新增 Windows/Linux 支持。该决定影响自动启动机制、凭据存储、文件权限及必需的实际环境验收，属于交付前必须解决的事项。
- 原前台同步命令通过环境变量取得凭据的使用方式须保持兼容；新增凭据持久化不得强制现有前台用户改用后台部署。
- 已有归档及进度须能够由选定的后台运行账号继续使用。不得因账号或工作目录变化创建一套空数据，并将其视为恢复成功。
- 来源不可达不应使已有归档失去检索能力。后台运行与检索入口之间如何协作，须在部署方案确定时明确。

## 设计决策

以下事项需维护者在实施前确认：

| 待确认事项 | 必须明确的内容及影响 |
|---|---|
| 支持环境 | 本次后台组件支持的操作系统、部署方式及适用范围；决定实际平台验收范围。 |
| 启动与进程生命周期 | 系统启动或用户登录触发、是否要求登录、后台进程如何持续运行；决定何种重启状态算自动恢复成功。 |
| 运行账号与数据访问 | 使用哪个账号、如何定位并访问已有归档和进度、如何供检索入口访问；决定权限与跨进程访问验收。 |
| 凭据持久化 | 存储及保护机制、录入与更新入口、从原环境变量配置迁移的方式、后台账号的读取条件；决定重启后免重新输入是否成立。 |
| 故障反馈与重试 | 用户查看失败的入口、状态内容、自动重试时机及恢复成功的判定；决定失败是否可见、恢复是否可验证。 |

凭据读取、数据定位和自动启动均依赖服务环境及运行账号，不能以交互式终端中运行成功替代后台验证。所选凭据机制若依赖登录会话或解锁状态，必须明确其与自动启动承诺是否相容。

## 验收条件

1. **范围及操作入口完整**  
   上述待确认事项均已形成明确决定并纳入规格。用户能够依据确定的入口完成后台配置、凭据录入或迁移、状态查看及凭据更新，无需补猜必要配置。范围未确认时，不能判定本次交付通过。

2. **实际重启恢复**  
   在每一种已确认支持的后台部署环境中，以选定运行账号配置来源、持久化凭据，并预先保存可检索归档及非初始同步进度。执行真实机器重启后，在已确认的启动或登录条件下，Hub 自动运行，无需手动启动或重新输入凭据；原归档仍可检索，原进度被沿用，新内容成功导入，已有内容不重复导入。验证不得依赖重启后另行打开的交互式终端提供凭据或环境变量。

3. **来源故障及恢复**  
   第 2 条所述每一种部署环境均须取得以下实际运行证据：来源在自动恢复时不可达，Hub 保留归档与进度，检索入口仍能检索已有内容，指定状态入口报告对应来源失败；来源恢复后，Hub 按确定的重试规则自动继续同步，新内容成功导入，已有内容不重复导入。仅证明服务能启动不足以通过。

4. **凭据与访问权限异常**  
   在各已确认部署环境中，覆盖所选机制实际存在的凭据缺失、失效、不可读取及数据访问权限不足状态。Hub 在指定入口报告对应失败，已有归档和进度未被删除或重置；修正配置后可继续同步，且无重复导入。凭据更新后，后台运行能够使用更新值，重启后仍无需再次输入。

5. **前台兼容**  
   原前台命令仍能使用环境变量提供凭据，并按原有方式同步。该检查须取得原有 macOS 交互式运行方式下的通过证据；它不代表后台运行或其他平台已通过。

6. **证据充分性**  
   归档保留、进度恢复及去重的共用逻辑可复用自动化验证，但不能替代各已确认部署环境中的实际重启、凭据读取、权限访问、故障检索及恢复同步证据。不同环境可共用上述行为判据，无需重复全部内部测试。缺少任何必需环境的关键证据，交付仍未完成。

具体机器、实现位置、实施顺序、测试步骤、命令及 CI 配置写入 `plan.md`。
