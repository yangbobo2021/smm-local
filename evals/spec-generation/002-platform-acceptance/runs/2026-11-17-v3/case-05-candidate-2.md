# 规格：Hub 重启后自动恢复同步

已确认意图见同目录 [intent.md](intent.md)。本规格依据已提供的意图和项目资料起草；支持平台、后台运行方式、部署账号及凭据持久化方案仍需维护者确认。

## 预期行为

1. 完成后台运行配置后，机器重启时 Hub 自动启动，并继续同步此前已配置的数据来源，无需用户打开交互式终端或重新输入凭据。已配置来源的配置、已有归档和同步进度在重启后保留。

2. 恢复同步时，Hub 根据持久化进度继续处理来源数据。已经成功导入的数据不重复导入；启动或同步中断不得导致已有归档丢失，也不得因进度提前记录而跳过尚未成功归档的数据。

3. 某个来源不可达时，Hub 保留其已有归档，用户仍可通过现有检索入口检索这些内容。Hub 报告该来源同步失败，不得将失败显示为同步成功；其他可达来源继续同步。

4. 来源恢复可达后，Hub 自动重试并继续同步，无需用户重新配置来源或输入凭据。重试沿用已有归档和进度，不重复导入此前成功归档的数据。

5. 后台运行配置入口必须向操作者说明以下内容，使其能够完成配置：
   - 适用的操作系统、后台运行方式，以及是否需要用户登录。
   - 后台进程使用的账号，以及该账号对来源配置、归档、同步进度和凭据的访问要求。
   - 来源凭据如何首次提供、持久化、更新，以及如何确认后台进程能够读取。
   - 如何确认自动启动已启用，以及从何处查看运行状态和来源同步失败信息。

   具体配置入口、必要配置值及其获取或确认途径须在相关设计决定确认后补齐，不得以沿用交互式终端环境变量代替后台配置说明。

## 边界与约束

- 已知运行要求仅为 Python 3.11+。现有资料未声明支持的操作系统、服务类型或部署账号，不能据此认定已支持 macOS、Windows 或 Linux。
- 当前 macOS 开发电脑上原前台命令的运行经历，只能证明该次交互式运行情况，不能证明重启后的后台启动、凭据读取或归档访问成立。
- 本次涉及 Hub 同步执行、启动接入、凭据持久化，以及已有归档检索在来源失败时的可用性。未受影响的组件不纳入新增平台验收范围。
- 保持原前台同步命令通过环境变量取得凭据的现有行为。新增持久化凭据与环境变量之间的优先级、适用入口及冲突处理须明确，避免静默使用错误凭据。
- 来源故障不得清除已有配置、归档或进度。失败报告不得暴露凭据。
- 操作系统、后台运行方式和部署账号的选择会改变实现及验收要求，目前不能默认仅支持 macOS，也不能视为已承诺新增 Windows/Linux 支持。

## 设计决策

以下事项须由维护者在实施前确认，确认后回填本规格：

| 待确认事项 | 必须明确的内容及影响 |
| --- | --- |
| 本次交付环境 | 操作系统及必要版本范围、后台运行方式、是否依赖登录。决定启动接入实现和实际环境验收范围。 |
| 部署账号与数据位置 | 后台账号、来源配置及归档和进度的位置、必要权限，以及如何接续原前台运行的数据。账号或路径变化不得形成空白归档或丢失进度。 |
| 凭据持久化 | 存储方式、首次配置及更新入口、访问保护、与环境变量的优先级。须确认重启后目标后台账号在约定登录状态下能够读取，不能假定交互式会话中的凭据访问能力可直接继承。 |
| 自动重试 | 重试触发方式、间隔或退避规则，以及成功恢复的判定方式。规则须足以判断恢复后是否在约定时限内继续同步。 |
| 状态与失败报告 | 用户查看状态和错误的入口，如何区分来源失败、凭据不可用、权限错误与启动失败，以及恢复成功后如何更新状态。 |

同步执行应复用持久化归档和进度，后台启动接入负责在所确认的环境中启动同步并提供必要配置。进度记录与归档写入必须协调，保证重启和重试既不漏导，也不重复导入。

后台环境可能缺少交互式终端的环境变量、文件权限或凭据解锁状态。这些差异直接影响本次承诺，因此实际后台账号、登录状态和重启后的进程生命周期必须纳入验收，不能仅以手动启动成功替代。

## 验收条件

1. **交付范围与配置可执行性**
   
   维护者已确认并记录支持的实际环境、后台运行方式、部署账号、凭据方案、重试规则及状态入口。操作者能够依据配置说明完成首次配置、凭据更新、自动启动启用和状态确认，无需依赖未说明的终端会话状态。必要决定未确认时，本规格仍为待审阅草稿，不能判定交付通过。

2. **实际后台环境中的重启恢复**
   
   在每一种确认纳入交付的操作系统与后台运行方式组合中，使用约定部署账号和登录状态，预先配置有效凭据、至少一个来源、已有归档及同步进度。机器实际重启后，Hub 自动启动，无需打开终端或重新输入凭据；原归档仍可检索，原配置和进度保留，来源新增数据能够继续同步，已成功归档的数据不重复导入。

3. **来源失败、检索与自动恢复**
   
   在第 2 条各适用环境中，由实际后台进程执行以下完整行为判据：已有归档和进度的来源不可达后，状态入口显示该来源失败且不泄露凭据；现有检索入口仍能检索其归档，其他可达来源继续同步。来源恢复后，Hub 在确认的重试规则内自动继续同步，导入新增数据，更新恢复状态，且无须重新配置或输入凭据，不产生重复导入。

4. **同步中断后的数据一致性**
   
   在第 2 条各适用环境中，后台同步处理新增数据期间发生机器重启，恢复后最终归档包含应导入的数据，已成功归档的数据没有重复，尚未完成归档的数据没有被进度记录跳过，已有归档仍可检索。验收须覆盖归档写入与进度记录之间可能发生中断的关键状态。

5. **凭据及权限边界**
   
   在各确认的后台账号及凭据访问条件下，首次配置和凭据更新后均可实际同步；重启后继续有效。凭据缺失、不可读取或归档及进度访问权限不足时，约定入口提供可辨识的失败信息，不误报成功、不清除已有数据、不泄露凭据。修复配置或权限后，能够按确认的恢复规则继续同步。

6. **原前台入口兼容**
   
   在确认适用的运行环境中，原前台命令仍可通过环境变量取得凭据并完成同步。若同时存在持久化凭据，实际选用结果符合已确认的优先级；前台与后台接续使用已有归档和进度时，不产生重复导入或进度丢失。

7. **证据充分性**
   
   去重、进度一致性和状态转换的共用逻辑可复用同一套测试判据，配置说明也可集中审阅；这些验证不能替代上述实际后台环境中的重启、凭据访问、故障恢复及检索证据。不同环境无需重复全部共用逻辑测试，但每个承诺环境必须取得其对应关键行为的通过证据。缺少必需环境或关键状态的证据即为未完成，不能仅标记“未验证”后判定交付通过。
