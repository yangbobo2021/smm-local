# 规格：SMM 同分检索结果按会话 ID 稳定排序

本规格依据同目录下已确认的 [intent.md](intent.md)。现有材料足以确定本次排序规则，无待维护者决定事项。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列，不受输入列表顺序影响。例如，会话 ID 为 `2` 和 `10` 的同分结果，`2` 排在 `10` 前。
2. 检索结果分数不同时，保持现有排序规则；会话 ID 不改变不同分数结果的相对顺序。
3. CLI、MCP 和 Web 均通过现有共用函数获得上述排序结果。
4. 项目过滤规则及结果字段保持不变。
5. limit 的既有语义保持不变；当 limit 截断同分结果时，入选结果及其顺序符合会话 ID 数值升序规则。

## 边界与约束

- 变更适用于 Windows、Linux 和 macOS，三平台采用相同排序语义。
- 输入为已解码的 Python 数值分数和整数会话 ID，使用现有受支持的 Python 数值比较语义，不新增类型转换或输入校验规则。
- 空列表仍返回空列表；单条结果的内容和顺序不变。
- 分数及会话 ID 均相同的结果，不新增其他排序依据，保持其既有相对顺序。
- 不改变运行时支持范围、依赖、安装或服务。
- 共用纯函数保持无系统、文件、数据库、网络、时间或区域设置访问，不引入平台分支。
- 当前仅具备 macOS 上使用合成输入验证的条件；没有本次 Windows 或 Linux 执行记录，不将其描述为已完成的跨平台实测。

## 设计决策

在现有三平台共用的排序纯函数中，以会话 ID 数值升序作为分数相同时的次级排序规则。CLI、MCP 和 Web 保持原调用方式，不增加入口专属排序层。

该选择使所有入口和平台共享同一规则，并保持不同分数结果的既有排序行为。

## 验收条件

1. 两条分数相同、会话 ID 分别为 `2` 和 `10` 的结果，无论输入顺序如何，输出均为 `2`、`10`。
2. 多条同分且会话 ID 不同的结果，在输入列表被打乱后，输出仍按会话 ID 数值升序排列。
3. 混合不同分数和同分结果时，不同分数结果保持原排序，同分组内按会话 ID 数值升序排列。
4. 分数及会话 ID 均相同的结果保持既有相对顺序。
5. limit 截断同分组时，返回数量符合既有 limit 语义，入选结果及其顺序符合新的同分排序规则；其他既有 limit 边界行为不变。
6. 项目过滤后的结果成员保持不变，各结果的字段和值保持不变。
7. 空列表和单条结果满足上述边界行为。
8. CLI、MCP 和 Web 沿用共用函数，均遵循同一排序规则。
9. 三平台共用相同排序逻辑和受支持的数值比较语义，无新增平台分支或外部环境依赖；验收记录明确区分 macOS 实测结果与尚无执行记录的平台。
