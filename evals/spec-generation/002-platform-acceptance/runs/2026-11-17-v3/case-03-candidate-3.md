# 规格：同分检索结果按数值会话 ID 稳定排序

本规格依据同目录下已确认的 [intent.md](intent.md) 及项目现有承诺起草。

## 预期行为

1. SMM 返回检索结果时，保持现有分数排序规则；分数相同的结果按整数会话 ID 的数值升序排列。例如，同分结果的会话 ID 为 `10`、`2` 时，`2` 排在 `10` 前。
2. 对于包含相同结果的不同输入排列，排序后的分数与会话 ID 序列一致。同分且会话 ID 不同的结果，其相对顺序不受输入列表顺序影响。
3. 不同分数结果的相对顺序、返回结果字段、项目过滤规则及 limit 语义保持不变。同分结果位于 limit 截断边界时，按会话 ID 升序确定保留项，不改变既有截断规则。
4. CLI、MCP 和 Web 沿用共用函数，均呈现上述排序行为。用户或调用方无需提供新增输入或配置。

## 边界与约束

- Windows、Linux、macOS 均继续受支持，并承诺相同的稳定排序语义。
- 本次改动限于三平台共用的纯排序函数。其输入为已解码的 Python 数值分数和整数会话 ID，不新增字符串解析、类型转换或输入校验规则。
- 不改变运行时支持范围、依赖、安装方式或服务。
- 空列表、单项列表及没有同分项的列表保持现有行为。
- 分数和会话 ID 均相同的结果，本次不新增进一步的排序规则，也不承诺这些结果在输入打乱后仍具有相同的逐项顺序。
- 项目资料未明确特殊数值分数（例如 NaN）的既有处理规则；本次不新增此类规则。如需改变其处理方式，须由维护者另行确认。

## 设计决策

以现有分数排序规则为第一排序依据，仅在分数相同时使用整数会话 ID 升序作为第二排序依据。CLI、MCP 和 Web 不增加独立排序层，以保证各入口语义一致。

本次验收采用 macOS 上对共用纯函数的合成输入验证，并核对三个入口继续复用该函数。其充分性依据为：函数无系统访问、外部状态或平台分支，三平台采用相同受支持的 Python 数值比较语义，且本次未改变运行时或部署条件。因此不要求 Windows、Linux 重复实际运行同一套排序用例，也不要求三个入口分别进行完整端到端测试。

上述验证仅证明共用逻辑在已知前提下满足三平台承诺，不表述为 Windows、Linux 已实际运行通过。若审阅或实施发现平台分支、入口额外排序或数值比较语义差异，则本验收依据不再充分，须在受影响环境取得对应行为的实际通过证据后才能完成交付。

## 验收条件

以下行为用例均在 macOS 上直接调用共用纯函数，以已解码的 Python 数值分数和整数会话 ID 为输入；通过判据共同适用于 Windows、Linux、macOS 的排序承诺。

1. **同分数值排序**：输入同分且会话 ID 包含 `10`、`2`、`1` 的结果，输出会话 ID 顺序为 `1`、`2`、`10`。
2. **输入顺序无关**：对包含多个分数组、每组有不同会话 ID 的同一批结果使用不同输入排列，输出的分数与会话 ID 序列完全一致；每个同分组均按 ID 数值升序。
3. **不同分数兼容**：输入包含不同分数及同分项的结果，输出的不同分数组顺序与既有分数排序规则一致，仅同分组内按 ID 升序排列。
4. **limit 边界**：使用既有支持的 limit 值，分别覆盖截断点位于同分组内、结果数量以内及结果数量以上的情形。输出数量和截断规则符合原语义，同分组内按 ID 升序确定保留项。
5. **字段与项目过滤兼容**：使用含多个项目及附加结果字段的合成数据，在既有项目过滤和 limit 调用路径下，确认项目筛选结果不变、返回字段和值不变，并对符合条件的结果应用新的同分排序规则。
6. **基本边界兼容**：空列表、单项列表和无同分项列表的输出符合既有行为；分数与会话 ID 均相同的结果不丢失、不重复。
7. **入口覆盖**：核对 CLI、MCP 和 Web 均继续调用上述已验收函数，且没有额外排序层或独立截断路径改变结果。三个入口均无需新增参数或配置。
8. **覆盖依据成立**：确认排序函数仍无系统访问、外部状态及平台分支，三个入口仍共用该实现，且运行时和数值比较语义未改变。若任一前提不成立，必须补齐受影响入口或实际平台上的相关验收证据；缺失时不得判定交付通过。
