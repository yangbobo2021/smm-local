# 规格：明确来源管理命令帮助

依据同目录下已确认的 [intent.md](intent.md)，本次仅完善 `smm source` 的 CLI 帮助文案。无待维护者确认事项。

## 预期行为

1. 用户执行 `smm source --help` 时，帮助以简体中文说明全部八个现有子命令的用途，使用户能直接选择对应操作：

   | 子命令 | 帮助须表达的含义 |
   |---|---|
   | `list` | 查看以来源 ID 为键的本机来源状态。 |
   | `validate` | 使用来源清单和测试样本验收候选适配器。 |
   | `register` | 验收候选适配器，通过后注册来源。 |
   | `enable` | 启用指定来源的导入。 |
   | `disable` | 停用指定来源的导入，保留已导入记录。 |
   | `rollback` | 将指定插件来源的适配器切回上一版。 |
   | `batches` | 查看指定插件来源的导入批次。 |
   | `purge-batch` | 从 SMM 本机档案删除指定批次已导入的记录。 |

2. `smm source --help` 须明确提示：清理批次前，必须先停用对应的插件来源；来源仍启用时，清理会被拒绝。用户能够区分：
   - 停用改变后续导入状态，并保留已导入记录。
   - 回退改变插件来源使用的适配器版本。
   - 清理删除本机档案中指定批次已导入的记录。

3. 用户执行 `smm source purge-batch --help` 时，帮助须说明：
   - `source_id` 是待清理批次所属插件来源的 ID，可通过 `smm source list` 查看本机来源状态并确认。
   - `batch` 是该来源的整数批次 ID，应通过 `smm source batches <source_id>` 查询，并取目标批次记录的 `id`，不能用列表序号代替。
   - 清理前须执行 `smm source disable <source_id>`，停用同一个插件来源；来源仍启用时拒绝清理。
   - 清理会从 SMM 本机档案删除指定批次已导入的记录。

4. 两条帮助命令均无需提供操作参数或测试样本即可查看；打印帮助后以状态码 `0` 退出，不创建或写入档案，不执行来源管理操作。

## 边界与约束

- 范围限于 `smm source` 的 CLI 帮助文案，沿用简体中文用途说明。
- 保留现有命令名、参数名、参数类型、必填要求及操作行为：
  - `validate`、`register` 继续接收位置参数 `manifest` 和必填选项 `--fixture`。
  - `enable`、`disable`、`rollback`、`batches`、`purge-batch` 继续接收位置参数 `source_id`。
  - `purge-batch` 继续额外接收整数位置参数 `batch`。
- 文案不得把停用描述为删除记录，把回退描述为清理批次，或把清理描述为删除来源、删除原始对话文件。
- 本次不改变来源注册、适配器验收、导入、版本回退和批次删除实现。
- 项目资料未列明 CLI 支持的操作系统或部署方式；本次不据此新增或缩减平台承诺。变更仅涉及共用 CLI 帮助内容及既有解析退出路径，没有已知的平台专属行为，无须为本次文案变更新增平台决定。

## 设计决策

在 `smm source --help` 中同时呈现各子命令用途和清理前置条件；在 `purge-batch` 自身帮助中再次说明前置条件、输入含义与查询途径，使从任一入口进入的用户都能理解操作。

验收以实际 CLI 帮助输出为依据，结合参数契约和变更范围核对。由于本次不修改平台相关逻辑，共用内容与解析路径的验证足以支撑本次交付，不要求各操作系统重复完整测试；该验证不代表其他平台已经实际运行通过。

## 验收条件

以下运行验收共用环境：能够运行该版本 SMM CLI 的本机运行环境。须记录实际运行环境并取得通过证据，不以包构建或仅检查文案源码代替。

1. 执行 `smm source --help`，输出包含全部八个现有子命令及其用途，逐项符合“预期行为”中的含义；`disable`、`rollback`、`purge-batch` 各自改变的对象和结果清晰可辨。

2. 同一输出明确表达清理批次前须先停用对应插件来源，以及来源仍启用时拒绝清理。仅写“谨慎操作”或只解释删除含义不算通过。

3. 执行 `smm source purge-batch --help`，输出完整说明两个位置参数、整数批次 ID 的要求、通过 `list` 确认来源 ID、通过 `batches` 获取批次记录 `id` 的途径，以及停用同一来源的命令和清理结果。用户无需查阅源码即可确定应提供的值及前置操作。

4. 在尚无本机档案的状态下，分别执行两条帮助命令：均正常输出帮助、以状态码 `0` 退出，不要求提供 `manifest`、`--fixture`、`source_id` 或 `batch`，不创建档案，也不执行子命令操作。

5. 在已有本机档案的状态下，分别执行两条帮助命令：均正常输出帮助、以状态码 `0` 退出；档案内容、来源启停状态、适配器版本和导入批次记录均保持原状。

6. 核对变更及 CLI 参数定义，确认修改仅涉及帮助文案，现有命令、参数类型、必填要求和操作实现保持不变。若引入共用逻辑之外的平台差异或操作逻辑变更，本规格所述验收依据不再充分，须先调整规格及相应验收覆盖。
