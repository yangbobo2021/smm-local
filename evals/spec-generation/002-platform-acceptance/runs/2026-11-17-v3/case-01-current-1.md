# 规格：Hub 自动归档 VibeInsight 历史与项目关联查询

本规格依据同目录下已确认的 [intent.md](intent.md)。尚需维护者决定的事项在下文标明。

## 预期行为

### 来源连接配置

1. 维护者通过 Hub CLI 提供 VibeInsight 来源连接参数和凭据后，Hub 验证来源可连接且可执行所需只读查询。验证成功后保存配置，供长期运行的 Hub 服务使用。
2. 新配置验证失败时，CLI 返回失败结果，原有效配置及凭据保持可用；首次配置失败时不产生有效来源配置。
3. CLI 配置操作与 Hub 服务使用不同账号或环境时，保存后的连接参数、凭据和 `psql` 配置仍须能被实际服务运行账号使用。若无法满足，配置操作须明确失败，不能报告配置成功。
4. Hub 重启后自动加载已保存配置并继续同步，无需维护者重新输入密码。CLI 输出、日志及对话数据库不包含密码原值。

### 自动同步与恢复

1. 来源配置有效且可访问时，Hub 自动发现并归档 VibeInsight 当前可读取的全部项目历史。
2. 来源出现新会话事件或已有会话追加轮次时，Hub 持续归档新增内容，并保留其来源、项目、原会话和消息位置。
3. 来源后来新增可读项目时，即使该项目的历史早于已有同步进度，Hub 仍须补齐其可读取历史，不能仅同步全局进度之后的数据。
4. 来源连接、读取或归档失败时，已有归档继续支持检索和原文读取。来源恢复后，Hub 自动重试尚未成功归档的数据。
5. Hub 重启后从已提交进度继续，并回查近期事件。重试、回查或重复读取同一来源数据不产生重复归档。
6. 每批归档内容与对应同步进度一同提交；失败批次不能仅推进进度而遗漏归档内容。

### 项目关联与查询范围

1. Hub 维护者统一管理项目关联，可以连接设备项目与 VibeInsight 项目，也可以连接不同设备上的项目。
2. 关联双向生效。查询某项目时，范围包含该项目及其直接关联项目，只扩展一层，不继续沿关联关系递归扩展。
3. 例如 A 关联 B、B 关联 C，而 A 未直接关联 C 时：查询 A 包含 A、B；查询 B 包含 A、B、C；查询 C 包含 B、C。
4. 解除关联后，后续项目查询按剩余关联关系确定范围。解除关联不删除任何已有归档，也不使已取得的原文引用失效。
5. 本机端补传项目归属，CLI/MCP 发起项目查询时携带当前项目身份。同名但身份不同的项目保持可区分，不能仅因名称相同而合并或关联。

### 检索、原文读取与兼容

1. 用户通过现有 CLI/MCP 检索 Hub 已归档的设备对话及 VibeInsight 对话，并读取对应原文。
2. CLI/MCP 检索结果返回来源、项目、原会话和消息位置，使调用方能够精确读取所指向的原文。同名项目、不同来源中的同名会话不得造成读取歧义。
3. 现有旧原文引用继续可用，不因新增来源、项目归属补传或关联变更而指向其他内容。
4. 旧客户端未携带当前项目身份时，继续执行现有全局查询。
5. Hub 不可用时，沿用现有本机全局回退行为。

## 边界与约束

- 首版面向单用户，不引入多用户权限或租户隔离要求。
- 同步范围为来源当前允许读取的全部项目历史；对 VibeInsight 仅执行只读查询。
- 首版处理新增会话事件与追加轮次，不要求发现没有新增事件的历史正文原地改写。
- 来源失败不影响已有归档的可查询性；项目解除关联不删除归档。
- Hub 与本机端继续支持 Windows、Linux、macOS，不得因本次来源接入缩减现有平台范围。
- 保持既有服务运行方式：Windows 使用 LocalService 系统服务，Linux 使用 systemd 用户服务，macOS 使用 launchd 系统服务。
- 来源读取由 Hub 服务调用外部 PostgreSQL 客户端 `psql`。不得假定配置 CLI 与服务具有相同的账号、安装路径、环境变量或可执行搜索路径。
- 密码保存在服务状态目录的专用秘密文件中。实际运行账号须能读取，其他未授权普通账号不能读取。
- 当前仅有 macOS 开发环境信息，尚无 Windows/Linux 本次执行记录；不得据此宣称三平台已验证通过，也不得据此免除兼容要求。
- 回归可使用合成事件，不要求在真实来源服务器创建测试数据。具体验证方法和实施安排写入 plan.md。

## 设计决策

1. **配置与秘密分开保存。** 连接参数保存在 Hub 配置文件，密码保存在服务状态目录的专用秘密文件。配置保存必须适配各平台实际服务账号的读取权限，避免依赖 CLI 操作者的个人环境。
2. **验证成功后替换有效配置。** 新配置验证及可供服务使用的保存条件全部满足后，才替换原有效配置；失败不能留下连接参数与凭据不匹配的有效状态。
3. **归档与进度原子提交。** 同步进度保存在 Hub 数据库，每批归档与进度共同提交，避免重启或失败后跳过未归档数据。近期事件回查配合去重处理重复读取。
4. **关联按身份维护。** 项目身份用于区分项目及计算一层双向关联范围；项目名称仅用于展示，不作为合并依据。原文定位须保留来源身份和原始位置，兼容既有引用。
5. **待维护者决定：**
   - `psql` 可执行文件的指定或发现方式，以及服务环境下不可执行时的具体诊断形式。
   - 自动同步、项目发现、失败重试的周期，以及近期事件回查窗口。
   - 来源连接配置、项目关联管理的具体 CLI 命令形式，以及 CLI/MCP 新增定位字段的名称和兼容表示。

上述待定项不得改变已确认的跨平台支持、服务类型、历史补齐、去重及兼容行为。

## 验收条件

1. 提交有效来源配置后，实际 Hub 服务账号能调用 `psql` 执行所需只读查询；重启 Hub 后无需重新输入密码即可恢复同步。
2. 已有有效配置时提交无效凭据，CLI 明确返回失败，原配置仍能继续同步；首次配置失败不产生有效配置。
3. CLI 与服务账号或环境不同时，配置成功必须对应服务可实际使用的配置；缺少可执行的 `psql` 或必要读取权限时，不得报告成功。
4. 服务账号可读取秘密文件，其他未授权普通账号不可读取；CLI 输出、日志及对话数据库均不含密码原值。
5. 初次同步后，来源可读取的每个项目及其历史会话、轮次均可在 Hub 中检索并读取。
6. 新增会话事件及旧会话追加轮次后，相应新增内容能自动归档并查询。
7. 已有同步进度后新增一个可读项目，其早于该进度的历史仍能完整补齐。
8. 来源失败期间，已有归档仍可检索和读取；来源恢复后，失败期间尚未归档的数据能自动补齐。
9. 批次提交失败或 Hub 中断后，不出现进度已推进而对应内容缺失的状态；重启、重试及近期回查后，同一来源内容只有一份归档。
10. 设备项目与 VibeInsight 项目、不同设备项目之间均可建立关联，且从任一端查询均包含直接关联项目。
11. 对 A—B—C 且无 A—C 关联的关系，查询范围分别为 A/B、A/B/C、B/C，不发生递归扩展。
12. 解除关联后，项目查询不再因已解除的关系包含对方内容；已有归档和此前取得的原文引用仍可读取。
13. 同名但身份不同的项目保持独立；本机端补传项目归属后，携带当前项目身份的 CLI/MCP 查询返回该项目及其一层关联范围内的内容。
14. CLI/MCP 返回的来源、项目、原会话和消息位置足以精确读取对应原文；不同来源或同名项目不会导致引用错指，既有旧引用继续有效。
15. 旧客户端不携带项目身份时保持全局查询；Hub 不可用时保持现有本机全局回退。
16. Windows、Linux、macOS 均保持既有发行支持及服务运行方式，并满足服务读取配置、秘密文件权限、调用 `psql` 和重启续传的要求。缺少平台执行记录时，相应平台验收状态须保持未验证。
