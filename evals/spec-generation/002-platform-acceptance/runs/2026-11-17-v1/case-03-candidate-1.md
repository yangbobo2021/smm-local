# 规格：同分检索结果按数值会话 ID 稳定排序

依据同目录下已确认的 [intent.md](intent.md) 起草。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列，不受输入列表顺序影响。例如，同分结果的会话 ID 为 `10`、`2` 时，输出顺序为 `2`、`10`。
2. 分数不同时，沿用原有排序规则；新增规则仅用于分数相同的结果。
3. CLI、MCP 和 Web 均通过现有共用函数获得上述排序结果，保持一致的排序语义。
4. 结果字段、项目过滤规则及 `limit` 语义保持不变。同分结果跨越截取边界时，入选结果应符合会话 ID 数值升序规则。

## 边界与约束

- Windows、Linux、macOS 均继续受支持，三平台承诺相同的稳定排序语义。
- 本次仅调整三平台共用纯函数的同分排序规则。输入为已解码的 Python 数值分数和整数会话 ID，不新增输入类型或转换规则。
- 纯函数不访问系统、文件、数据库、网络、时间或区域设置，没有平台分支；三平台使用相同受支持的 Python 数值比较语义。
- 不改变运行时范围、依赖、安装或服务，也不改变 CLI、MCP、Web 的调用方式。
- 同分且会话 ID 相同的结果，本次不新增进一步的排序规则，沿用现有行为。
- 空列表、单条结果以及既有 `limit` 边界行为应保持兼容。

## 设计决策

采用分数原排序规则作为首要排序依据，仅在分数相同时使用整数会话 ID 升序作为次要依据。排序规则统一由现有共用纯函数承担。

本次验收可使用 macOS 上的合成输入验证共用逻辑，无须在 Windows、Linux 重复执行相同测试。依据是本次行为完全由无外部依赖、无平台分支的纯函数决定，且三平台采用相同的数值比较语义，三个入口也没有额外排序层。

该覆盖仅证明本次共用排序逻辑符合三平台共同承诺，不代表 Windows、Linux 已实际运行通过，也不覆盖安装、服务或其他平台集成行为；这些行为不在本次变更范围内。若实施引入平台分支、外部依赖或入口独立排序层，须重新确认验收覆盖的充分性。

现有材料足以确定本次排序规则及验收范围，无待确认的环境决定。

## 验收条件

以下条件须在 macOS 对实际共用纯函数取得通过证据：

1. 输入多条同分结果，包含会话 ID `2` 和 `10`，输出按 ID 数值升序排列。
2. 对同一组分数和会话 ID 各不重复的结果改变输入顺序，输出的会话 ID 顺序一致；其中包含多条同分结果。
3. 输入不同分数及多个同分组，分数组之间保持原有排序，每个同分组内部按会话 ID 数值升序排列。
4. 排序不改变结果数量或任何结果字段；项目过滤仍遵循原有规则，其他项目的结果不会因本次排序变化而进入输出。
5. 对同分结果跨越 `limit` 边界的输入，截取结果符合新增排序规则；既有 `limit` 数量及边界语义保持不变。
6. 空列表、单条结果及同分同 ID 的结果保持既有行为。
7. 通过调用关系审阅确认 CLI、MCP、Web 继续使用该共用函数，且未新增额外排序层或平台实现。

上述共用逻辑执行证据与调用关系审阅足以验收本次变更，不要求三平台分别重复完整测试。验收记录须明确实际执行平台为 macOS，不得记为 Windows、Linux 已实测通过。
