# 规格：SMM 同分检索结果按会话 ID 稳定排序

依据：[已确认意图](intent.md)。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列，不受输入列表顺序影响。例如，同分结果的会话 ID 为 `10`、`2` 时，输出顺序为 `2`、`10`。
2. 检索结果分数不同时，保持现有按分数排序的顺序；会话 ID 仅用于同分结果的排序。
3. CLI、MCP 和 Web 均通过现有共用函数获得上述排序结果，调用方式不变。
4. 项目过滤和 limit 的现有语义不变。同分结果跨越 limit 截断边界时，按会话 ID 数值升序确定其先后，再依照现有 limit 语义返回结果。
5. 排序不改变结果字段及其值。

## 边界与约束

- Windows、Linux、macOS 必须具有相同的排序语义。
- 变更限于三平台共用的纯排序函数。输入为已解码的 Python 数值分数和整数会话 ID，输出为排序后的列表。
- 沿用受支持 Python 运行时的数值比较语义，不新增分数转换、字符串比较或平台专属规则。
- 空列表和单条结果保持原有行为；分数及会话 ID 均相同的条目不新增排序规则。
- 不改变运行时支持范围、依赖、安装方式或服务，也不引入对系统、文件、数据库、网络、时间或区域设置的访问。

## 设计决策

- 在共用纯函数中将会话 ID 数值升序作为同分时的次级排序规则，使所有入口和平台共享同一行为，避免入口之间产生排序差异。
- 三平台一致性依据共用实现、无平台分支及相同的 Python 数值比较语义建立。当前仅具备 macOS 上使用合成输入验证的条件，不将其表述为 Windows 或 Linux 的执行记录。
- 待维护者决定：验收是否要求补充 Windows、Linux 的实际执行记录；该决定不影响三平台必须满足相同排序语义的要求。

## 验收条件

1. 对包含多个同分结果的输入，输出会话 ID 按数值升序排列；包含 `2` 和 `10` 时，`2` 位于 `10` 之前。
2. 将同一组具有不同会话 ID 的同分结果打乱输入顺序，输出的会话 ID 顺序始终一致。
3. 对包含不同分数及同分组的输入，不同分数之间的顺序与现有行为一致，每个同分组内部按会话 ID 数值升序排列。
4. 同分组跨越 limit 截断边界时，返回的条目符合上述排序；返回数量及其他 limit 行为与现有语义一致。
5. 项目过滤后的结果范围与现有行为一致，排序不引入被过滤的结果。
6. 排序前后，每条结果的字段及字段值一致；空列表和单条结果的行为保持不变。
7. CLI、MCP 和 Web 继续使用共用函数，获得一致的同分排序规则。
8. 三平台适用同一排序规则。验收材料明确区分共用实现提供的一致性依据与实际执行记录，不声称已在未执行的平台完成验证。
