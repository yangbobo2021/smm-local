# 规格：同分检索结果按数值会话 ID 稳定排序

本规格依据同目录下已确认的 [intent.md](intent.md) 及项目现有承诺起草。

## 预期行为

1. 检索结果分数相同时，按数值会话 ID 升序排列，不受输入列表顺序影响。例如，同分会话 ID 为 `10`、`2` 时，输出顺序为 `2`、`10`。
2. 检索结果分数不同时，保持原有按分数排序的规则，仅在同分组内使用会话 ID 决定顺序。
3. CLI、MCP 和 Web 沿用共用排序函数，获得一致的同分排序语义。
4. 结果字段、项目过滤和 limit 语义保持不变。同分排序影响 limit 边界处的结果选择时，应按会话 ID 升序确定入选结果。

## 边界与约束

- 现有客户端继续支持 Windows、Linux、macOS，三平台均承诺相同的稳定排序语义。
- 本次范围限于三平台共用的纯函数。其输入为已解码的 Python 数值分数和整数会话 ID，输出为排序后的列表。
- 会话 ID 按整数数值比较，不按字符串字典序比较。
- “同分”依据现有受支持的 Python 数值比较语义判断，不引入近似相等、精度截断或分数转换。
- 不新增输入类型支持或异常输入处理规则。分数和会话 ID 均相同的记录不新增排序承诺，保持现有行为。
- 不改变运行时支持范围、依赖、安装、服务或各入口的调用方式。

## 设计决策

在共用纯函数中增加同分时的会话 ID 升序规则，保留原有分数排序优先级。CLI、MCP 和 Web 不增加独立排序逻辑，避免入口之间产生差异。

本次排序只依赖三平台一致的 Python 数值比较语义，不访问系统、文件、数据库、网络、时间或区域设置，也没有平台分支。因此，macOS 上对共用纯函数的合成输入验证足以支撑本次排序变更，无须要求 Windows、Linux 重复实际运行相同测试。

该充分性仅适用于上述纯函数及现有调用关系保持成立的范围。若实施引入平台依赖、额外排序层或运行方式变化，须重新确认设计及必要验收覆盖。

## 验收条件

1. 对同分且会话 ID 不同的合成结果，输出 ID 按数值升序排列；至少包含 `2`、`10`，确认未采用字符串排序。
2. 对同一组结果采用不同输入排列，输出的同分会话 ID 顺序一致。
3. 对包含多个分数组的结果，各分数组之间保持原有排序规则，每个同分组内部按会话 ID 升序排列。
4. 排序前后，各结果的字段和值保持一致；项目过滤仍排除不符合条件的结果。
5. limit 的数量及边界语义保持不变；当截断位置落在同分组内时，入选结果符合会话 ID 升序规则。空结果及结果数量不足 limit 时，保持原有行为。
6. 确认 CLI、MCP 和 Web 继续调用同一纯函数，且未新增入口或平台专属排序层。
7. 上述行为须取得 macOS 上共用纯函数的实际验证通过证据，并确认其仍满足无外部环境依赖、无平台分支及三平台比较语义一致的前提。此覆盖足以验收本次改动，但不得表述为 Windows、Linux 已实际运行通过。
