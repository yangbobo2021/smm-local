# 规格：Hub 自动同步 VibeInsight 历史与项目关联检索

以同目录下已确认的 [intent.md](intent.md) 为依据。文中标明的待确认事项需由维护者在实施前决定。

## 预期行为

### 来源连接与凭据配置

- 维护者通过 Hub CLI 提供 VibeInsight 来源连接参数和密码。CLI 验证连接及只读查询能力，验证成功后保存为有效配置。
- 新配置验证失败时，CLI 返回可识别的失败原因，不覆盖原有效配置及凭据。
- 连接参数保存在 Hub 配置文件，密码保存在 Hub 服务状态目录的专用秘密文件。长期运行的 Hub 服务能够读取并使用该配置，即使配置 CLI 与服务使用不同账号或环境。
- Hub 重启后自动使用已保存的有效配置继续同步，无需重新输入密码。
- CLI 输出、日志及对话数据库不包含密码原值。

### 自动同步与恢复

- 配置生效后，Hub 自动发现并归档 VibeInsight 当前可读取的全部项目历史。
- 持续同步期间，Hub 自动归档新增会话以及旧会话追加的轮次。
- 来源后来新增可读项目时，Hub 补齐该项目全部可读历史，包括早于已有同步进度的历史。
- 同步批次的归档数据与进度一同提交。Hub 重启后从已提交的位置继续，并回查近期事件；重复读取不产生重复归档。
- 来源连接、查询或读取失败时，已有归档继续可检索、可读取。来源恢复后，Hub 自动重试尚未成功归档的数据，不因失败跳过历史。

### 项目身份与关联

- 本机端补传会话的项目归属；CLI/MCP 发起项目查询时携带当前项目身份。
- 同名项目保持可区分，不因名称相同而合并。
- Hub 维护者统一管理项目关联，可关联设备项目与 VibeInsight 项目，也可关联不同设备的项目。
- 项目关联双向生效。查询某项目时，范围包含该项目及与其直接关联的项目，只扩展一层。
- 若 A 关联 B、B 关联 C，而 A 未直接关联 C，则从 A 发起的项目查询不因上述关系包含 C。
- 解除关联后，后续项目查询不再通过该关系扩展范围；已归档数据不被删除，已有原文引用仍可使用。

### CLI/MCP 检索与原文读取

- 用户通过现有 CLI/MCP 检索 Hub 已归档的设备对话与 VibeInsight 对话，并读取对应原文。
- 检索结果和原文读取响应提供来源、项目、原会话及消息位置，足以区分同名项目、不同来源的会话，并精确定位原文。
- 现有原文引用在引入来源身份和项目身份后仍可解析、读取。
- 支持项目查询的新客户端按当前项目及一层关联范围查询；旧客户端的全局查询保持兼容。
- Hub 不可用时，CLI/MCP 沿用现有本机全局回退行为。

## 边界与约束

- 首版仅支持单用户，不引入多用户权限管理。
- 来源仅执行只读查询，不修改 VibeInsight 数据。
- 同步覆盖新增会话事件及追加轮次；没有新增事件的历史正文原地改写不在本次发现范围内。
- 项目关联只影响查询范围，不删除归档，也不使旧原文引用失效。
- 保持 Hub 与本机端对 Windows、Linux、macOS 的支持，不缩减部署平台范围。
- 保持既有服务运行方式：
  - Windows：以 LocalService 运行的系统服务。
  - Linux：systemd 用户服务。
  - macOS：launchd 系统服务。
- Hub 服务调用外部 PostgreSQL 客户端 `psql`。配置验证与服务运行必须考虑可执行文件路径、账号和环境差异，不能仅以配置 CLI 所在环境中可执行为准。
- 专用秘密文件须允许 Hub 运行账号读取，同时阻止其他未授权普通账号读取；该要求适用于全部支持平台。

## 设计决策

- 采用外部 `psql` 执行来源只读查询。其定位与执行必须适用于既有服务环境。
- 连接参数与密码分开保存，以满足服务重启续用、跨账号读取及秘密隔离要求。新配置验证成功后才替换有效配置，失败时保留原有效状态。
- 同步进度保存在 Hub 数据库，批次归档与进度使用同一提交边界，避免进度已推进但对应数据未归档。
- 采用稳定身份区分来源、项目、会话和消息位置，不能仅依赖项目名称；兼容既有原文引用。
- 查询关联范围以请求中的当前项目为起点，取直接关联项目，不递归扩展。

实施前需维护者确认：

- Hub CLI 中来源配置、验证及项目关联管理的具体命令和参数。
- `psql` 路径的配置或发现规则，以及如何确认既有服务账号能够执行它并读取秘密文件。
- 来源发现、增量同步和失败重试的周期，以及近期事件回查窗口。所选规则必须满足新增可读项目历史补齐及失败数据重试要求。
- CLI/MCP 中来源、项目、原会话和消息位置的具体字段及兼容格式。

## 验收条件

1. 有效来源配置通过 Hub CLI 验证并保存后，既有 Hub 服务能够使用该配置进行只读同步；CLI 与服务账号或环境不同时仍成立。
2. 无效新配置返回明确失败结果，原有效连接和凭据仍可用于同步。
3. Hub 重启后无需重新输入密码即可继续同步。
4. 在 Windows、Linux、macOS 上，既有服务类型保持不变；服务能够执行 `psql`、读取专用秘密文件，其他未授权普通账号不能读取密码原值。
5. CLI 输出、日志及对话数据库中均不出现密码原值。
6. 首次同步后，来源当前全部可读项目的历史均已归档，可经现有 CLI/MCP 检索和读取。
7. 来源出现新增会话或旧会话追加轮次后，对应内容自动进入归档，原会话身份及消息位置保持正确。
8. 新增可读项目包含早于当前同步进度的历史时，该历史仍被完整补齐。
9. 同步中断或 Hub 重启后，已提交归档保留，未提交数据能够重试；归档与进度不出现一方提交而另一方未提交的状态。
10. 近期事件回查、重启续传及失败重试重复读取同一数据时，不产生重复归档。
11. 来源不可用期间，已有归档仍可检索和读取；来源恢复后，未成功归档的数据能够自动补齐。
12. 本机端补传的项目归属可用于查询；同名设备项目及 VibeInsight 项目能够独立识别。
13. 设备项目与 VibeInsight 项目、不同设备项目之间均可建立双向关联；从任一端查询均包含直接关联项目。
14. 对 A—B—C 关联链，从 A 查询不包含仅通过 B 间接关联的 C；从 B 查询包含其直接关联的 A 和 C。
15. 解除关联后，新查询范围随之收窄，既有归档不被删除，旧原文引用仍可读取。
16. CLI/MCP 返回的来源、项目、原会话及消息位置能够精确读取对应原文；不同来源或同名项目之间不会误定位。
17. 旧客户端全局查询继续可用；Hub 不可用时，现有本机全局回退行为保持可用。

当前仅有 macOS 开发与验证环境的信息，Windows/Linux 尚无本次执行记录，不能据此认定跨平台验收通过。具体实现位置、实施顺序和验证方法写入 plan.md；回归可使用合成事件，无需在真实来源服务器造数。
