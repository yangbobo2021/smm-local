# 规格：Hub 重启后自动恢复同步

依据：[已确认意图](./intent.md)。

## 预期行为

1. 已配置数据来源且完成后台运行配置后，机器重启应自动启动 Hub，并继续同步这些来源，无需用户打开交互式终端、手动执行命令或重新输入凭据。
2. 自动恢复同步应保留并使用已有归档和同步进度，避免重启导致归档丢失、进度重置或已导入数据重复导入。
3. 来源不可达时，Hub 应保留已有归档及进度，已有归档仍可检索；同时报告该来源的同步失败，使用户能够识别受影响的来源和失败原因。
4. 来源恢复可达后，Hub 应自动重试并继续同步，无需用户重新配置来源或凭据，且不得重复导入已归档的数据。

## 边界与约束

- Python 3.11+ 是已知运行要求，不能据此推断支持的操作系统、系统服务类型或部署方式。README 示例路径和当前 macOS 开发电脑也不构成支持范围承诺。
- 本次操作系统支持范围尚待维护者确认；不得默认仅支持 macOS，也不得自行承诺新增 Windows 或 Linux 支持。该决定影响后台启动、凭据保存与读取、文件访问以及实际验收所需环境，是交付前置决定。
- 服务类型、部署账号及是否要求在无人登录状态下运行尚待确认。应明确“随系统启动”的运行条件，不能用用户登录后启动替代未经确认的系统启动要求。
- 已有归档、来源配置和进度必须可由选定的后台运行账号访问并持续保存。更换运行账号或运行方式不得隐式创建空数据目录，造成原归档或进度不可见。
- 原前台命令通过环境变量获取凭据的方式应保持兼容。新增持久化机制不得要求用户每次重启后重新提供凭据。
- 来源不可达不应删除归档、清空进度或使已有归档失去检索能力。资料未明确检索组件及其运行方式；保证检索可用所需的组件和启动安排须在实施前确认。
- 本规格仅规定来源不可达后的恢复行为；凭据失效或被撤销时的更新流程尚无已确认要求，不承诺无需有效凭据即可继续同步。

## 设计决策

以下决定需要维护者在实施前确认：

| 待确认事项 | 决定及其影响 |
| --- | --- |
| 支持的操作系统与部署方式 | 明确本次交付覆盖哪些实际环境，以及各环境采用的后台运行机制；不能由当前开发环境代替决定。 |
| 服务账号与启动条件 | 明确账号身份、登录依赖及生命周期，保证机器重启后能够按约定自动运行。 |
| 凭据持久化方案 | 明确存储位置、访问权限、初次配置及已有环境变量凭据的接入方式；所选机制必须能由服务账号在约定启动状态下读取，不能默认交互式终端环境或已解锁的用户会话可用。凭据不得出现在失败报告中。 |
| 数据位置与访问方式 | 明确来源配置、归档和进度的持久化位置及服务账号权限，确保前台与后台使用既有数据，并处理同步中断时的进度一致性。 |
| 检索运行方式 | 明确来源离线或同步失败时，由哪些组件提供归档检索，以及它们所需的启动和文件访问条件。 |
| 失败报告与重试策略 | 明确用户从何处查看来源、失败原因及恢复状态，以及自动重试的触发方式和时间界限，使失败与恢复均可独立验收。 |

后台运行涉及启动环境、账号权限、凭据可用性和进程生命周期变化，因此原前台命令在交互式终端运行成功，不能证明本次承诺成立。上述决定确认后，应补入本规格对应的运行条件和验收范围。

## 验收条件

1. **支持范围已确定**：维护者已确认操作系统、后台运行方式、服务账号和启动条件，并补齐上述影响实施与验收的决定。未完成这些确认，不得判定本次交付通过。
2. **实际重启后自动恢复**：在每个确认支持的操作系统及后台部署方式中，以约定的实际服务账号完成机器重启验证。Hub 在约定登录状态下自动启动，读取已配置来源和持久化凭据并继续同步，全程无需打开终端、手动启动或重新输入凭据。
3. **已有数据与进度保留**：在上述实际环境中，重启前已有的归档在重启后仍可检索；同步沿用原进度，已导入数据不重复导入，新增数据正常归档。
4. **中断后保持一致**：在同步尚未完成时发生重启，恢复后既不遗漏尚未完成导入的数据，也不重复导入已完成的数据。该一致性逻辑可用共用测试覆盖，但仍须在每种确认部署环境中验证后台服务实际读取和更新同一份持久化数据。
5. **来源不可达时可用且可诊断**：在每种确认部署环境中，使来源不可达后，原归档仍能通过约定检索入口查询，进度保留；约定报告入口显示受影响来源及失败原因，且不泄露凭据。
6. **恢复后自动重试**：来源恢复后，Hub 在确认的重试时间界限内自动继续同步，无需重新配置或提供凭据；新增数据成功导入，原数据无重复，报告状态反映恢复结果。
7. **原入口兼容**：原前台同步命令仍能通过环境变量取得凭据并执行同步。共用逻辑测试可证明凭据解析和导入规则，但不能替代后台账号、启动状态及持久化访问的实际验证。
8. **证据覆盖充分**：实际平台证据必须覆盖系统启动、服务账号读取凭据、访问既有数据、离线检索及自动恢复。与平台无关的去重、进度和报告内容逻辑可共用验证，无需各平台重复全部逻辑测试；包构建成功或当前 macOS 交互式终端验证不能替代上述运行证据。缺少任一确认支持环境的必要证据，交付仍未完成。

具体机器、实施位置、测试步骤、命令及 CI 配置写入 `plan.md`。
