# 规格：SMM 同分检索结果按会话 ID 稳定排序

依据：[已确认意图](intent.md)。

## 预期行为

1. 检索结果分数相同时，按数值会话 ID 升序排列。较小的整数 ID 排在较大的整数 ID 前面，不按字符串字典序比较。
2. 对同一组分数及会话 ID，改变输入列表顺序，不改变同分且会话 ID 不同的结果之间的排序。
3. 分数不同时，保持现有排序规则。
4. CLI、MCP 和 Web 均通过现有共用函数获得上述排序行为。
5. 项目过滤及 limit 的现有语义保持不变。同分排序影响 limit 边界处的入选结果时，按会话 ID 升序确定先后，不改变 limit 对结果数量的约束。

## 边界与约束

- 变更限于三平台共用的纯排序函数，输入为已解码的 Python 数值分数和整数会话 ID，输出为排序后的列表。
- Windows、Linux、macOS 必须具有相同的排序语义，不引入平台分支或额外排序层。
- 沿用受支持的 Python 数值比较语义，不新增分数或会话 ID 的类型转换、校验规则。
- 结果字段及其值保持不变；除现有过滤和 limit 行为外，不新增、删除或合并结果。
- 空列表、单条结果，以及分数和会话 ID 均相同的结果，保持现有处理行为；不新增第三排序键。
- 不改变运行时范围、依赖、安装方式或服务，不引入系统、文件、数据库、网络、时间或区域设置访问。
- 当前仅有 macOS 可执行验证的条件，没有 Windows、Linux 的本次执行记录。维护者仍需决定是否要求额外的平台执行记录作为交付门槛；这不改变三平台一致的行为要求。

## 验收条件

1. 对分数相同、会话 ID 分别为 `10`、`2`、`1` 的结果，输出 ID 顺序为 `1`、`2`、`10`。
2. 对同分且会话 ID 不同的同一组结果，任意打乱输入后，输出 ID 顺序一致。
3. 对分数不同的结果，即使会话 ID 大小顺序与现有分数排序相反，仍保持原有的分数排序。
4. 对包含多个分数组的结果，各分数组之间保持现有排序，每个同分组内部按会话 ID 升序排列。
5. limit 截断发生在同分组内部时，优先保留会话 ID 较小的结果；返回数量及其他 limit 边界行为与现有语义一致。
6. 项目过滤的匹配规则保持不变；过滤后返回的结果满足上述排序规则。
7. 排序前后，各结果的字段及其值一致，未新增去重或结果合并行为。
8. 空列表、单条结果及分数和会话 ID 均相同的结果，处理行为与变更前一致。
9. CLI、MCP 和 Web 沿用共用函数，均获得相同的同分排序规则。
10. 三平台对相同有效输入具有相同的预期输出；缺少其他平台的执行记录不得表述为已在这些平台验证通过。
