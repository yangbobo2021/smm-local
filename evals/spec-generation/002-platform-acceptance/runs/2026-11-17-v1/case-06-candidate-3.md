# 规格：明确来源管理命令帮助

本规格依据同目录下已确认的 [intent.md](intent.md) 和提供的项目资料。无待维护者确认事项。

## 预期行为

1. 用户执行 `smm source --help` 时，帮助以简体中文列出全部现有子命令及用途，使用户能够区分以下操作：

   | 子命令 | 帮助须表达的用途 |
   |---|---|
   | `list` | 查看以来源 ID 为键的本机来源状态。 |
   | `validate` | 使用来源清单和测试样本验收候选适配器。 |
   | `register` | 使用来源清单和测试样本验收候选适配器，通过后注册来源。 |
   | `enable` | 启用指定来源的导入。 |
   | `disable` | 停用指定来源的导入，保留已导入记录。 |
   | `rollback` | 将指定插件来源的适配器切回上一版。 |
   | `batches` | 查看指定插件来源的导入批次；批次记录的 `id` 是批次 ID。 |
   | `purge-batch` | 从 SMM 本机档案删除指定来源、指定批次已导入的记录；清理前须先停用对应插件来源。 |

2. 用户执行 `smm source purge-batch --help` 时，帮助明确说明：
   - `source_id` 是来源 ID。
   - `batch` 是整数批次 ID，可从 `smm source batches` 返回的批次记录 `id` 获取。
   - 清理会从 SMM 本机档案删除该批次已导入的记录。
   - 清理前须先停用对应插件来源；来源仍启用时拒绝清理。

3. 两条帮助命令均打印帮助并以状态码 `0` 退出，不创建档案对象，不执行来源操作，不写入档案。

## 边界与约束

- 本次仅修改 `smm source` 的 CLI 帮助文案，沿用简体中文用途说明。
- 保留全部现有命令名、参数名、参数类型、必填性和操作行为：
  - `validate`、`register` 保留位置参数 `manifest` 和必填选项 `--fixture`。
  - `enable`、`disable`、`rollback`、`batches`、`purge-batch` 保留位置参数 `source_id`。
  - `purge-batch` 保留整数位置参数 `batch`。
- 不将停用描述为删除记录，不将回退描述为清理批次，不将清理批次描述为删除来源或原始对话文件。
- 不新增清理前置条件；帮助须准确披露现有“对应插件来源仍启用时拒绝清理”的行为。
- 提供的资料未列明 CLI 支持的操作系统和部署方式。本次不新增、缩减或推断环境支持承诺；交付范围仅为既有 CLI 的帮助内容及其退出行为。

## 设计决策

- 在顶层帮助中为每个子命令提供可直接辨认用途的简体中文说明，并在 `purge-batch` 的说明中直接呈现先停用的要求，避免用户必须进入子命令帮助才能发现此前置条件。
- 在批次清理帮助中解释位置参数及批次 ID 的来源，使用户能够从查看批次衔接到清理操作。
- 本次内容与共用命令行解析路径有关，未涉及操作系统接口、外部依赖、服务账号、文件访问实现或进程生命周期变更。因此，共用帮助内容检查与实际 CLI 调用足以覆盖本次改动，无须机械地在所有平台重复完整测试。该验证不代表其他平台已实际运行通过。

## 验收条件

1. 实际执行 `smm source --help`，全部八个现有子命令均有简体中文用途说明，逐项符合“预期行为”中的含义。
2. 仅阅读顶层帮助即可明确区分：
   - `disable` 停止后续导入且保留已导入记录；
   - `rollback` 将插件来源适配器切回上一版；
   - `purge-batch` 删除指定批次已导入的本机档案记录。
3. 顶层帮助和 `purge-batch` 帮助均明确提示：清理批次前须先停用对应插件来源；批次清理帮助同时说明来源仍启用时拒绝清理。
4. 实际执行 `smm source purge-batch --help`，可明确识别 `source_id`、整数批次 ID `batch`，以及通过 `smm source batches` 输出中批次记录的 `id` 获取批次 ID 的方式。
5. 两条帮助命令实际调用均以状态码 `0` 退出；验证其执行路径未创建档案对象、未执行来源操作、未写入档案。
6. 命令接口与既有定义一致：全部命令名、上述位置参数、`--fixture` 的必填性和 `batch` 的整数类型保持不变，帮助文案未承诺新的操作行为。
7. 本次必须具备一个可运行现有 SMM CLI 的环境中的两条帮助命令通过证据，并结合共用定义或解析路径检查确认上述内容及兼容性。仅有文案审阅或包构建不足以判定通过；不要求据此推断其他平台实际运行结果。
