# 规格：Hub 自动归档 VibeInsight 历史与项目关联检索

以同目录 [intent.md](intent.md) 中已确认的意图及现有平台、服务运行承诺为依据。尚缺的来源兼容范围、服务依赖配置及权限决定见下文，须由维护者确认。

## 预期行为

### 来源连接与凭据

- 维护者通过 Hub CLI 配置 VibeInsight 来源连接和凭据。CLI 验证来源可读后才保存并启用新配置；验证失败时保留原有效配置及凭据，既有同步继续使用原配置。
- 已保存的连接和凭据可供 Hub 长期运行服务使用。服务重启后自动恢复同步，无需再次输入密码，不依赖配置 CLI 的交互会话仍然存在。
- CLI 输出、日志及对话数据库不包含密码原值。

### 自动同步与恢复

- Hub 自动发现并归档来源当前可读取的全部项目历史，持续同步新增会话事件和已有会话追加的轮次。
- 来源后来新增可读项目时，即使该项目历史早于其他项目已有同步进度，也须完整补齐，不能被已有进度跳过。
- 来源连接、查询或读取失败时，已经提交的归档仍可检索和读取。来源恢复后，Hub 自动重试尚未成功归档的数据。
- 批次归档与同步进度一同提交。重启后从已提交位置继续；重复读取及近期事件回查不会产生重复归档。
- 首版不发现没有新增事件的历史正文原地改写。

### 项目身份与关联

- 本机端上传会话时补传项目归属；CLI/MCP 发起项目查询时携带当前项目身份。同名项目保持可区分。
- Hub 维护者统一管理项目关联，可关联设备项目与 VibeInsight 项目，也可关联不同设备项目。
- 关联双向生效，只扩展一层。例如 A 与 B 关联、B 与 C 关联时，查询 A 包含 A 和 B，不因该链条包含 C。
- 解除关联后，后续查询不再通过该关系扩展，但不删除任何已归档数据，已有原文引用仍可使用。

### 检索、原文与回退

- 用户通过现有 CLI/MCP 检索已归档的设备对话和 VibeInsight 对话，并读取对应原文。
- CLI/MCP 返回可区分的来源、项目、原会话和消息位置，足以精确定位对应原文；不同来源或同名项目之间不能串读。
- Hub 不可用时，沿用本机全局回退。
- 旧客户端未携带当前项目身份时，继续使用既有全局查询行为。

## 边界与约束

- 首版为单用户功能，不引入多用户授权或隔离承诺。
- Hub 和本机端继续支持 Windows、Linux、macOS，不缩减既有发行范围。
- Hub 保持现有服务方式：Windows 为 LocalService 系统服务，Linux 为 systemd 用户服务，macOS 为 launchd 系统服务。
- Hub 服务通过外部 PostgreSQL 客户端 `psql` 读取来源，对 VibeInsight 仅执行只读查询。服务必须能在自身账号及执行环境下找到并运行该客户端，不能以配置 CLI 能执行为依据认定服务可执行。
- 连接参数保存在 Hub 配置文件，密码保存在服务状态目录的专用秘密文件。运行账号须可读取密码，其他未授权普通账号不可读取。
- 自动同步范围为来源可读取的项目历史，不承诺获取来源权限之外的数据。
- 来源删除、权限撤销及历史正文原地改写的镜像处理不在本次已确认范围内；解除关联不触发归档删除。
- 默认回归可使用合成来源事件，无需在真实业务服务器造数。合成事件不能替代实际服务账号、文件权限及外部进程调用验证。

## 设计决策

### 服务可用的配置与秘密存储

配置成功须同时满足来源可读、配置可持久保存，以及既有服务运行账号可使用保存后的连接和秘密。CLI 与服务可能属于不同账号，不能把密码只保存在 CLI 用户环境中。

更换连接配置时，连接参数与密码应作为同一有效配置切换。验证或保存失败不得留下新旧参数、密码混用的状态，也不得损坏原有效配置。

以下事项待维护者确认：

- 各平台的服务状态目录、秘密文件归属与访问权限，以及 CLI 跨账号写入所需的操作权限。该决定影响凭据保存、服务重启恢复和未授权读取验收。
- `psql` 的安装责任、支持版本及服务定位可执行文件的配置方式。该决定影响部署前提和三平台服务验收；不能默认开发电脑的安装和 PATH 足够。
- VibeInsight 支持的数据库结构或版本范围，以及只读账号所需权限。该决定影响“全部可读历史”的判定和来源兼容验收。

### 归档进度与来源定位

归档数据与进度在同一数据库事务中提交，避免已推进进度却缺少归档。进度设计须支持独立发现新增可读项目并回补早期历史，不能仅依赖一个全局时间水位。

归档须保留稳定的来源、项目、会话和消息定位信息。项目关联只影响查询范围，不改变归档身份或旧引用含义。近期回查及重试使用稳定身份去重。

### 验收覆盖的充分性

同步、去重、一层关联及查询范围等共用逻辑，可通过合成事件和独立 Hub 验证；其依据是这些判定不依赖操作系统服务机制。

外部 `psql` 调用、跨账号配置、秘密文件权限及重启生命周期具有平台差异，必须在三种实际服务环境分别取得通过证据。包构建、wheel 安装或 macOS 共用逻辑测试不能替代 Windows/Linux 服务证据。

## 验收条件

1. **配置验证与替换**
   - 有效来源配置保存后，Hub 服务能使用该配置读取来源。
   - 提交错误密码、不可读来源或保存失败时，原有效配置仍可用，未出现参数与密码混用。
   - CLI 输出、相关日志及对话数据库中均无密码原值。

2. **历史与增量同步**
   - 合成来源包含多个项目、多个会话和多轮消息时，全部可读历史均被归档，可通过 CLI/MCP 检索并精确读取。
   - 新增会话及旧会话追加轮次后，相应内容自动进入归档。
   - 新增一个历史时间早于现有进度的可读项目后，其早期历史仍完整归档。
   - 不以无新增事件的原地正文改写被发现作为通过要求。

3. **失败、事务与恢复**
   - 来源失败期间，已提交归档仍可检索和读取；恢复后未成功数据自动补齐。
   - 在批次提交前后中断并重启，归档与进度保持一致，无跳过数据。
   - 重复读取、失败重试和近期回查均不产生重复归档。

4. **项目与关联**
   - 分别验证设备项目与来源项目、不同设备项目的关联，两个方向的查询均包含直接关联项目。
   - 对 A—B—C 关联链，查询 A 不因链式关系返回 C；无关项目不进入项目查询结果。
   - 同名项目可独立查询，结果身份和原文不混淆。
   - 解除关联后查询范围收回，归档仍存在，旧原文引用仍精确可读。

5. **CLI/MCP 兼容**
   - 两个入口均验证项目身份传递、关联范围查询、来源定位信息及原文读取。
   - 旧客户端全局查询保持可用。
   - Hub 不可用时，本机全局回退行为保持可用。
   - Windows、Linux、macOS 本机端分别取得项目归属上传、项目查询、旧引用读取及本机回退的实际运行证据；共用查询规则无需在各平台重复全部组合。

6. **三平台 Hub 服务**
   - Windows LocalService 系统服务、Linux systemd 用户服务、macOS launchd 系统服务分别验证：服务环境调用 `psql`、读取持久配置和秘密、完成归档，以及重启后无需输入密码继续同步。
   - 各平台分别证明运行账号可读取秘密，未授权普通账号无法读取；配置 CLI 会话退出后不影响服务使用。
   - 各平台验证无效配置提交不会破坏原有效配置。来源查询使用只读权限完成，未执行来源写入。
   - 平台服务验证可使用隔离的 PostgreSQL 测试来源，不要求修改真实业务数据。

7. **完成判定**
   - 当前 macOS 开发环境可提供共用逻辑及本平台验证，但不能据此判定其他平台通过。
   - Windows/Linux 本次执行记录尚不存在，对应必要证据属于未完成项。
   - 上述待确认决定须在实施前落实；全部必要验收证据齐备后，方可判定交付通过。具体机器、步骤、命令及 CI 配置写入 plan.md。
