# 规格：明确来源管理命令帮助

依据同目录下已确认的 [intent.md](intent.md) 和给定项目资料制定。本次无待维护者确认的事项。

## 预期行为

1. 用户执行 `smm source --help` 时，帮助以简体中文为全部现有子命令提供用途说明，用户无需进入各子命令帮助即可理解：
   
   | 子命令 | 帮助必须表达的含义 |
   |---|---|
   | `list` | 查看以来源 ID 为键的本机来源状态。 |
   | `validate` | 使用来源清单和测试样本验收候选适配器。 |
   | `register` | 使用来源清单和测试样本验收候选适配器，验收通过后注册来源。 |
   | `enable` | 启用指定来源的导入。 |
   | `disable` | 停用指定来源的导入，保留已导入记录。 |
   | `rollback` | 将指定插件来源的适配器切回上一版。 |
   | `batches` | 查看指定插件来源的导入批次；每条批次记录的 `id` 是批次 ID。 |
   | `purge-batch` | 按来源 ID 和整数批次 ID，从 SMM 本机档案删除该批次已导入的记录。 |

2. `smm source --help` 明确提示：清理批次前须先停用对应的插件来源；来源仍启用时，清理会被拒绝。

3. 用户执行 `smm source purge-batch --help` 时，帮助以简体中文说明删除范围及上述停用前提，并明确两个位置参数的含义：`source_id` 是来源 ID，`batch` 是整数批次 ID，可从 `batches` 返回记录的 `id` 获取。

4. 两条帮助命令均打印帮助，以状态码 `0` 退出，不创建档案对象、不执行子命令操作、不写入档案。

## 边界与约束

- 本次仅修改 `smm source` 的 CLI 帮助文案，沿用全部现有命令名、参数、参数类型、必填要求和操作行为。
- `validate`、`register` 继续接收位置参数 `manifest` 和必填选项 `--fixture`；`enable`、`disable`、`rollback`、`batches`、`purge-batch` 继续接收位置参数 `source_id`；`purge-batch` 继续额外接收整数位置参数 `batch`。
- 文案必须区分停用导入、切回适配器上一版和删除批次记录，不得暗示 `disable` 会删除记录、`rollback` 会清理批次，或 `purge-batch` 会删除整个来源。
- 停用前提的提示不增加自动停用行为，也不改变来源仍启用时拒绝清理的现有行为。
- 给定资料未列明 CLI 的操作系统支持清单。本次不新增、缩减或推断平台及部署支持承诺；交付范围为现有 CLI 的共用帮助内容和帮助解析行为，不涉及其他组件。

## 设计决策

沿用现有 CLI 帮助机制，以共用静态文案表达用途、参数含义及清理前提，不引入平台分支、外部服务或档案访问。具体措辞可调整，但必须完整保留上述含义。

本次改动的风险集中于文案缺失、语义混淆、参数兼容性及帮助路径意外执行操作。共用内容和解析路径的验证足以覆盖该范围，无需为文案改动要求所有操作系统重复完整测试；该验证不代表其他平台已经实际运行通过。若实施引入平台相关逻辑或改变运行依赖，须先修订本规格的范围与验收覆盖。

## 验收条件

1. 实际执行 `smm source --help`，输出包含全部八个现有子命令，且每项用途说明均满足“预期行为”表中的含义，使用简体中文。
2. 仅阅读父命令帮助，即可明确判断：
   - `disable` 停用后保留已导入记录；
   - `rollback` 切回插件适配器上一版；
   - `purge-batch` 删除指定批次已导入的记录。
3. 两条帮助输出均明确提示先停用对应插件来源，并说明来源仍启用时拒绝清理。
4. 实际执行 `smm source purge-batch --help`，输出保留位置参数 `source_id` 和 `batch`，准确说明其含义、`batch` 的整数类型，以及批次 ID 来自 `batches` 结果的 `id`。
5. 两条帮助命令均以状态码 `0` 退出；验证证据确认帮助解析在创建档案对象及执行操作前结束，且没有档案写入。
6. 对照现有 CLI 定义，全部命令名、参数、类型和必填要求保持一致；变更未修改来源注册、启停、回退、批次查询或清理逻辑。
7. 在一个能够运行现有 CLI 的实际环境中取得上述帮助输出、退出状态和无副作用的通过证据，并记录实际平台及运行方式。结合共用帮助定义及解析路径的审阅，该证据足以验收本次文案改动；仅有包构建成功或静态文案检查不能替代实际帮助调用证据。
