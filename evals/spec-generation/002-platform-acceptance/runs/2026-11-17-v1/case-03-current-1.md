# 规格：同分检索结果按会话 ID 稳定排序

依据：[已确认意图](intent.md)。

## 预期行为

1. 检索结果分数相同时，按数值会话 ID 升序排列；输入列表顺序变化不影响不同会话之间的同分排序。
2. 检索结果分数不同时，保持现有按分数排序的行为。
3. CLI、MCP 和 Web 均呈现上述排序结果，沿用共用纯函数的调用方式。
4. 项目过滤与 limit 的现有语义保持不变。同分排序规则适用于最终返回的结果，包括同分结果跨越 limit 截断位置的情况。
5. 排序不改变结果字段或字段值。

## 边界与约束

- Windows、Linux、macOS 必须具有相同的排序语义。
- 变更范围限于三平台共用的排序纯函数。输入为已解码的 Python 数值分数和整数会话 ID，输出为排序后的列表。
- 会话 ID 使用数值比较，不使用字符串比较。例如，同分时 ID `2` 排在 ID `10` 之前。
- 不引入系统、文件、数据库、网络、时间或区域设置依赖，不增加平台分支。
- 不更改受支持的 Python 运行时范围、依赖、安装或服务。
- 空列表、单条结果及不足 limit 的结果继续遵循现有行为。
- 分数与会话 ID 均相同的记录之间不新增排序规则。
- 特殊数值分数的既有比较行为保持不变，本次不新增分数归一化或异常值处理规则。

## 设计决策

在现有分数排序规则之后，以整数会话 ID 升序作为同分时的次级排序规则。规则由共用纯函数统一承担，确保三个入口和三个平台具有一致行为。

当前材料未显示需要维护者额外决定的事项。现有执行环境仅为 macOS，不能将本机验证结果表述为已在 Windows、Linux 上执行验证；跨平台排序一致性仍是交付要求。

## 验收条件

1. 对分数相同、会话 ID 不同的结果，输出中的会话 ID 按数值升序排列，包括 `2` 与 `10` 这样的数值顺序与字符串顺序不同的情况。
2. 对同一组同分且会话 ID 不同的结果，改变输入排列后，输出的会话 ID 顺序一致。
3. 对分数不同的结果，输出相对顺序与变更前一致；混合分数组中，仅同分组内按会话 ID 升序排列。
4. CLI、MCP 和 Web 对相同检索条件呈现一致的排序规则。
5. 项目过滤后的结果仍仅包含符合原过滤条件的记录；排序不改变过滤语义。
6. limit 的数量与边界处理保持现有语义；当同分结果跨越截断位置时，返回的同分会话符合 ID 升序规则，且不因输入排列变化而改变。
7. 排序前后，各条结果的字段及字段值保持一致。
8. 空列表、单条结果及不足 limit 的结果保持现有返回行为。
9. Windows、Linux、macOS 对相同输入具有相同排序语义，且实现不依赖平台分支或外部环境状态。
