# 规格：Hub 重启后自动恢复同步

依据：[已确认意图](./intent.md)。

## 预期行为

1. 已配置数据来源并启用自动同步后，机器重启时，Hub 自动在后台启动并继续同步，无需用户手动运行前台命令或重新输入凭据。
2. 重启前已有的归档、来源配置和同步进度得到保留。恢复同步时沿用已保存的进度，不因重启清空归档或重复导入已有数据。
3. 某个来源不可达时，Hub 保留该来源已有归档及其可检索能力，并报告同步失败，不将失败视为同步成功或丢弃恢复所需的进度。
4. 来源恢复可达后，Hub 自动重试并继续同步；重试不重复导入已经成功归档的数据。

## 边界与约束

- 仓库目前仅声明 Python 3.11+，未声明支持的操作系统、服务类型或部署账号。本次不能据此推断跨平台支持，也不能以开发电脑为 macOS 为由将交付范围限定为 macOS。
- README 示例路径、现有前台命令在 macOS 交互式终端中的运行经历，均不能证明系统启动后台运行、凭据持久化或其他部署环境已受支持。
- 本次变更涉及后台同步进程、凭据存储，以及归档和进度的持久化访问。各组件的适用环境须分别明确；不得假定后台进程继承交互式终端的环境变量、文件访问权限或登录状态。
- 现有归档、同步进度及前台命令通过环境变量读取凭据的行为应保持兼容。新增后台运行方式不得要求用户重新配置已有来源或重新导入已有归档。
- 来源不可达期间，已有归档仍须可检索；新数据的同步允许延后至来源恢复。
- 凭据失效、撤销或权限不足与来源不可达应区分处理。凭据持久化不承诺失效凭据可以继续使用，也不得静默丢弃归档或进度。

以下事项待维护者确认，确认前不能确定完整交付范围或判定交付通过：

- **支持的操作系统及部署方式**：决定采用哪些系统启动机制，以及必须取得哪些实际平台的重启恢复证据。
- **后台服务账号及启动时机**：明确是否必须在无人登录时启动，以及账号对凭据、归档和进度的访问权限。
- **归档检索的运行方式**：明确重启后如何提供检索能力，以验收来源不可达时归档仍可检索的承诺。

## 设计决策

1. **凭据持久化方案待确认。** 需明确凭据存储机制、读取身份、访问控制，以及现有环境变量凭据如何进入后台可用的持久化配置。不能以依赖用户重新打开终端或重新提供环境变量的方案满足自动恢复承诺。验收须覆盖选定服务账号在实际启动环境中读取凭据，且不能将凭据写入普通日志或失败报告。
2. **持久化状态的访问方式待确认。** 需明确后台进程使用的配置、归档和进度位置，以及与现有前台命令的共享方式。服务账号、工作目录和文件权限变化不得造成读取空状态、创建另一套归档或无法检索已有数据。
3. **恢复与去重的一致性要求。** 重启可能发生在导入过程中。归档写入与进度保存的设计须保证恢复后既不漏掉尚未完成的导入，也不重复导入已完成的数据；不得仅覆盖正常退出后的重启。
4. **失败报告与重试策略待确认。** 需明确后台失败的可查看入口、自动重试间隔或退避规则，以及恢复判定方式，使失败和恢复结果均可独立验收。
5. **前后台并发策略待确认。** 自动启动后仍可能有人执行原前台命令。需明确互斥或协调行为，避免同一来源被并发重复导入或损坏进度。

上述决定影响启动行为、凭据可用性、文件访问和进程生命周期，须在实施前确认，并据此补齐验收环境。

## 验收条件

1. **范围已明确**：维护者已确认支持的操作系统、部署方式、服务账号、启动时机及上述待确认设计；验收覆盖与这些决定一致。
2. **实际重启自动恢复**：在每个确认支持且启动机制不同的操作系统及部署方式中，机器实际重启后，Hub 在约定的登录状态下自动启动并继续同步，无需手动启动或重新输入凭据。
3. **实际服务身份可用**：在每种确认支持的凭据存储与服务账号组合中，后台进程能够读取持久化凭据，并访问重启前的来源配置、归档和进度；凭据不出现在普通日志或失败报告中。
4. **状态连续且无重复**：分别在已有同步进度和导入中途发生重启的情况下，恢复后的归档保留原有内容，继续导入应有的新数据，已成功归档的数据无重复，未完成的数据无遗漏。
5. **不可达时仍可检索**：来源不可达并经历重启后，使用约定的实际检索入口仍能检索重启前的归档；失败报告可查看且能识别失败来源，同步进度未被错误推进。
6. **恢复后自动重试**：来源恢复可达后，无需人工重新启动同步，Hub 在已确认的重试规则内继续同步；此前成功导入的数据不重复，故障期间新增的数据最终被导入。
7. **现有入口兼容**：原前台命令仍能通过环境变量取得凭据并使用现有归档和进度；与后台进程同时运行时，行为符合已确认的并发策略，且不产生重复数据或状态损坏。
8. **证据覆盖充分**：启动、凭据访问、文件权限及归档检索须在对应的实际操作系统和运行方式中取得通过证据。与环境无关的进度恢复、去重和重试逻辑可以共用测试，但须说明其覆盖边界，不能替代实际重启和服务环境验证。无需各平台重复全部共用逻辑测试。
9. **未取得必要证据不算完成**：当前 macOS 交互式终端经历不足以证明本次后台运行承诺。任何已确认支持环境缺少必需的实际运行证据，均属于交付未完成项；不能仅标记“未验证”后判定通过。

具体机器、实施位置、测试步骤、命令及 CI 配置写入 `plan.md`，不得由其另行决定必要验收范围。
