# 规格：Hub 自动归档 VibeInsight 历史与项目关联检索

依据同目录下已确认的 [intent.md](intent.md)。本规格中标为“待维护者决定”的事项需在实施前确认。

## 预期行为

### 来源配置与持续同步

1. 维护者通过 Hub CLI 提供 VibeInsight 来源连接参数和凭据时，CLI 验证连接及来源读取能力。验证成功后保存配置；验证失败时报告错误，不替换已有有效配置及凭据。
2. 保存有效来源配置后，Hub 自动同步该来源可读取的全部项目历史，无需逐项目手工开启。此后持续同步新增会话事件及旧会话追加的轮次。
3. 来源后来新增可读项目时，即使其历史事件早于已有同步进度，Hub 仍补齐该项目的可读历史。
4. Hub 重启后使用已保存的连接参数和凭据自动继续同步，无需维护者重新输入密码。
5. 来源连接、查询或同步失败时，已经归档的数据仍可通过现有 CLI/MCP 检索和读取。来源恢复后，Hub 重试尚未成功归档的数据。
6. 重复读取事件、近期事件回查以及失败后重试均不产生重复归档。批次归档内容与对应进度一同提交；未成功提交的批次不得使进度越过尚未归档的数据。

### 项目身份与关联

1. 本机端上传对话时补传项目归属；CLI/MCP 发起项目查询时携带当前项目身份。同名但身份不同的项目保持可区分。
2. Hub 维护者统一管理项目关联，既可关联设备项目与 VibeInsight 项目，也可关联不同设备上的项目。
3. 关联双向生效且仅扩展一层：若 A 与 B 关联、B 与 C 关联，从 A 发起项目查询时包含 A 和 B，不因 B 与 C 的关系自动包含 C；从 B 查询时包含 B、A 和 C。
4. 解除项目关联后，后续项目查询不再通过该关系扩展范围；已归档数据不被删除，仍可在适用的全局查询或直接原文读取中访问。

### 检索与原文读取

1. 用户通过现有 CLI/MCP 可检索已归档的 VibeInsight 对话，并精确读取对应原文。
2. CLI/MCP 返回足以定位原文的来源、项目、原会话及消息位置信息。不同来源、同名项目或同名会话不得导致原文定位混淆。
3. 新增来源及项目身份后，已有原文引用仍可使用。
4. Hub 不可用时，客户端沿用现有本机全局回退行为。
5. 未携带项目身份的旧客户端继续执行兼容的全局查询，不因新增项目范围能力而失效或被意外限定到某个项目。

## 边界与约束

- 首版仅面向单用户，不引入多用户授权与数据隔离要求。
- 来源读取仅使用由 Hub 服务调用的外部 PostgreSQL 客户端 `psql`，对 VibeInsight 仅执行只读查询。
- 同步覆盖新增会话事件和追加轮次；不要求发现没有新增事件的历史正文原地改写。
- 保持 Windows、Linux、macOS 支持范围，不缩减既有部署平台。
- 保持既有服务运行方式：Windows 使用 LocalService 系统服务，Linux 使用 systemd 用户服务，macOS 使用 launchd 系统服务。
- 配置 CLI 与长期运行的 Hub 服务可能属于不同账号或环境。配置成功的判断必须覆盖实际服务账号读取配置、读取秘密文件和调用 `psql` 所需的能力，不能仅以 CLI 当前环境能够连接为依据。
- 密码不得以原值出现在 CLI 输出、日志或对话数据库中。服务运行账号必须能够读取秘密文件，其他未授权普通账号不得读取。
- 当前仅具备 macOS 执行条件；Windows/Linux 尚无本次执行记录，不能据此认定跨平台验收已通过。未来默认回归可使用合成事件，无需在真实来源服务器造数。

## 设计决策

1. 连接参数保存在 Hub 配置文件，密码保存在服务状态目录的专用秘密文件。秘密文件的访问控制须适配各平台及既有服务账号。
2. 新配置验证成功后才替换有效配置。替换结果必须保持连接参数与凭据一致；验证或保存失败不得破坏原有效配置。
3. 同步进度保存在 Hub 数据库，批次归档与进度在同一次事务中提交。重启后从已提交位置继续，并回查近期事件去重。
4. 项目关联由 Hub 统一维护，以项目身份而非显示名称确定关联对象。查询仅使用起始项目的直接关联，不递归展开。

待维护者决定：

- 来源配置、状态查看、项目关联及解除关联的具体 CLI 命令与参数形式。
- 跨账号配置时，如何确定实际服务环境、验证 `psql` 可执行路径及秘密文件权限，并向维护者报告缺失条件。
- 同步与重试间隔、近期事件回查窗口，以及新增可读项目的发现和补齐周期。
- CLI/MCP 定位字段的具体结构、稳定身份规则及与旧原文引用的兼容方式。

## 验收条件

1. 使用有效来源配置后，全部可读项目的历史均可归档；新增会话和旧会话追加轮次随后均可被检索并读取。
2. 已有同步进度后新增一个可读项目，其早于该进度的历史仍能完整归档。
3. 保存有效配置并重启 Hub 后，无需再次输入密码即可继续同步。
4. 提交无效凭据后，CLI 明确报告失败；原有效配置仍可使用，重启后仍能连接原来源。
5. 在 CLI 与服务账号或环境不同的条件下，服务仍可读取所保存配置及秘密文件并调用 `psql`；缺少必要条件时不能报告配置成功。
6. 在 Windows、Linux、macOS 上，既有服务类型保持不变；服务账号可读取秘密文件，未授权普通账号不能读取，CLI 输出、日志及对话数据库均不含密码原值。
7. 来源中断期间，已有归档仍可检索及读取；恢复后遗漏数据能够补齐，重复读取和重试不增加重复归档。
8. 批次提交失败或 Hub 在提交前中断时，进度不会越过未归档数据；提交成功后重启可继续，回查不产生重复记录。
9. 设备上传的项目归属和 CLI/MCP 的当前项目身份可用于项目查询；同名项目查询结果保持可区分。
10. 设备项目与来源项目、不同设备项目均可建立双向关联；A—B—C 关系下，从 A 查询仅扩展至 B，从 B 查询可扩展至 A 和 C。
11. 解除关联后，项目查询范围相应收缩；归档数据仍存在，已有有效原文引用仍可读取。
12. CLI/MCP 检索结果包含来源、项目、原会话和消息位置，使用这些信息可精确读取对应原文，不混淆同名项目或会话。
13. 旧客户端不携带项目身份时仍可进行全局查询；Hub 不可用时客户端沿用本机全局回退行为。
14. 来源读取过程中不修改 VibeInsight 数据；没有新增事件的历史正文原地改写不作为本次同步完整性的验收要求。
