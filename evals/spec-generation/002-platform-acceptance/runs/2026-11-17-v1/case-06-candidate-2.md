# 规格：明确来源管理命令帮助

本规格依据同目录下已确认的 [intent.md](intent.md) 及提供的项目资料，变更范围限于来源管理 CLI 帮助文案，无待维护者确认事项。

## 预期行为

1. 用户执行 `smm source --help` 时，帮助以简体中文显示全部现有子命令及其用途，用户无需查阅其他文档即可区分：

   | 子命令 | 帮助须表达的含义 |
   |---|---|
   | `list` | 查看本机来源状态。 |
   | `validate` | 使用来源清单和测试样本验收候选适配器。 |
   | `register` | 使用来源清单和测试样本验收候选适配器，通过后注册来源。 |
   | `enable` | 启用指定来源的导入。 |
   | `disable` | 停用指定来源的导入，保留已导入记录。 |
   | `rollback` | 将指定插件来源的适配器切回上一版。 |
   | `batches` | 查看指定插件来源的导入批次，记录中的 `id` 是批次 ID。 |
   | `purge-batch` | 从 SMM 本机档案删除指定来源、指定批次已导入的记录；清理前须先停用对应的插件来源。 |

2. 用户执行 `smm source purge-batch --help` 时，帮助须说明：

   - `source_id` 是待清理批次所属的插件来源 ID。
   - `batch` 是整数批次 ID，可从 `smm source batches` 返回的批次记录 `id` 获取。
   - 清理会从 SMM 本机档案删除该批次已导入的记录。
   - 清理前须先使用 `smm source disable` 停用对应的插件来源；来源仍启用时，清理会被拒绝。

3. 两条帮助命令均打印帮助并以状态码 `0` 退出，不创建档案对象、不执行来源操作、不写入档案。

## 边界与约束

- 沿用现有命令名、参数、参数类型、必填性及操作行为。本次不新增命令、选项或操作前置检查。
- `validate`、`register` 继续接收位置参数 `manifest` 和必填选项 `--fixture`。
- `enable`、`disable`、`rollback`、`batches`、`purge-batch` 继续接收位置参数 `source_id`；`purge-batch` 继续额外接收整数位置参数 `batch`。
- 文案须明确区分停用导入、回退适配器版本和删除批次记录，不能将三者描述为等价操作。
- 删除范围限于 SMM 本机档案中该批次已导入的记录，不应暗示会删除原始来源文件或整个来源的全部历史记录。
- 本次仅涉及本机 CLI 帮助，不涉及其他组件的操作系统或部署支持。提供的资料未列出 CLI 支持的操作系统，本次不新增、缩减或推断平台承诺。

## 设计决策

帮助沿用现有 CLI 帮助入口与解析流程，以简体中文补充用途、参数含义和清理前置条件。无需为展示帮助访问来源、加载候选适配器或建立档案。

本次交付风险集中在文案准确性、帮助输出和解析兼容性。改动不涉及平台专属路径、外部服务、服务账号或进程生命周期，因此可在一个实际可运行现有 CLI 的环境中验证共用帮助逻辑，无需机械重复各平台完整测试。该证据仅证明共用帮助行为，不代表其他平台已实际运行通过。

## 验收条件

1. 实际执行 `smm source --help`，输出包含全部八个现有子命令及对应的简体中文用途，逐项符合“预期行为”中的含义。
2. 顶层帮助明确表达以下三个不同结果：`disable` 停用导入且保留记录；`rollback` 将插件适配器切回上一版；`purge-batch` 删除指定批次已导入的记录。
3. 两条帮助输出均明确提示：清理批次前须先停用对应的插件来源。
4. 实际执行 `smm source purge-batch --help`，输出保留 `source_id`、`batch` 两个位置参数，并准确说明批次 ID 的整数要求、获取来源、删除范围及来源启用时拒绝清理的行为。
5. 两条帮助命令均以状态码 `0` 退出；即使档案尚未建立，也能展示帮助，且不创建档案对象、不执行来源操作、不产生档案写入。
6. 现有命令及参数定义保持兼容，包括 `manifest`、必填的 `--fixture`、`source_id` 和整数 `batch`；变更未修改来源注册、启停、回退或批次清理逻辑。
7. 上述帮助输出、退出状态和无档案副作用，须在至少一个实际可运行现有 CLI 的环境中取得通过证据；仅审阅文案或完成包构建不足以判定通过。其充分性限于本次共用 CLI 帮助文案与解析行为，不构成新增平台支持声明。
