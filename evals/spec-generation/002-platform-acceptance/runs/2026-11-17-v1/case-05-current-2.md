# 规格：Hub 重启后自动恢复同步

本规格依据同目录下已确认的 [intent.md](intent.md)。支持的操作系统、后台服务类型、部署账号与凭据持久化方案仍需维护者决定；当前开发电脑为 macOS 不构成部署范围的确认。

## 预期行为

1. 完成后台运行与凭据持久化配置后，机器重启时，Hub 自动启动并继续同步已配置的数据来源，无需用户打开交互式终端、手动执行同步命令或重新输入凭据。
2. 自动恢复同步时，Hub 保留并使用已有来源配置、归档和同步进度，不因重启清空归档或从头重复导入已有内容。
3. 某个来源不可达时，Hub 保留该来源已有归档及其可检索能力，并报告同步失败。失败报告应能识别对应来源，不能将失败呈现为同步成功。
4. 来源恢复可达后，Hub 自动重试，依据保留的同步进度继续导入；不可达期间的失败和重试不得导致同一内容被重复导入。

## 边界与约束

- 已确认的运行要求仅为 Python 3.11+，不足以确定后台服务所支持的操作系统、服务机制或部署账号。
- 不得依据 README 示例路径、当前 macOS 开发环境或前台命令的运行经历，将本次支持范围限定为 macOS；也不得据此承诺支持 Windows 或 Linux。
- 现有归档和同步进度须在后台运行、机器重启、来源不可达及恢复重试过程中保留。
- 现有前台同步命令通过环境变量取得凭据的方式须保持可用。新增后台运行方式不得要求现有前台调用方改用持久化凭据。
- 后台运行不得依赖交互式终端中临时设置的环境变量。持久化凭据须能由选定的服务账号在重启后读取，具体存储与访问控制方案待确认。
- 本规格不承诺未确认平台的支持能力；平台相关验收范围须在维护者确认部署范围后确定。

## 设计决策

以下事项须在实施前由维护者确认：

| 待确认事项 | 需要明确的内容 |
| --- | --- |
| 部署范围 | 本次支持的操作系统及适用环境。现有资料无法据此作出选择。 |
| 后台服务与账号 | 启动机制、运行账号，以及该账号访问来源配置、归档、同步进度和凭据的权限。 |
| 凭据持久化 | 存储方式、首次配置方式，以及现有环境变量凭据如何供后台服务持续使用。不得默认将凭据明文写入服务配置。 |
| 失败报告 | 报告的查看入口和必要信息，使维护者能够识别失败来源。 |
| 自动重试 | 重试触发方式与间隔，使来源恢复后无需人工操作即可继续同步。 |

上述决定须共同保证：后台服务在重启后能够访问原有数据和有效凭据，且无需用户重新输入凭据。

## 验收条件

1. 在确认支持的部署环境中完成配置后，机器重启，无需交互式终端或人工启动，Hub 自动继续同步已配置来源。
2. 重启前已有的来源配置、归档和同步进度在重启后仍可使用；已有归档仍可检索，恢复同步不重复导入已有内容。
3. 凭据完成持久化配置后，机器重启，后台服务无需再次输入凭据即可访问对应来源；该行为不依赖原交互式终端的环境。
4. 某个已配置来源不可达时，其已有归档仍可检索，并通过确认的报告入口明确呈现该来源同步失败。
5. 来源由不可达恢复为可达后，Hub 按确认的重试机制自动继续同步，导入待同步内容，且不产生重复导入。
6. 原有通过环境变量提供凭据的前台同步命令仍可使用。
7. 维护者已明确部署范围、服务类型、运行账号、凭据持久化方案、失败报告入口及重试机制；最终验收覆盖所确认的部署范围，不以当前 macOS 开发环境替代支持范围确认。
