# 规格：明确来源回退命令的简体中文用途

本规格依据同目录下已确认的 [intent.md](intent.md)，保留项目现有平台支持和命令行为承诺。现有材料足以确定本次交付范围，无待维护者确认事项。

## 预期行为

1. 用户执行 `smm source --help` 时，`rollback` 的用途说明显示为“将该插件来源的适配器切回上一版，保留已导入对话”，明确回退对象是该插件来源的适配器，已导入对话会保留。
2. 用户执行 `smm source rollback --help` 时，用途说明显示相同文案。
3. 两条帮助命令均继续在创建档案对象前输出帮助，以状态码 `0` 退出，不访问来源、不写档案、不启动服务。
4. 命令名、参数、命令解析、非帮助调用的退出行为及真实回退操作保持不变。

## 边界与约束

- 本次仅修改同一 Python 模块内的静态 argparse 简体中文帮助字符串，不调整其他帮助内容或回退功能。
- 本机端继续支持 Windows、Linux、macOS，不缩减或扩大支持范围。
- 三平台共用该字符串定义，且无平台分支。本次不修改终端编码、输出组件、依赖或打包配置。
- 原版本在三平台均可显示中文帮助，且没有针对本说明文本的渲染或编码缺陷报告；本次不引入新的平台适配要求。
- 帮助中的“保留已导入对话”用于澄清已有回退语义，不构成对真实回退操作的变更。

## 设计决策

两条帮助入口使用相同的已确认文案，避免总帮助与子命令帮助对回退范围表达不一致。

本次变更的直接观察面是两条帮助输出、参数和退出行为。由于仅修改三平台共用的静态字符串，且中文输出能力已有支持承诺，当前 macOS 环境中的实际帮助输出验证，结合变更范围审查，足以验收本次修改；无需在 Windows、Linux 重复完整测试。

上述充分性仅适用于本次静态文案修改，不代表 Windows、Linux 已实际运行验证。若实施涉及平台分支、编码、输出组件、依赖或打包配置变化，则超出本规格范围，需重新确认验收覆盖。

## 验收条件

1. 在 macOS 实际执行 `smm source --help`，`rollback` 条目的用途文案为“将该插件来源的适配器切回上一版，保留已导入对话”；允许终端正常换行，文字及标点须一致。
2. 在 macOS 实际执行 `smm source rollback --help`，用途说明包含相同文案，且不再以原有含糊说明描述该用途。
3. 两条帮助命令均以状态码 `0` 退出，并有可判定证据表明其在创建档案对象前结束，不访问来源、不写档案、不启动服务。
4. 两条帮助输出中的命令名、参数及其他帮助内容与变更前一致，仅允许本次文案变化及其引起的正常换行变化。
5. 变更审查确认仅修改三平台共用的静态帮助字符串，未改变命令解析、退出行为、真实回退操作、编码、输出组件、依赖或打包配置。
6. 项目保留的既有回退功能测试继续通过，用于确认真实回退行为未受影响。
7. 完成上述 macOS 实际输出验证、共用定义及变更范围审查后，可判定本次文案交付通过；Windows、Linux 的支持承诺继续保留，但不记为本次已取得实际运行证据。
