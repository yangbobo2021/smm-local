# 规格：同分检索结果按数值会话 ID 稳定排序

本规格依据同目录下已确认的 [intent.md](intent.md) 及项目现有承诺起草。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列。例如，会话 ID 为 `10`、`2` 的同分结果，应按 `2`、`10` 返回。
2. 对同一组结果打乱输入顺序后，同分且会话 ID 不同的结果仍返回相同顺序。
3. 不同分数结果之间沿用现有排序规则；会话 ID 仅用于分数相同时的排序。
4. 结果字段及其值、项目过滤规则和 limit 语义保持不变。limit 截取边界涉及同分结果时，按会话 ID 升序确定相应结果的先后。
5. CLI、MCP 和 Web 继续使用共用排序函数，均提供上述排序语义。

## 边界与约束

- 现有客户端对 Windows、Linux、macOS 的支持保持不变，三平台承诺相同的稳定排序语义。
- 本次变更限定于三平台共用的纯排序函数。输入为已解码的 Python 数值分数和整数会话 ID，输出为排序后的列表。
- 会话 ID 按数值比较，不转换为字符串进行字典序比较。
- 分数和会话 ID 均相同的结果，不新增第三排序规则，沿用现有行为。
- 不新增输入类型、异常数值处理规则或重复结果处理规则。
- 不改变 Python 运行时范围、依赖、安装方式或服务运行方式。

## 设计决策

在现有分数排序规则之后，以整数会话 ID 升序作为次级排序规则。CLI、MCP 和 Web 沿用现有调用方式，不增加入口专属排序逻辑。

本次验收可在当前 macOS 环境使用合成输入验证共用函数。其充分性依据是：函数没有平台分支，不访问系统、文件、数据库、网络、时间或区域设置，三平台采用相同受支持的 Python 数值比较语义；本次也不涉及部署或进程生命周期变化。

因此，不要求 Windows 和 Linux 重复执行本次排序测试。该覆盖结论仅适用于上述共用纯函数的排序行为，不代表已在 Windows 或 Linux 实际运行通过，也不覆盖安装、服务启动等未变更行为。

现有资料足以确定本次交付及验收范围，无待确认的环境决定。

## 验收条件

1. 在 macOS 上对共用函数取得通过证据：同分结果按会话 ID 数值升序排列，包含 `2` 与 `10` 等可区分数值排序和字符串排序的输入。
2. 对同一组分数相同、会话 ID 不同的结果采用不同输入排列，输出的会话 ID 顺序一致且为升序。
3. 混合不同分数和同分结果时，不同分数之间保持现有排序，同分组内按会话 ID 升序排列。
4. 排序前后结果字段及其值保持一致，结果不因排序而新增或丢失；空列表和单条结果沿用现有行为。
5. 项目过滤行为保持不变；limit 的现有边界行为保持不变，截取边界落在同分组内时，返回顺序符合会话 ID 升序规则。
6. 分数及会话 ID 均相同的结果保持现有处理行为。
7. 确认 CLI、MCP 和 Web 仍调用该共用函数，且没有额外排序层或平台实现；结合共用函数通过证据，覆盖三个入口的排序语义。
8. 审阅确认实现仍满足上述纯函数及相同数值比较语义的前提。若引入平台分支或环境依赖，须重新明确受影响平台所需的实际运行证据，并在取得必需证据前保持交付未完成。
