# 规格：Hub 自动同步 VibeInsight 历史与项目关联检索

本规格依据同目录下已确认的 [intent.md](intent.md)。尚需维护者决定的事项列于「设计决策」。

## 预期行为

### 来源配置与恢复

1. 维护者通过 Hub CLI 提交 VibeInsight 来源连接参数和凭据时，Hub 验证连接及只读访问能力。验证成功后保存配置；验证失败时返回可诊断的错误，已有有效配置和凭据保持可用。
2. 配置成功后，长期运行的 Hub 服务能够使用保存的连接参数、秘密文件和 `psql` 读取来源，不依赖执行配置命令的终端会话或临时环境。
3. Hub 重启后自动恢复来源连接并继续同步，无需维护者重新输入密码。
4. 来源连接、凭据或读取失败时，Hub 保留已有归档及已提交进度，现有归档仍可检索和读取；来源恢复后自动重试未成功归档的数据。

### 历史与持续同步

1. Hub 自动发现并归档 VibeInsight 当前凭据可读取的全部项目历史，无需逐项目手动导入。
2. 来源新增会话或已有会话追加轮次后，Hub 持续将新增内容归档，使其可通过现有 CLI/MCP 检索和读取。
3. 来源后来新增可读项目时，Hub 补齐该项目的全部可读历史，包括时间早于其他项目已有同步进度的内容。
4. 重复读取、近期事件回查或失败重试不得产生重复归档。同一会话的追加内容归入对应会话，已归档消息的位置保持可引用。
5. 每个同步批次的归档数据与同步进度一同提交。批次未提交时不得推进进度；重启后从已提交位置继续，并通过近期事件回查与去重补齐遗漏。

### 项目归属与关联

1. 本机端补传项目归属；CLI/MCP 发起项目查询时携带当前项目身份。项目身份能够区分同名项目。
2. Hub 维护者统一创建和解除项目关联，支持设备项目与 VibeInsight 项目之间、不同设备项目之间的关联。
3. 关联双向生效。查询任一项目时，范围包括该项目及其直接关联项目，只扩展一层。
4. 若 A 关联 B、B 关联 C，而 A 未直接关联 C，则从 A 发起的项目查询不因上述关系纳入 C。
5. 解除关联后，后续项目查询不再通过该关系扩展范围；已归档内容不被删除，已有原文引用仍可读取。

### 检索、原文读取与回退

1. 用户通过现有 CLI/MCP 检索 Hub 归档时，能够获得符合查询范围的设备历史和 VibeInsight 历史。
2. CLI/MCP 返回足以区分并定位内容的来源、项目、原会话和消息位置信息；调用方可据此精确读取对应原文。同名项目、不同来源的会话不得混淆。
3. 新增来源和项目身份信息后，既有原文引用继续可用。
4. Hub 不可用时，沿用本机全局查询回退行为。
5. 旧客户端未携带项目身份的全局查询继续可用，不强制要求升级为项目查询。

## 边界与约束

- 首版面向单用户，项目关联由 Hub 维护者统一管理。
- 来源同步仅覆盖当前凭据可读取的数据，对 VibeInsight 仅执行只读查询。
- 首版支持新增会话事件与已有会话追加轮次；不要求发现没有新增事件的历史正文原地改写。
- 保持 Hub 与本机端对 Windows、Linux、macOS 的支持，不缩减平台范围。
- 保持既有服务运行方式：Windows 使用 LocalService 系统服务，Linux 使用 systemd 用户服务，macOS 使用 launchd 系统服务。
- 来源读取使用外部 PostgreSQL 客户端 `psql`，由 Hub 服务调用。必须考虑 CLI 与服务账号、安装路径及可执行环境不同的情况。
- 连接参数保存在 Hub 配置文件；密码保存在服务状态目录的专用秘密文件。运行账号须可读取，其他未授权普通账号不可读取。
- CLI 输出、日志和对话数据库均不得包含密码原值。
- 来源失败或解除项目关联均不得删除已有归档。
- Hub 不可用时的本机全局回退不承诺提供仅存在于 Hub 中的归档。

## 设计决策

### 已确认的决定

- 采用配置文件保存连接参数、专用秘密文件保存密码，使长期服务可在重启后恢复连接，并限制凭据暴露。
- 新配置验证成功后才替换有效配置，避免无效凭据破坏现有同步能力。配置成功必须意味着目标服务账号能够实际使用该配置。
- 同步进度存入 Hub 数据库，并与批次归档原子提交，避免进度领先于归档造成数据遗漏。
- 采用项目身份而非项目名称确定查询范围；项目关联由 Hub 维护，按双向直接关系扩展一层。
- 在现有 CLI/MCP 上提供来源和定位信息，同时保持旧客户端全局查询及旧原文引用兼容。

### 仍需维护者决定

- Hub CLI 中来源配置、验证和项目关联管理的命令名称、参数及错误展示形式。
- 各平台服务账号所用的秘密文件位置、访问权限设置方式，以及 CLI 如何完成跨账号配置交付。
- `psql` 的安装前提、路径配置与服务环境下的可执行性检查方式。
- 自动发现、持续同步和失败重试的周期，以及近期事件回查窗口。
- CLI/MCP 新增来源、项目、原会话及消息位置字段的具体结构与兼容方式。
- 项目身份映射、归档去重和原文定位采用的稳定标识规则。

上述决定不得削弱本规格规定的跨平台支持、凭据保护、历史补齐及兼容行为。

## 验收条件

1. 提交可用来源配置后，Hub 服务可执行只读查询并保存配置；提交无效连接或凭据后，原有效配置仍可使用。
2. CLI 配置账号与服务运行账号或环境不同时，配置成功后服务仍能找到 `psql` 并读取凭据；服务重启无需再次输入密码。
3. Windows、Linux、macOS 均保持既有发行支持和服务类型；各平台的服务账号均可读取秘密文件，未授权普通账号不可读取。
4. CLI 输出、错误信息、日志及对话数据库中均不出现密码原值。
5. 来源包含多个可读项目时，所有项目的既有历史均可在 Hub 检索并读取；新增会话和追加轮次能够持续归档。
6. 在已有同步进度之后开放一个含更早历史的项目，该项目的早期历史和后续新增内容均能归档。
7. 对同一批事件重复读取、回查或重试后，不产生重复会话或消息；追加轮次仍归属原会话。
8. 同步批次在提交前中断时，归档与进度均不部分生效；提交后重启时，从已提交位置继续且不遗漏未成功数据。
9. 来源中断期间，已有归档仍可查询和读取；来源恢复后，无需重新配置即可自动重试并补齐未成功归档的数据。
10. 本机端补传的项目归属可用于项目查询；两个同名项目保持可区分，查询范围不会因同名而合并。
11. 设备项目与 VibeInsight 项目、不同设备项目之间均可建立双向关联；从关联任一端查询均包含另一端。
12. 对 A—B—C 的关联结构，从 A 查询包含 A 和 B，不因 B—C 关系包含 C；解除 A—B 后，不再通过该关系纳入 B，归档及原文引用仍可用。
13. CLI 和 MCP 的检索结果均提供来源、项目、原会话和消息位置，使用返回信息能精确读取对应原文；既有原文引用继续有效。
14. Hub 不可用时，CLI/MCP 保持既有本机全局回退；旧客户端未携带项目身份时，仍能执行全局查询。
15. 没有新增事件的历史正文原地改写不作为首版同步通过条件。

当前仅有 macOS 执行条件，Windows/Linux 的本次执行记录尚不存在，不能据此认定跨平台验收已通过。具体实施位置、实施顺序和验证方法写入 plan.md；默认回归可使用合成事件，无需在真实来源服务器造数。
