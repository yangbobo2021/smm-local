# 规格：Hub 重启后自动恢复同步

以同目录下已确认的 [intent.md](intent.md) 为依据。本草稿中的操作系统范围、后台服务形式、运行账号及凭据持久化方案仍需维护者决定。

## 预期行为

1. 已配置数据来源且完成后台运行配置后，机器重启时 Hub 自动启动并继续同步，无需用户打开交互式终端或再次手动执行前台命令。
2. 自动恢复同步时，Hub 使用原有来源配置、归档和同步进度，不要求重新输入凭据，也不因重启而清空归档或从头重复导入。
3. 某个已配置来源不可达时，Hub 保留该来源已有归档及其可检索性，并报告同步失败。失败信息应能识别受影响的来源，不泄露凭据。
4. 来源恢复可达后，Hub 自动重试并继续同步；此前已经导入的内容不被重复导入。
5. 后台运行所需凭据在机器重启后仍可供选定的运行账号使用。首次保存、更新凭据的操作方式及失败报告入口，需在实施前确认。

## 边界与约束

- 仓库目前仅声明 Python 3.11+，尚未确认本次支持的操作系统、服务类型或部署账号。不得根据当前开发电脑或 README 示例路径推定部署范围。
- 当前 macOS 交互式终端运行记录不能证明后台启动、重启恢复或凭据持久化可用，也不能证明其他平台受支持。
- 本次既不默认限定为 macOS，也不默认新增 Windows/Linux 支持。最终适用范围须由维护者明确。
- 后台服务不得依赖交互式终端临时提供的环境变量才能在重启后取得凭据；原命令通过环境变量取得凭据的使用方式应保持兼容。
- 归档和进度的持久化位置、访问权限须与选定的服务账号相容，避免后台启动后使用空目录而表现为数据丢失或重新导入。
- 来源不可达不得导致已有归档或同步进度被删除。重试应保留已完成同步的成果。
- 不在失败信息或日志中输出凭据明文。

## 设计决策

以下事项缺少确认依据，实施前需维护者决定：

| 待决定事项 | 需要明确的内容 |
| --- | --- |
| 部署范围 | 本次承诺支持的操作系统及适用部署场景 |
| 后台运行方式 | 随系统启动的服务机制、运行账号，以及是否需要用户登录 |
| 数据持久化 | 后台与前台访问既有配置、归档和进度的位置及权限安排 |
| 凭据持久化 | 保存机制、访问权限，以及首次配置和更新方式；应满足重启后无需再次输入凭据 |
| 失败报告 | 用户或调用方查看来源同步失败的入口 |
| 自动重试 | 重试触发方式及间隔，明确恢复后何时再次尝试同步 |

上述决定不得以当前开发环境代替部署范围确认。具体实现位置、实施顺序和验证方法写入 plan.md。

## 验收条件

1. 在每个经维护者确认的支持环境中，已完成配置的 Hub 在机器重启后自动继续同步，无需打开终端、手动启动命令或重新输入凭据。
2. 重启前已有的来源配置、归档及同步进度在重启后仍被使用；已有归档保持可检索，已导入内容不因重启再次导入。
3. 使某个已配置来源不可达后，该来源同步失败可通过已确认的报告入口查看，且能够识别来源；其已有归档仍可检索，归档和进度未被删除。
4. 来源恢复可达后，Hub 按已确认的重试规则自动继续同步，新增内容可被导入，已经导入的内容不产生重复记录。
5. 选定的后台运行账号能够在重启后取得持久化凭据，并访问既有配置、归档和进度，无需交互式终端提供临时环境变量。
6. 原有前台命令仍可通过环境变量取得凭据并执行同步。
7. 凭据保存和更新操作符合已确认方案，失败信息及日志不包含凭据明文。
8. 支持环境、后台服务、运行账号、持久化方案、报告入口和重试规则均已由维护者确认；未确认的部署范围不得表述为已支持。
