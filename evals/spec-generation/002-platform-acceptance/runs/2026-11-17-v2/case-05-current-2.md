# 规格：Hub 重启后自动恢复同步

依据：[已确认意图](./intent.md)。

本草稿供维护者审阅。支持的操作系统、后台服务类型、部署账号及凭据持久化方式仍需维护者决定；当前开发电脑为 macOS，不构成仅支持 macOS 的授权，也不构成新增 Windows/Linux 支持的承诺。

## 预期行为

1. 对已配置数据来源完成后台运行配置后，机器重启时，Hub 自动启动并继续同步，无需用户登录交互式终端、手动执行原前台命令或重新输入凭据。
2. 自动恢复同步时，Hub 保留并使用已有归档和同步进度，不因重启要求重新配置来源或从头导入。
3. 某个来源不可达时，Hub 保留该来源已有归档及其可检索性，并报告能够识别失败来源和失败原因的信息。失败不得被报告为同步成功。
4. 来源恢复可达后，Hub 自动重试，从已有有效进度继续同步。重启、失败和重试均不得导致同一来源中的同一条数据重复导入。
5. 凭据在首次配置后能够供重启后的后台运行使用，无需再次人工输入；凭据不可用时，Hub 报告凭据相关失败，保留已有归档和进度。

## 边界与约束

- 本次变更面向已配置的数据来源，不要求自动发现或新增来源。
- 现有归档、有效同步进度和检索能力必须保留；不得通过清空归档或重置进度实现恢复。
- 原前台同步命令通过环境变量取得凭据的使用方式应保持兼容。后台运行不得依赖交互式终端临时设置的环境。
- Python 3.11+ 是当前唯一已声明的运行要求，不能据此推定操作系统、服务管理机制或部署账号。
- README 示例路径、当前 macOS 开发环境及前台运行经历，均不能作为后台部署范围或跨平台验证依据。
- 本规格不宣称任何平台的后台运行已经通过验证。实施前须确认适用部署范围。

## 设计决策

以下事项尚待维护者确认：

1. **部署范围与服务机制**：明确本次支持的操作系统及对应后台服务类型，确定机器启动后无需交互式登录即可运行的方式。
2. **部署账号与访问权限**：明确后台服务使用的账号，以及其对已有归档、进度和凭据的访问权限，确保后台进程能够继续使用原有数据。
3. **凭据持久化**：明确凭据存储方式、访问保护、首次配置流程，以及现有环境变量凭据如何用于后台配置。不得默认后台服务继承交互式终端环境；凭据不得出现在失败报告中。
4. **重试与状态报告**：明确自动重试的间隔或退避规则，以及失败、恢复和凭据不可用状态的报告入口，使失败可见且恢复无需人工触发。
5. **进度与去重语义**：确认各来源如何识别已导入数据，以及进程在导入过程中因重启中断时如何恢复，保证重试不重复导入、不跳过尚未完成的数据。

## 验收条件

1. 在维护者确认的部署环境中，完成一次来源和凭据配置后重启机器，无需交互式登录、手动启动或重新输入凭据，Hub 自动继续同步。
2. 重启前已有归档在重启后仍可检索，已保存的有效进度继续生效，来源配置无需重建。
3. 来源不可达时，已有归档仍可检索，有效进度不被清空，并能查看对应来源的失败状态及原因。
4. 来源恢复后，无需人工触发，Hub 按已确认的重试规则继续同步并导入待同步数据。
5. 对已导入数据经历重启、来源不可达及恢复重试后，同一来源中的同一条数据仍只有一份导入结果。
6. 在导入过程中发生重启后，恢复同步既不重复导入已完成的数据，也不跳过尚未完成的数据。
7. 持久化凭据缺失或不可用时，Hub 明确报告凭据失败，不泄露凭据，不损坏已有归档或有效进度。
8. 原前台命令仍可按原有方式通过环境变量取得凭据并执行同步。
9. 部署范围、服务类型、部署账号、凭据方案、重试规则及状态报告入口均已获得维护者确认；验收结论仅覆盖已确认并验证的环境。
