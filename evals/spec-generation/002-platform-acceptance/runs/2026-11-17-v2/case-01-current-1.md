# 规格：Hub 自动同步 VibeInsight 历史与项目关联检索

依据：[已确认意图](./intent.md)。

## 预期行为

### 来源配置与持续同步

1. 维护者通过 Hub CLI 提交 VibeInsight 连接参数和凭据时，CLI 验证连接及读取能力。验证成功后保存为有效配置；验证失败时报告错误，保留原有效配置及凭据。
2. 配置成功后，Hub 自动归档该来源可读取的全部项目历史，并持续同步新增会话事件及已有会话追加的轮次，不要求用户逐个项目启动同步。
3. 来源后来新增可读项目时，Hub 补齐该项目全部可读取历史，包括时间早于已有同步进度的数据。
4. Hub 重启后，服务使用已保存的配置和凭据自动继续同步，无需维护者重新输入密码。
5. 来源连接、认证或读取失败时，已提交的归档仍可通过现有 CLI/MCP 查询和读取。来源恢复后，Hub 重试未成功归档的数据；重复读取和近期事件回查不产生重复归档。
6. 同步批次的归档与进度一同提交。中断后按已提交位置继续，不得因进度提前保存而遗漏数据。

### 项目关联与查询范围

1. 本机端补传对话的项目归属；CLI/MCP 发起项目查询时携带当前项目身份。项目身份必须能区分同名项目。
2. Hub 维护者统一管理项目关联，可建立设备项目与 VibeInsight 项目之间、不同设备项目之间的关联，并可解除关联。
3. 项目关联双向生效。查询项目 A 时，范围包括 A 及其直接关联项目；不沿关联继续扩展。例如 A 关联 B、B 关联 C 时，仅凭这两条关系，查询 A 不包含 C。
4. 解除关联后，后续项目查询不再通过该关系扩展范围；已有归档不删除，仍可通过全局查询及原文引用访问。

### 检索、原文读取与回退

1. 用户通过现有 CLI/MCP 检索同步归档时，结果包含来源、项目、原会话和消息位置，足以区分同名项目中的会话，并精确读取对应原文。
2. 新增来源和项目归属信息后，已有原文引用继续可用。
3. Hub 不可用时，客户端沿用现有本机全局回退行为。
4. 旧客户端未携带项目身份发起全局查询时，继续获得全局查询结果，不因新增项目范围能力而被隐式限制到某个项目。

## 边界与约束

- 首版为单用户，不引入多用户隔离或权限体系。
- 同步覆盖新增会话事件与追加轮次；不要求发现没有新增事件的历史正文原地改写。
- VibeInsight 来源仅执行只读查询，不写入或修改来源数据。
- 保持 Hub 和本机发行包对 Windows、Linux、macOS 的支持，不缩减平台范围。
- 保持既有服务运行方式：Windows 使用 LocalService 系统服务，Linux 使用 systemd 用户服务，macOS 使用 launchd 系统服务。
- CLI 配置操作与 Hub 服务可能由不同账号、在不同环境下执行。配置成功必须保证长期运行服务可读取配置和秘密文件，并能调用所配置的 `psql`，不能仅以 CLI 当前环境可连接为准。
- 来源故障不删除已归档数据；解除项目关联也不删除归档。
- Windows/Linux 尚无本次执行记录，不能据 macOS 上的结果宣称三平台验收通过。验收不要求在真实 VibeInsight 服务器造数，可使用合成事件覆盖同步场景。

## 设计决策

1. **来源访问**：由 Hub 服务调用外部 PostgreSQL 客户端 `psql`。其安装位置和可执行环境必须适配各平台现有服务账号，不能依赖 CLI 进程的临时环境。
2. **配置与凭据**：连接参数保存在 Hub 配置文件；密码保存在服务状态目录的专用秘密文件。服务运行账号可读取，其他未授权普通账号不可读取。CLI 输出、日志及对话数据库不得包含密码原值。
3. **有效配置替换**：仅在新配置验证成功后替换有效配置及凭据，避免失败的配置尝试破坏现有同步。
4. **同步状态**：进度保存在 Hub 数据库，批次归档与进度在同一事务中提交；重启后从已提交位置继续，并回查近期事件去重。新增可读项目的历史补齐不能只依赖来源的既有整体进度。
5. **待维护者决定**：
   - 来源配置、`psql` 路径设置及项目关联管理的具体 CLI 命令和参数。
   - 持续同步周期、失败重试间隔及近期事件回查窗口。
   - CLI/MCP 中来源、项目、原会话和消息位置的具体字段及编码形式，需保持旧客户端和旧原文引用兼容。

## 验收条件

1. 提交有效来源配置后，Hub 保存配置并自动同步；提交无效配置后，CLI 返回失败，原有效配置和凭据仍可支持同步。
2. CLI 与服务使用不同账号或环境时，配置后的 Hub 服务仍能调用 `psql`、读取凭据并访问来源；缺少服务运行条件时，不得将候选配置报告为验证成功。
3. Hub 重启后无需再次输入密码，能从已提交进度继续同步。
4. 来源已有多个可读项目时，各项目历史均可归档；随后新增会话和追加轮次均能被同步并检索。
5. 新增可读项目包含早于已有同步进度的历史时，该历史仍被完整补齐。
6. 来源故障期间，已有归档仍可检索和读取；恢复后，未成功归档的数据得到补齐，重复读取不产生重复记录。
7. 批次中断时，归档与进度同时提交或同时不提交；重启重试后无数据遗漏或重复。
8. 维护者可建立并解除两类项目关联：设备项目与 VibeInsight 项目、不同设备项目。关系从任一端查询均生效。
9. A 关联 B、B 关联 C 且 A 未直接关联 C 时，查询 A 包含 A、B，不因该关系链包含 C。
10. 解除关联后，项目查询不再通过该关系扩展；相关归档仍能通过全局查询和原文引用读取。
11. 本机归档具有可区分的项目归属，CLI/MCP 项目查询携带当前项目身份；同名项目不会被合并或混淆。
12. CLI/MCP 检索结果提供来源、项目、原会话和消息位置，能够据此读取准确原文；已有原文引用仍然可用。
13. Hub 不可用时沿用本机全局回退；旧客户端未携带项目身份时仍可执行全局查询。
14. 密码秘密文件对服务运行账号可读，对其他未授权普通账号不可读；CLI 输出、日志及对话数据库均不含密码原值。
15. 来源访问仅执行只读查询；同步行为不依赖无新增事件的正文改写检测。
16. Windows、Linux、macOS 均保持发行包支持及既有服务类型，并满足服务调用 `psql`、凭据访问和重启续传要求；缺少平台执行记录的项目明确标为待验证。
