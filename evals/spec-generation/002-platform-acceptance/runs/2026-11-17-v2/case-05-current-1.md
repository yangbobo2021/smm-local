# 规格：Hub 重启后自动恢复同步

本规格依据同目录下已确认的 [intent.md](intent.md)。支持的操作系统、服务类型、部署账号和凭据持久化方案仍需维护者决定；当前 macOS 开发环境不构成部署范围确认。

## 预期行为

1. 在已确认支持的部署环境中，完成后台运行配置后，机器重启应自动启动 Hub，并继续同步已配置的数据来源，无需用户手动运行原前台同步命令。
2. 重启后，Hub 应保留并使用已有来源配置、归档和同步进度，不要求重新配置来源或重新输入凭据。
3. 自动同步应从已保存的进度继续；重启和恢复同步不得导致已有数据重复导入。
4. 某个来源不可达时，Hub 应报告该来源的同步失败，保留已有归档及同步进度，已有归档仍可检索。
5. 不可达的来源恢复后，Hub 应自动重试并继续同步，无需用户重新配置来源或输入凭据；重试不得重复导入已归档的数据。

## 边界与约束

- 已知运行要求为 Python 3.11+。本规格不据此推定任何操作系统、系统服务机制或部署账号。
- 支持平台范围尚待确认，不得将本次变更默认为仅支持 macOS，也不得将 Windows 或 Linux 视为已确认支持的平台。
- README 示例路径、当前开发电脑及交互式终端运行经历，均不能作为后台部署范围或可用性的证明。
- 原前台同步命令通过环境变量取得凭据，其现有调用方式应保持兼容。后台运行所需的凭据持久化不得要求用户在每次重启后重新输入凭据。
- 自动启动和恢复同步不得清空已有归档、重置已有进度，或要求以重新导入替代恢复。
- 本次资料没有部署清单或其他平台的验证记录，因此本草稿不声明任何平台上的后台运行已经可用。

## 设计决策

以下事项须由维护者在实施前确认：

1. **部署范围与启动机制**：确定支持的操作系统及其版本范围、后台服务类型、部署账号，以及是否需要用户登录后才能启动。选择应满足机器重启后自动继续同步的意图。
2. **凭据持久化与读取方式**：确定首次配置时如何取得凭据、凭据保存位置、访问权限，以及后台部署账号如何在重启后读取凭据。原有环境变量入口须保持兼容。
3. **状态存储与访问**：确定后台服务如何定位并访问现有来源配置、归档和进度，避免因运行账号或工作目录变化而使用新的空状态。
4. **失败报告与重试策略**：确定同步失败的可查看入口、报告内容，以及自动重试的触发方式和间隔，使维护者能够识别失败来源，并在来源恢复后自动继续同步。

## 验收条件

1. 在维护者确认的每一种支持部署环境中，完成配置并重启机器后，Hub 自动启动并继续同步已配置来源，无需手动执行前台命令。
2. 重启前已存在的来源配置、归档和同步进度在重启后保持可用；恢复同步无需重新输入凭据。
3. 对已有归档的数据执行重启恢复和自动重试后，不产生重复导入；新增数据仍能正常归档。
4. 来源不可达时，可以通过已确认的报告入口识别该来源的同步失败；已有归档仍可检索，已保存进度不被清空或重置。
5. 来源恢复可达后，Hub 按已确认的重试策略自动恢复同步，无需用户重新配置来源或输入凭据。
6. 原前台同步命令仍可使用原有环境变量方式取得凭据并执行同步。
7. 部署范围、服务类型、部署账号、凭据持久化方式、状态访问方式及失败报告与重试策略均已获得维护者确认；未确认前，不得宣称对应后台部署行为已完成验收。
