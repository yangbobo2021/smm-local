# 规格：同分检索结果按会话 ID 稳定排序

本规格依据同目录下已确认的 [intent.md](intent.md)。现有材料足以确定本次排序行为，无待维护者决定事项。

## 预期行为

1. 当检索结果的数值分数相等时，按整数会话 ID 的数值升序排列，不受输入列表顺序影响。例如，同分的会话 ID 为 `10` 和 `2` 时，`2` 排在 `10` 前。
2. 当检索结果的分数不同时，保持现有按分数排序的行为。
3. CLI、MCP 和 Web 沿用共用纯函数，均呈现上述排序结果；Windows、Linux 和 macOS 具有相同排序语义。
4. 排序不改变结果字段或字段值，也不改变项目过滤规则。
5. 保持现有 limit 语义。同分结果的先后次序及其在截断边界上的取舍遵循会话 ID 数值升序；limit 的其他行为保持不变。

## 边界与约束

- 本次范围限于三平台共用纯函数的同分排序规则，不改变各入口的调用方式。
- 输入为已解码的 Python 数值分数和整数会话 ID；比较遵循三平台共同支持的 Python 数值比较语义。
- 空列表和单条结果保持原有行为。
- 分数和会话 ID 均相同的结果之间不新增排序键，保持现有行为。
- 纯函数继续不访问系统、文件、数据库、网络、时间或区域设置，不引入平台分支。
- 不改变运行时支持范围、依赖、安装或服务。
- 当前仅有 macOS 可用于本次验证，尚无 Windows、Linux 的本次执行记录。三平台一致性要求仍然适用，不将单平台验证表述为三平台实测通过。

## 验收条件

1. 给定两条同分、会话 ID 分别为 `10` 和 `2` 的结果，无论输入顺序如何，输出均为 `2`、`10`。
2. 给定多条同分且会话 ID 不同的结果，输出 ID 按数值升序排列；打乱输入后，输出顺序一致。
3. 给定不同分数的结果，其相对次序与现有按分数排序的行为一致。
4. 给定包含多个分数组的结果，各分数组之间保持现有次序，每个同分组内部按会话 ID 数值升序排列。
5. limit 截断落在同分组内部时，保留结果符合会话 ID 数值升序；返回数量及其他 limit 边界行为与现有语义一致。
6. 排序前后，保留结果的全部字段及字段值不变；项目过滤后的结果成员与现有规则一致。
7. 空列表、单条结果，以及分数和会话 ID 均相同的结果，保持现有行为。
8. CLI、MCP 和 Web 对相同输入与参数呈现一致的排序次序，均沿用共用纯函数。
9. Windows、Linux 和 macOS 的行为约定一致，共用函数不新增平台分支或外部环境依赖；验收记录明确区分实际执行的平台与尚未执行的平台。
