# 规格：明确来源回退命令的简体中文用途

意图依据：[已确认意图](intent.md)。

## 预期行为

1. 用户执行 `smm source --help` 时，`rollback` 子命令的简体中文用途显示为“将该插件来源的适配器切回上一版，保留已导入对话”，明确回退对象是适配器，已导入对话会被保留。
2. 用户执行 `smm source rollback --help` 时，用途说明同样显示“将该插件来源的适配器切回上一版，保留已导入对话”。
3. 两条帮助命令均无需提供来源或创建档案；打印帮助后以状态码 `0` 退出，不访问来源、不写档案、不启动服务。
4. 命令名、参数名称及含义、参数解析、退出行为和真实回退操作保持不变。

## 边界与约束

- 本次仅修改同一 Python 模块中的静态 argparse 简体中文帮助字符串，不修改其他帮助内容或功能逻辑。
- 本机端继续支持 Windows、Linux、macOS，不缩减或扩大现有支持范围。
- 三平台共用帮助字符串定义且无平台分支；命令解析、终端编码、输出组件、依赖和打包配置均不变。
- 原版本在已支持平台均可显示中文帮助，且没有针对本说明文本的渲染或编码缺陷报告。
- 项目现有回退功能测试继续保留；帮助说明变更不改变真实回退操作的既有承诺。

## 设计决策

沿用现有 argparse 帮助机制，仅替换两处入口所展示的用途文本，不增加配置或新的输入要求。

本次直接观察面是两条帮助输出、参数和退出行为。由于变更限于三平台共用且无平台分支的静态字符串，既有中文显示能力没有已知缺陷，也未改变任何平台相关输出环节，macOS 上的实际帮助输出验证结合变更范围审查，足以支撑本次改动验收。无需在 Windows、Linux 重复运行相同帮助用例；此依据不代表已在这两个平台实际运行通过，也不替代其既有支持承诺。

当前资料没有需要维护者补充决定的事项。

## 验收条件

1. 在 macOS 实际运行 `smm source --help`，无需来源配置或已有档案，输出中 `rollback` 的用途为“将该插件来源的适配器切回上一版，保留已导入对话”，中文完整可读，进程以状态码 `0` 退出。
2. 在相同环境和前提下实际运行 `smm source rollback --help`，用途说明为同一文本，中文完整可读，进程以状态码 `0` 退出。
3. 对上述两条帮助命令，确认均在创建档案对象前结束，不访问来源、不写档案、不启动服务。此项可由既有帮助控制流与本次仅修改字符串的差异审查共同确认。
4. 对照变更前后两条帮助输出，除指定用途文本及其引起的正常自动换行外，命令名、参数展示和其他帮助内容保持一致。
5. 变更审查确认修改仅涉及指定静态帮助字符串，没有修改参数定义、解析、退出或真实回退逻辑，也没有修改平台分支、编码、输出组件、依赖及打包配置；既有回退功能测试仍保留。
6. Windows、Linux 的本次覆盖依据为三平台共用定义及上述变更范围审查。macOS 的两条实际帮助输出证据和范围审查缺一不可；仅有包构建或字符串断言不足以判定本次交付通过。
