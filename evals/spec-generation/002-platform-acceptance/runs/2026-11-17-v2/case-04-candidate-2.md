# 规格：Hub 启动后自动同步已配置来源

本规格依据同目录下已确认的 [intent.md](intent.md) 及现有项目承诺。交付范围为 Linux systemd 用户服务；尚需维护者确认的生命周期决定见「设计决策」。

## 预期行为

1. 已配置来源的 Hub 随机器重启启动后，自动执行已有的一次同步操作，无需用户另行运行同步命令。同一自动同步行为也适用于该 systemd 用户服务的启动和重启。

2. 自动同步沿用 Hub 服务账号用户状态目录中的现有来源凭据及数据库进度，不要求重新配置凭据、迁移进度或修改配置格式。来源及凭据通过既有配置途径维护，本次不新增输入或配置项。

3. 同步成功后，新对话进入现有归档，可通过既有检索入口访问；原有归档和同步进度保持有效。

4. 启动同步失败时，报告可用于定位问题的失败原因，包括凭据无法读取等服务环境问题。失败不应阻止 Hub 提供既有归档的检索服务，已有客户端仍可通过既有 HTTPS 协议检索。

5. 失败后再次执行同步，或服务再次启动触发同步时，沿用数据库记录的进度与既有去重行为，不重复导入已经归档的消息。失败前已成功归档的消息同样适用。

## 边界与约束

- Hub 本次仅支持 Linux systemd 用户服务，不承诺 Windows 或 macOS 上的 Hub 运行方式。
- Windows、macOS、Linux 本机客户端继续通过既有 HTTPS 协议访问 Hub。本次不修改客户端程序、协议、API、CLI/MCP、同步算法或配置格式。
- 自动同步必须在相应 Linux 服务账号的权限和服务环境中读取现有状态目录，不得依赖交互式登录 shell 中才存在的环境或权限，也不得扩大凭据的访问权限。
- 本次不新增周期同步或失败后的定时重试机制。既有同步入口和行为保持兼容。
- 当前 macOS 开发环境只能提供共用逻辑验证，不能提供 Linux systemd 生命周期验证。现有材料没有本次 Linux 启动或重启后的通过证据。

## 设计决策

1. **生命周期接入。** 服务启动后调用既有的一次同步操作，复用其凭据读取、进度管理及去重能力。自动同步失败应与归档检索服务隔离，避免同步错误导致已有归档不可访问。

2. **服务账号环境。** 凭据定位和数据库访问必须在实际 systemd 用户服务环境下成立。交互式命令执行成功不能替代此项验证；需覆盖服务账号读取成功及读取失败两种状态。

3. **待维护者确认：机器重启后的用户服务启动条件。** 材料未说明是否要求用户尚未交互登录时即启动 Hub，以及现有部署是否已具备对应的用户服务启动条件。该决定影响部署前提和机器重启验收场景，实施前必须明确；不得以登录后手动启动服务替代机器重启后的自动启动验收。

4. **待维护者确认：失败报告入口。** 材料未说明现有同步错误的报告渠道。需确认沿用的具体入口，使维护者能够在无人值守启动失败后查看失败原因；报告不得泄露来源凭据。

## 验收条件

以下 Linux 场景均须在实际 Linux systemd 用户服务环境取得通过证据。缺少必要场景证据时，本次交付仍未完成；共用单测、包构建或 macOS 上的运行结果不能替代。

1. **机器重启后自动同步。** 已按确认的部署条件启用用户服务，服务账号状态目录中存在有效凭据和数据库进度，来源中存在尚未归档的新对话。机器重启后，在确认的登录条件下，Hub 自动启动并完成同步，无需手动执行同步命令；新对话可经既有 HTTPS 检索入口访问，原有归档仍可检索。

2. **服务启动及重启。** 在上述有效配置状态下，分别启动和重启 systemd 用户服务，均自动触发已有的一次同步操作。存在新增对话时能够归档；来源内容未变化时，不新增重复消息。此项与机器重启场景共用凭据、进度及检索结果判据。

3. **沿用进度。** 在 Linux 服务账号已有归档和同步进度、来源包含新增内容的状态下启动服务。自动同步沿用已有进度完成处理，历史归档保持有效，新增内容可检索，已归档消息不重复导入。

4. **凭据读取失败。** 在已有归档可检索、服务账号无法读取来源凭据的状态下启动服务。自动同步通过已确认的报告入口给出可定位的失败原因，不泄露凭据；Hub 继续运行，已有归档仍可通过 HTTPS 检索。

5. **同步失败与重试。** 在实际 Linux 用户服务环境中，使同步在部分消息已成功归档后失败。失败原因可查看，已有归档及本次已成功归档内容仍可检索。恢复失败条件后，通过既有同步入口重试或重启服务，剩余内容成功归档，失败前已归档的消息不重复导入。既有入口重试与服务重启触发须分别取得证据，可复用同一组结果判据。

6. **客户端兼容边界。** 在 Linux 上验证既有 HTTPS 检索入口在同步成功及失败状态下均符合上述结果。由于客户端程序与协议均未改变，本次不要求 Windows、macOS、Linux 客户端重复完整测试；共用接口兼容验证仅证明此次服务端改动的协议边界，不宣称各客户端已实际运行通过。

7. **共用逻辑验证的适用范围。** 可在当前 macOS 环境验证生命周期调用的共用逻辑、错误处理及去重相关回归。其结果仅覆盖共用代码行为，不覆盖 Linux 服务账号权限、systemd 环境、机器重启启动条件及实际服务生命周期。
