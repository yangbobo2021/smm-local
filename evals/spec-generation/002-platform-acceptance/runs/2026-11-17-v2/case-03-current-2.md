# 规格：同分检索结果按数值会话 ID 稳定排序

依据：[已确认意图](intent.md)。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列，不受输入列表顺序影响。例如，会话 ID `2` 排在 `10` 之前。
2. 检索结果分数不同时，保持现有的分数排序规则。
3. CLI、MCP 和 Web 沿用共用排序函数，均获得上述排序结果。
4. Windows、Linux 和 macOS 采用相同的排序语义。
5. 结果字段、项目过滤及 limit 的现有语义保持不变。limit 限定的结果应符合新的同分排序规则。

## 边界与约束

- 适用对象为已解码的 Python 数值分数和整数会话 ID，不新增字符串解析或类型转换规则。
- 分数相同依据受支持运行时的 Python 数值比较语义判定，不新增近似相等或舍入规则。
- 分数和会话 ID 均相同的结果，本次不新增进一步的排序键，也不承诺其相互顺序独立于输入顺序。
- 空列表仍返回空列表；单条结果的内容保持不变。
- 排序不得修改结果字段或增删结果；现有项目过滤和 limit 导致的排除或截断除外。
- 共用函数保持纯函数性质，不引入系统、文件、数据库、网络、时间或区域设置依赖，也不新增平台分支。
- 不更改支持的运行时范围、依赖、安装或服务。
- 当前仅具备 macOS 上使用合成输入的验证条件，没有 Windows 或 Linux 的本次执行记录；不得将单平台验证描述为三平台实测通过。

## 设计决策

沿用三平台及三个入口共用的纯函数，以现有分数排序规则为主排序依据，以数值会话 ID 升序作为同分时的排序依据。共享实现与一致的 Python 数值比较语义支撑跨平台行为一致性，无需新增入口或平台专属排序层。

待维护者决定：交付验收是否要求补充 Windows、Linux 的执行记录。该决定不改变三平台必须具有相同排序语义的要求。

## 验收条件

1. 对同分且会话 ID 为 `10`、`2`、`1` 的结果，输出顺序为 `1`、`2`、`10`。
2. 对分数与会话 ID 组合相同、输入顺序不同的结果列表，只要排序键能够区分各项，输出顺序一致。
3. 对不同分数的结果，其相对顺序与现有分数排序规则一致。
4. 对包含多个分数组的结果，每个同分组内部按数值会话 ID 升序排列，组间顺序保持现有规则。
5. 排序前后，每条保留结果的字段和值一致；项目过滤的纳入与排除规则保持不变。
6. 启用 limit 后，返回数量及其边界处理保持现有语义；同分结果在截断边界处的取舍符合会话 ID 升序规则。
7. 空列表输出为空列表，单条结果的内容不变。
8. CLI、MCP 和 Web 对等价输入获得相同的排序结果，且继续使用共用函数。
9. Windows、Linux 和 macOS 的排序行为均符合上述条件；验收记录明确区分实际执行结果与基于共享实现及运行时语义的分析结论。
