# 规格：Hub 自动归档 VibeInsight 历史与项目关联检索

以同目录下已确认的 [intent.md](intent.md) 为依据。尚需维护者决定的事项列于“设计决策”。

## 预期行为

### 来源配置与服务恢复

1. 维护者通过 Hub CLI 配置 VibeInsight 来源连接与凭据。CLI 验证新配置成功后才保存并替换有效配置；验证失败时保留原有效配置和凭据。
2. Hub 长期运行服务能够使用保存的配置调用外部 PostgreSQL 客户端 `psql`，对 VibeInsight 执行只读查询。配置不能仅因 CLI 所在账号或环境可以连接，就被视为服务可用。
3. Hub 重启后自动读取已保存的连接参数和凭据，继续同步，无需重新输入密码。
4. 来源连接失败或凭据失效时，已归档内容仍可通过现有 CLI/MCP 查询和读取。来源恢复后，Hub 自动重试尚未成功归档的数据。

### 自动同步与归档

1. 配置生效后，Hub 自动发现并归档该来源当前可读取的全部项目历史。
2. 持续同步期间，Hub 自动归档新增会话，以及已有会话通过新增事件追加的轮次。
3. 来源后来新增可读取项目时，Hub 补齐该项目的全部可读历史，即使其事件早于已有同步进度，也不得遗漏。
4. 每个同步批次的归档数据与同步进度一同提交。失败不得产生“进度已推进但对应归档未保存”的状态。
5. 重启后，Hub 从已提交位置继续，并回查近期事件。重复读取、回查和失败重试不得产生重复归档。
6. 已归档历史不因来源暂时不可用或项目解除关联而删除。

### 项目关联与检索范围

1. Hub 维护者统一管理项目关联，可关联设备项目与 VibeInsight 项目，也可关联不同设备项目。
2. 项目关联双向生效。以任一端项目发起项目查询时，范围包含该项目及其直接关联项目。
3. 关联只扩展一层。例如 A 与 B 关联、B 与 C 关联时，从 A 查询不得仅因该关系链纳入 C；从 B 查询则包含 A 和 C。
4. 本机端补传项目归属，CLI/MCP 发起项目查询时携带当前项目身份。不同设备或来源中的同名项目保持可区分，不得仅凭名称合并。
5. 解除关联后，后续项目查询不再因该关联扩大范围；已归档内容仍可通过适用的全局查询或原文引用访问。

### 查询、原文定位与回退

1. 用户通过现有 CLI/MCP 检索已归档的设备对话和 VibeInsight 对话，并读取对应原文。
2. CLI/MCP 返回足以区分来源、项目、原会话和消息位置的信息，使调用方能够精确读取对应原文。
3. 本次变更前已支持的原文引用继续可用，不因新增来源、项目身份或关联关系而失效。
4. Hub 不可用时，沿用现有本机全局回退行为。
5. 未携带项目身份的旧客户端继续支持全局查询，不得被隐式限制到某个项目。

## 边界与约束

- 首版面向单用户，不引入多用户权限或租户隔离要求。
- 同步范围为 VibeInsight 授权连接当前可读取的项目及历史，不读取授权范围之外的数据。
- 首版仅保证发现新增会话事件和追加轮次；没有新增事件的历史正文原地改写不在发现范围内。
- 对 VibeInsight 仅执行只读查询，不要求在真实来源服务器创建测试数据。
- Hub 和本机发行包继续支持 Windows、Linux、macOS，不缩减已有部署平台范围。
- 保持现有服务类型：Windows 使用 LocalService 系统服务，Linux 使用 systemd 用户服务，macOS 使用 launchd 系统服务。
- CLI 配置账号与 Hub 服务账号可能不同，二者的安装路径和可执行环境也可能不同。`psql` 的定位、配置验证及凭据访问必须适用于实际服务环境。
- 连接参数保存在 Hub 配置文件；密码保存在服务状态目录的专用秘密文件。运行账号必须可读取密码，其他未授权普通账号不得读取。
- CLI 输出、日志和对话数据库不得包含密码原值；失败诊断同样遵守该约束。
- 当前只有 macOS 开发条件已知，Windows/Linux 尚无本次执行记录。平台兼容要求不因缺少记录而视为已验收。

## 设计决策

已选定的设计：

- 使用 Hub 服务调用外部 `psql` 读取来源，不改变现有服务运行方式。
- 将连接参数与密码分开保存，并在新配置验证成功后替换有效配置，以支持服务重启和防止无效配置覆盖。
- 将同步进度保存在 Hub 数据库，并与批次归档原子提交；结合近期事件回查与去重，支持中断恢复和重复读取。
- 项目查询使用项目身份，关联关系由 Hub 维护；名称不作为跨设备、跨来源项目合并的唯一依据。

尚需维护者确认：

- 各平台如何提供或定位服务可调用的 `psql`，以及 CLI 如何验证实际服务账号对客户端、配置和秘密文件的访问能力。
- 自动同步频率、来源失败后的重试间隔，以及近期事件回查窗口。
- 来源事件的稳定标识、排序与分页依据，以及去重键；应保证跨项目补齐历史和重启恢复不会遗漏或重复。
- 项目身份、关联管理命令及 CLI/MCP 来源定位字段的具体接口形式，以及旧原文引用的兼容映射方式。

上述决定不得削弱本规格已确认的行为与平台范围。

## 验收条件

1. 使用有效来源配置后，Hub 自动归档所有当前可读项目的历史；各项目的会话与消息均可检索并读取。
2. 来源新增会话和向旧会话追加轮次后，Hub 在后续同步中归档对应内容，原有归档仍可访问。
3. 已有同步进度建立后，新增一个可读项目，其历史事件早于该进度；该项目历史仍被完整补齐。
4. 对同一批事件重复读取、回查或重试后，每条来源消息仅有一份归档，不重复出现在查询结果中。
5. 批次失败时，归档与进度均不发生部分提交；重启后能够补齐该批次且不重复已提交数据。
6. 保存有效配置后重启 Hub 服务，无需再次输入密码即可继续同步；CLI 与服务账号或环境不同时也满足该条件。
7. 尝试保存无效连接或凭据后，原有效配置仍可使用；错误信息不泄露密码。
8. 来源不可用期间，已有归档可检索和读取；来源恢复后，失败期间未成功归档的数据自动补齐。
9. Windows、Linux、macOS 均保持既有服务类型和发行包支持；实际服务能够调用 `psql`、读取配置及秘密文件。
10. 各平台秘密文件均允许运行账号读取，并阻止其他未授权普通账号读取；CLI 输出、日志及对话数据库中均无密码原值。
11. 设备项目与 VibeInsight 项目、不同设备项目均可建立关联，并从任一端查询到另一端内容。
12. 在仅有 A—B、B—C 关联时，A 的项目查询包含 A、B，不包含 C；B 的项目查询包含 A、B、C。
13. 解除 A—B 关联后，项目查询范围随之更新；对应归档未删除，原文引用继续可用。
14. 不同设备或来源的同名项目可独立识别；携带当前项目身份的 CLI/MCP 查询只按该身份及直接关联确定范围。
15. CLI/MCP 检索结果提供可区分的来源、项目、原会话和消息位置，并能据此读取准确对应的原文；旧原文引用继续有效。
16. 旧客户端未携带项目身份时仍执行全局查询；Hub 不可用时，新旧客户端均沿用现有本机全局回退行为。
