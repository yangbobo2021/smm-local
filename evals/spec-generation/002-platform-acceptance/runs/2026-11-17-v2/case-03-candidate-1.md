# 规格：同分检索结果按数值会话 ID 稳定排序

依据同目录下已确认的 [intent.md](intent.md)。本次仅调整同分结果的次级排序规则。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列。例如，同分会话 ID 为 `10`、`2` 时，输出顺序为 `2`、`10`。
2. 对同一组结果打乱输入顺序后，同分且会话 ID 不同的结果仍输出相同顺序。
3. 不同分数之间沿用现有排序规则；会话 ID 不得改变不同分数结果的相对顺序。
4. 项目过滤规则、结果字段及其值、limit 的含义与既有边界行为保持不变。排序规则应作用于最终截取结果的选择：当 limit 截断同分结果时，按会话 ID 数值升序确定入选顺序。
5. CLI、MCP 和 Web 均通过现有共用函数获得上述排序语义，用户无需提供新增配置或输入。

## 边界与约束

- Windows、Linux、macOS 均继续受支持，并承诺相同的稳定排序语义。
- 本次变更限于三平台共用的纯排序函数。输入为已解码的 Python 数值分数和整数会话 ID，不新增输入解析或类型转换规则。
- 同分且会话 ID 相同的条目不新增排序依据，沿用现有行为。
- 空列表、单条结果及已有 limit 边界行为不得发生回归。
- 不改变运行时支持范围、依赖、安装方式或服务；CLI、MCP 和 Web 的调用方式保持不变。
- 材料未说明特殊数值分数的既有处理规则，本次不另行定义或改变其语义；如实施需要改变这些规则，须由维护者另行确认。

## 设计决策

在共用纯函数中增加会话 ID 数值升序的同分排序依据，保留现有分数排序规则。三个入口不引入独立排序层，以保持语义一致。

本次改动不依赖操作系统、文件、数据库、网络、时间或区域设置，也没有平台分支。三平台使用相同受支持的 Python 数值比较语义，因此在 macOS 上对共用函数进行合成输入验证，足以覆盖本次排序逻辑变更；不要求 Windows、Linux 重复执行相同用例。

这一充分性判断仅适用于上述纯函数及既有调用路径。macOS 验证不能表述为 Windows、Linux 已实际运行通过。若实施引入平台分支、外部依赖或入口专有排序逻辑，必须重新明确相应环境的验收覆盖，不能沿用本判断。

## 验收条件

以下行为用例均须在 macOS 上针对实际修改后的共用纯函数取得通过证据；其共同前提为使用受支持的 Python 运行时，输入为已解码的数值分数及整数会话 ID。

1. **同分数值排序**：输入同分结果，会话 ID 包含 `10`、`2`、`1`；输出 ID 顺序为 `1`、`2`、`10`，结果字段及其值保持不变。
2. **输入顺序无关**：对同分且会话 ID 不同的同一组结果使用多个不同输入排列；各次输出顺序完全一致，并符合 ID 数值升序。
3. **不同分数兼容**：输入包含多个分数组及各组内多个会话；分数组之间与现有排序一致，各同分组内按 ID 数值升序排列。
4. **limit 兼容**：使用会截断同分组的既有有效 limit，返回数量符合原语义，入选结果为完整排序结果的对应前缀；同时验证项目已有的 limit 边界行为保持不变。
5. **基础边界兼容**：空列表仍返回空列表；单条结果保持不变；同分且 ID 相同的条目沿用现有行为，不丢失、不新增或改写结果。

另须通过代码审阅确认：

6. 项目过滤规则和结果字段未被修改，CLI、MCP、Web 仍调用同一纯函数，且未增加各自的排序层。
7. 实现仍无平台分支或外部环境依赖，运行时、依赖、安装和服务范围未改变，满足共用逻辑验证可覆盖三平台排序承诺的依据。

全部必要条件通过后，本次交付可判定完成。验收记录应明确实际执行平台为 macOS，Windows、Linux 的排序承诺由共用纯函数及相同数值比较语义支撑，并无本次实际执行记录。
