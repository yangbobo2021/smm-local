# 规格：同分检索结果按数值会话 ID 稳定排序

本规格依据同目录下已确认的 [intent.md](intent.md) 及项目现有承诺起草。

## 预期行为

1. SMM 返回检索结果时，分数相同的结果按整数会话 ID 的数值升序排列。例如，会话 ID 为 `10`、`2` 的两条同分结果，无论输入顺序如何，均先返回 `2`，再返回 `10`。
2. 分数不同的结果保持现有排序规则；会话 ID 仅用于同分结果的次级排序。
3. 对同一组结果打乱输入顺序后，同分且会话 ID 不同的结果仍得到相同的相对顺序。
4. 排序不修改结果字段或字段值，不增删结果；项目过滤与 `limit` 的现有语义保持不变。`limit` 截取涉及同分结果时，入选结果及顺序应符合会话 ID 数值升序规则。
5. CLI、MCP 和 Web 沿用共用函数，均呈现上述排序语义，不要求调用方提供新增参数或配置。

## 边界与约束

- 现有客户端继续支持 Windows、Linux、macOS，三平台承诺相同的稳定排序语义。
- 本次改动限于三平台共用的纯排序函数。输入为已解码的 Python 数值分数和整数会话 ID；不新增输入解析、类型转换或非法输入处理规则。
- 同分按现有受支持的 Python 数值比较语义判定，不引入近似相等容差或分数归一化。
- 分数与会话 ID 均相同的结果不新增排序键，其相对顺序沿用现有行为。
- 不改变运行时支持范围、依赖、安装方式、服务或各入口调用方式。项目资料未进一步列举现有部署方式，本次不新增或缩减相关承诺。

## 设计决策

在共用纯函数中保留现有分数主排序规则，增加数值会话 ID 升序作为同分时的次级排序规则。CLI、MCP 和 Web 无独立排序层，因此无需分别设计排序实现。

本次验收可使用 macOS 上的合成输入验证共用逻辑，无需三平台重复执行完整测试。依据是：函数不访问系统、文件、数据库、网络、时间或区域设置，没有平台分支，且三平台使用相同受支持的 Python 数值比较语义。本次也不涉及安装、服务或进程生命周期差异。

该充分性判断仅覆盖本次纯函数排序变更，不代表 Windows、Linux 或各入口已取得本次实际运行证据。若实施引入平台分支、外部依赖或入口专属排序，必须重新明确受影响环境的验收覆盖，不能沿用上述判断。

## 验收条件

以下条件均在 macOS 上，以已解码的 Python 数值分数、整数会话 ID 和合成结果记录验证三平台共用纯函数；它们共同构成本次变更的必要行为证据：

1. **同分数值排序**：输入多条同分结果，包含会话 ID `10`、`2`、`1`；输出顺序为 `1`、`2`、`10`，不采用字符串排序。
2. **输入顺序无关**：对同一组会话 ID 不同的同分结果使用不同输入排列，输出的会话 ID 顺序完全一致，且为数值升序。
3. **不同分数兼容**：输入包含多个不同分数及组内同分结果；不同分数组之间的顺序与变更前规则一致，各同分组内按会话 ID 升序排列。
4. **结果与过滤兼容**：使用可区分项目和字段值的结果记录，确认项目过滤仍遵循现有规则；输出结果字段及值保持原样，除既有过滤和 `limit` 外不增删记录。
5. **limit 边界**：在截取位置落于同分组内的输入上，使用现有有效 `limit` 值；返回数量符合现有语义，入选记录及顺序与先按本规格排序再按既有规则截取的结果一致。其余现有 `limit` 边界行为保持兼容。
6. **空输入与单条输入**：空输入仍返回空列表；单条结果输入返回原结果，字段和值不变。
7. **入口共用关系**：审阅确认 CLI、MCP 和 Web 继续调用该共用函数，未新增额外排序层或平台专属实现。该结构证据与上述函数验证共同覆盖三个入口的本次排序变更。

验收记录须明确实际执行环境为 macOS，并记录上述条件的通过结果。不得将其表述为 Windows、Linux 已实际运行通过；在上述共用逻辑及环境无关前提成立时，缺少这两个平台的本次执行记录不构成交付阻塞。
