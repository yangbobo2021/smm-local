# 规格：Hub 自动同步 VibeInsight 历史与项目关联检索

本规格依据同目录下已确认的 [intent.md](intent.md)。尚需维护者决定的事项列于“设计决策”。

## 预期行为

### 来源配置与恢复

1. 维护者通过 Hub CLI 提交 VibeInsight 来源连接参数和凭据。CLI 验证连接及只读查询能力，成功后保存为有效配置；验证失败时报告原因，保留原有效配置。
2. 保存成功的配置可由长期运行的 Hub 服务读取，即使 CLI 与服务使用不同账号或环境。Hub 重启后自动恢复同步，无需再次输入密码。
3. 来源连接失败或凭据失效时，已归档内容仍可通过现有 CLI/MCP 查询和读取。来源恢复后，Hub 自动重试尚未成功归档的数据。

### 自动同步

1. Hub 自动同步 VibeInsight 对该连接可读取的全部项目历史，无需逐项目手动启动。
2. 完成历史同步后，Hub 持续同步新增会话事件以及旧会话追加的轮次。
3. 来源后来新增可读项目时，Hub 补齐该项目的全部可读历史，包括早于其他项目已有同步进度的数据。
4. 重复读取近期事件、失败重试或服务重启，不产生重复归档。
5. 每批归档内容与对应同步进度共同提交。批次未成功提交时，不将其视为已同步；重启后从已提交位置继续，并回查近期事件去重。

### 项目归属与关联

1. 本机端补传对话的项目归属；CLI/MCP 发起项目查询时携带当前项目身份。
2. Hub 维护者统一管理项目关联，可连接设备项目与 VibeInsight 项目，也可连接不同设备的项目。
3. 项目关联双向生效。查询某项目时，包含该项目及其直接关联项目的内容，只扩展一层，不沿关联关系继续传递。
4. 解除关联后，后续项目查询不再通过该关系扩展，但不删除已经归档的内容。
5. 项目身份不能仅由名称决定；同名项目仍可区分。补传项目归属或调整关联后，已有原文引用仍可读取其原先指向的内容。

### 检索、原文读取与回退

1. 用户通过现有 CLI/MCP 检索同步归档，并按返回的定位信息读取对应原文。
2. CLI/MCP 返回来源、项目、原会话及消息位置，足以区分不同来源或项目中的同名、同标识内容，并精确定位对应原文。
3. Hub 不可用时，沿用现有本机全局回退行为。
4. 未携带项目身份的旧客户端继续使用全局查询，不因新增项目查询能力而失效。

## 边界与约束

- 首版面向单用户，仅处理新增会话事件和追加轮次。不要求发现没有新增事件的历史正文原地改写。
- VibeInsight 仅接受只读查询，不对来源执行写入或要求在真实服务器造数。
- 保持 Hub 和本机发行包对 Windows、Linux、macOS 的支持，不因当前开发电脑为 macOS 而缩减范围。
- 保持既有服务运行方式：Windows 使用 LocalService 系统服务，Linux 使用 systemd 用户服务，macOS 使用 launchd 系统服务。
- 来源查询由 Hub 服务调用外部 PostgreSQL 客户端 `psql`。可执行文件及其运行环境必须对实际服务账号有效，不能仅依赖配置 CLI 的交互式环境。
- 连接参数保存在 Hub 配置文件；密码保存在服务状态目录的专用秘密文件。服务运行账号可读取，其他未授权普通账号不可读取。
- CLI 输出、日志和对话数据库不得包含密码原值。
- 当前仅具备 macOS 开发与验证环境；尚无本次 Windows/Linux 执行记录，不能据此声称已完成三平台验证。具体实施与验证安排写入 plan.md。

## 设计决策

### 已选定的设计

- 使用外部 `psql` 执行来源只读查询，保持现有服务类型。配置验证必须覆盖实际服务账号所需的执行环境和秘密读取能力，避免出现 CLI 验证成功但服务无法运行的配置。
- 验证新配置成功后才替换有效配置；失败不得使原连接参数与密码组合失效。
- 同步进度存于 Hub 数据库，与批次归档共同提交；通过近期事件回查和去重支持重启恢复与失败重试。
- 项目身份、来源身份及原文定位信息需保持稳定且可区分，保证同名项目与旧原文引用的兼容性。

### 仍需维护者决定

- 来源配置、状态查看及项目关联管理的具体 CLI 命令、参数与输出格式。
- 三个平台下服务状态目录、秘密文件权限设置，以及 CLI 向服务配置交接所需的权限处理方式。
- `psql` 的定位或显式配置方式，以及缺失、不可执行时的诊断形式。
- 自动同步、可读项目发现和失败重试的周期，以及近期事件回查范围。
- CLI/MCP 中来源、项目、原会话和消息位置的具体字段与兼容表示。

上述决定不得改变本规格已确认的行为与平台范围。

## 验收条件

1. 提交有效来源配置后，Hub 服务可执行只读查询并保存配置；提交无效配置后，原有效配置仍可用于同步，且错误可诊断。
2. CLI 与服务账号或环境不同时，保存成功的配置仍可被服务使用；重启 Hub 后无需重新输入密码即可继续同步。
3. 服务账号可读取秘密文件，未授权普通账号不能读取；CLI 输出、日志和对话数据库中不存在密码原值。
4. 来源包含多个可读项目时，其历史均被自动归档；新增会话及旧会话追加轮次随后可通过 CLI/MCP 检索和读取。
5. 新增可读项目包含早于现有进度的历史时，该历史仍完整补齐，不被已有进度跳过。
6. 重复读取相同事件、失败重试及重启回查后，同一来源内容不出现重复归档。
7. 批次提交前中断时，归档与进度均不部分生效；批次提交后重启时，已提交内容保持可用，未成功内容继续同步。
8. 来源不可用期间，已归档内容仍可查询和读取；来源恢复后，遗漏数据自动补齐。
9. 对关联 A—B、B—C，从 A 查询可包含 B，但不能仅经 B 包含 C；从 B 查询可包含其直接关联的 A 和 C。设备与来源项目、不同设备项目均满足此规则。
10. 解除 A—B 后，两者不再通过该关系相互扩展查询；解除前已归档内容仍可通过其自身项目或原文引用访问。
11. 同名项目可独立区分；本机端补传项目归属后，项目查询使用对应身份，已有原文引用仍指向原内容。
12. CLI/MCP 检索结果包含来源、项目、原会话及消息位置；使用这些定位信息可精确读取对应原文。
13. Hub 不可用时触发现有本机全局回退；旧客户端不携带项目身份时仍能进行全局查询。
14. Windows、Linux、macOS 均保持发行与既有服务方式支持；各平台实际服务账号能够调用 `psql`、读取有效配置并在重启后恢复同步。缺少执行证据的平台应标记为待验证，不能记为验收通过。
15. 验收不以发现无新增事件的历史正文原地改写为通过条件，也不要求修改真实 VibeInsight 数据来构造样本。
