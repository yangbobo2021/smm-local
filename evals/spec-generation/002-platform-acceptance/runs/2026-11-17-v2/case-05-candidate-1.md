# 规格：Hub 重启后自动恢复同步

依据：[已确认意图](intent.md)。

## 预期行为

1. 已配置数据来源且已完成后台运行配置后，机器重启应自动启动 Hub，并继续同步这些来源，无需用户打开交互式终端、手动执行同步命令或重新输入凭据。自动启动发生在系统启动阶段还是用户登录后，须由维护者确认。

2. 后台运行应保留并使用现有归档、来源配置和同步进度。重启后的同步不得清空归档、重置进度或从头重复导入已归档的数据。

3. 用户应能完成后台运行所需的凭据持久化配置。该入口须说明所需凭据的含义、对应来源、获取途径、保存范围及后台运行账号如何访问。现有资料未提供具体来源的凭据要求，也未确定持久化方式，因此这些内容仍需确认；不能要求用户在每次重启后重新提供凭据。

4. 来源不可达时，Hub 应保留已有归档及有效同步进度，使已有内容仍可通过既有检索入口检索，并通过确定的状态或诊断入口报告同步失败。单次来源访问失败不得导致归档被删除或进度被错误推进。

5. 来源恢复可达后，Hub 应自动重试并继续同步，无需重新配置来源或凭据。失败、重试及机器重启均不得导致重复导入。重试时机、失败状态的展示入口及恢复后的状态表达须在实施前确认。

## 边界与约束

- 运行要求沿用 Python 3.11+。该要求不代表已支持任何特定操作系统或后台服务方式。
- 本次后台组件的操作系统、服务类型、运行账号及部署方式尚未确定。当前 macOS 开发电脑和 README 示例路径均不能作为部署范围依据。
- 不默认仅支持 macOS，也不默认新增 Windows 或 Linux 支持。维护者须确认本次交付的平台与运行方式；该决定直接影响自动启动、凭据访问、文件权限、检索可用性及验收环境。
- 原前台命令通过环境变量取得凭据的使用方式应保持兼容。新增持久化与后台运行配置不得破坏原入口。
- 归档、来源配置和进度须在选定后台账号及运行方式下持续可用。不得依赖交互式终端继承的环境变量、工作目录或临时进程状态才能恢复同步。
- 本次未确认新增来源类型、改变既有检索语义或扩大原有数据同步范围。

## 设计决策

以下事项缺少确认依据，须在实施前由维护者确定并补入本规格：

| 待确认事项 | 必须明确的内容及影响 |
| --- | --- |
| 部署支持范围 | 支持的操作系统及运行方式；决定必须取得实际运行证据的环境 |
| 自动启动生命周期 | 系统启动或用户登录后启动、是否要求无人登录时运行；决定重启验收的动作前状态与通过标准 |
| 后台运行账号 | 账号身份、创建或选用方式，以及访问来源、凭据、归档和进度所需权限 |
| 凭据持久化 | 配置入口、各来源所需值及获取途径、保存和读取方式、账号访问边界；须保证重启后无需再次输入，且诊断输出不泄露凭据 |
| 数据位置与接续 | 现有配置、归档和进度的定位方式；若需迁移，须明确迁移入口和保留规则 |
| 检索与失败报告 | 后台运行时既有检索入口如何使用、失败状态在哪里查看，以及恢复后如何确认同步已继续 |
| 重试与重复防护 | 重试时机、重启及失败中断后的进度接续规则，确保恢复后不重复导入 |

服务账号可能无法读取交互式用户的环境变量、凭据存储或归档文件；后台进程的生命周期也可能不同于前台命令。因此，交互式终端运行成功不能证明后台自动恢复成立。相关行为须在最终选定的真实服务环境中验收。

## 验收条件

1. **范围与配置完整性**  
   上述待确认事项均已有维护者决定，并已补入规格。用户能够依据确定的配置入口和说明完成来源、凭据、数据位置及后台运行配置，无需实施者临时补充关键参数或权限知识。

2. **实际重启后自动接续**  
   在每个确认支持的操作系统与后台运行方式中，以选定账号配置来源和持久化凭据，预先形成可检索归档及同步进度，再实际重启机器。按已确认的启动或登录条件，Hub 自动运行；无需打开终端、手动启动或重新输入凭据，即可继续导入新增数据。原归档仍可检索，进度未被重置，已导入数据无重复。

3. **来源故障期间保留能力**  
   在第 2 条规定的实际后台环境与账号下，使已配置来源不可达，并覆盖来源在重启前已不可达、运行中变为不可达两种状态。Hub 均通过确定的诊断入口报告失败；已有归档仍能通过既有入口检索，数据未丢失，有效进度未被错误推进。

4. **恢复后自动重试**  
   在第 3 条的故障状态下恢复来源可达，并提供可识别的新增数据。Hub 在确定的重试机制下自动继续同步，无需重新配置或输入凭据；新增数据完整导入，已有数据及重试涉及的数据均无重复，状态入口能够确认恢复结果。

5. **同步中断后的接续**  
   在各确认支持的实际后台环境中，于同步尚未完成时重启机器。自动恢复后，Hub 能完成该批数据的同步，归档完整、无重复，进度与已完成的同步结果一致。

6. **凭据与文件访问**  
   第 2 至第 5 条均须由选定后台账号实际读取持久化凭据及现有数据完成，不得以交互式终端注入凭据替代。验收同时确认诊断输出不暴露凭据，归档与进度能够持续读写。

7. **前台兼容性**  
   原前台命令仍可通过原环境变量方式取得凭据并完成同步，既有归档检索行为保持兼容。共用逻辑测试可验证进度接续、重复防护及数据保留规则，但不能替代上述真实后台环境、账号和重启证据。

当前材料没有后台运行或实际重启验证记录。缺少已确认支持环境的必需证据时，本次交付不得判定通过。不同环境可复用上述行为判据；具体机器、命令、实施位置、步骤及 CI 配置写入 plan.md。
