# 规格：同分检索结果按会话 ID 稳定排序

依据：[已确认意图](./intent.md)。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列。例如，会话 ID 为 `2` 和 `10` 的同分结果始终按 `2、10` 排列，不受输入列表顺序影响。
2. 分数不同时，沿用现有分数排序规则；本次仅增加同分时的会话 ID 排序规则。
3. CLI、MCP 和 Web 均通过现有共用函数获得上述排序结果，无需用户提供新增参数或配置。
4. 结果字段、项目过滤规则及 limit 语义保持不变。同分结果跨越 limit 截断边界时，入选结果应符合会话 ID 升序规则，不能由输入顺序决定。

## 边界与约束

- Windows、Linux、macOS 客户端均须满足相同的稳定排序语义，不缩减现有平台支持范围。
- 改动限于三平台共用的纯排序函数。输入为已解码的 Python 数值分数和整数会话 ID；不新增字符串解析、ID 转换或输入校验要求。
- 纯函数不访问系统、文件、数据库、网络、时间或区域设置，没有平台分支。
- 不变更 Python 运行时支持范围、依赖、安装方式或服务运行方式。
- 同分且会话 ID 也相同的记录，不新增其他排序键或去重规则，沿用现有行为。
- 空列表、单条结果及现有 limit 边界行为保持兼容。

## 设计决策

使用现有分数排序规则作为主排序规则，数值会话 ID 升序作为同分时的次排序规则。排序关系须在决定 limit 入选结果前生效，避免先截断导致同分结果仍随输入顺序变化。

本次可在 macOS 使用合成输入验证共用逻辑，无需为 Windows、Linux 重复执行整套测试。依据是三平台使用相同的受支持 Python 数值比较语义，函数无平台分支或外部环境依赖，且 CLI、MCP、Web 均无额外排序层。

该验证仅支撑本次纯函数排序变更，不代表 Windows、Linux 已实际运行通过，也不覆盖安装、服务或其他平台集成行为。若实施引入平台分支、外部依赖或入口专属排序，则上述覆盖依据失效，须先修订规格中的验收范围。

现有资料足以确定本次行为与验收范围，无新增环境决定待维护者确认。

## 验收条件

以下行为用例均须在 macOS 上针对实际共用函数取得通过证据。合成输入使用符合现有输入契约的 Python 数值分数和整数会话 ID；各用例独立判定。

1. **同分排序**：输入至少包含会话 ID 为 `10、2、1` 的同分结果，输出顺序为 `1、2、10`，证明采用数值升序。
2. **输入顺序无关**：对分数相同、会话 ID 各不相同的同一组记录，以不同排列输入，输出的会话 ID 序列完全一致。
3. **不同分数兼容**：输入混合不同分数及同分记录，输出的分数组间顺序符合现有规则，每个同分组内按会话 ID 升序排列。
4. **limit 截断**：使同分组跨越有效 limit 的截断边界，改变输入排列后，返回条数仍符合原有 limit 语义，入选记录和返回顺序均一致，且同分记录优先保留较小的会话 ID。
5. **现有行为兼容**：空列表、单条结果、无同分结果及现有 limit 边界输入，保持既有结果；排序前后记录字段和值不变。存在项目过滤时，结果仍满足原有项目范围，并在该范围内符合本次排序与 limit 判据。
6. **共用范围核对**：确认 CLI、MCP、Web 仍调用同一纯函数，未新增入口专属排序；确认函数仍无平台分支及外部环境依赖。结合上述 macOS 行为证据，支撑三平台共同的排序承诺。

交付通过须同时满足上述行为证据与共用范围核对。仅有包构建成功或入口启动成功不足以判定通过；无需新增 Windows、Linux 的本次实际执行记录。
