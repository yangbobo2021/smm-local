# 规格：同分检索结果按数值会话 ID 稳定排序

本规格依据同目录下已确认的 [intent.md](intent.md)。现有材料足以确定本次行为，无待维护者决定的事项。

## 预期行为

1. 检索结果分数相同时，按整数会话 ID 的数值升序排列，不受输入列表顺序影响。
2. 检索结果分数不同时，保持现有分数排序规则；会话 ID 仅用于同分结果的排序。
3. CLI、MCP 和 Web 均通过现有共用函数获得上述排序结果，调用方式和结果字段不变。
4. 项目过滤和 limit 的既有语义不变。同分排序规则适用于既有排序环节，不改变过滤范围、截取时机或返回数量规则。
5. Windows、Linux、macOS 具有相同的排序语义。

## 边界与约束

- 本次改动限定于三平台共用的排序纯函数。输入仍为已解码的 Python 数值分数和整数会话 ID，输出仍为排序后的列表。
- 会话 ID 按数值比较，例如同分时 ID `2` 排在 ID `10` 之前。
- 分数相等与大小关系沿用受支持的 Python 数值比较语义，不新增分数归一化、精度容差或类型转换规则。
- 空列表、单条结果及分数和会话 ID 均相同的结果，保留既有处理行为；本次不新增去重或第三排序键。
- 不引入系统、文件、数据库、网络、时间或区域设置依赖，不新增平台分支。
- 不改变运行时范围、依赖、安装或服务。
- 当前仅有 macOS 可用于本次执行验证。三平台一致性是验收要求，不代表已有 Windows 或 Linux 的执行记录。

## 验收条件

1. 输入两条同分结果，整数会话 ID 分别为 `10` 和 `2`，两种输入顺序均输出 ID `2`、`10`。
2. 输入多条同分且会话 ID 互异的结果，任意打乱输入后，输出均按会话 ID 数值升序排列。
3. 输入包含不同分数的结果时，各分数组之间的顺序与既有规则一致，不因会话 ID 大小而改变；每个同分组内部按会话 ID 数值升序排列。
4. 排序前后，每条返回结果的字段和值保持不变。
5. 启用项目过滤时，仍按既有规则确定结果范围，范围内的同分结果满足新的排序规则。
6. 使用 limit 时，返回数量和截取语义符合既有规则；截取所依据的排序满足新的同分排序规则。
7. CLI、MCP 和 Web 均沿用共用函数的调用方式，返回结果满足同一排序规则。
8. 空列表、单条结果以及分数和会话 ID 均相同的结果，保持既有处理行为。
9. 三平台共用相同的纯函数和受支持的 Python 数值比较语义，不存在额外排序层、平台分支或环境依赖；验收记录明确区分已执行验证的平台与尚无执行记录的平台。
