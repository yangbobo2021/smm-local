# SPEC 模板对比 v3：最终结果

**建议采用候选 v3，正式模板尚未替换。** 在这套固定 EVAL 上，v3 的 18 份回答全部通过对应检查，
当前模板为 3/18；检查得分分别为 75/75、48/75。六个样本各重复三次，v3 均为 3/3。
这是规格生成质量比较，不代表已经完成 SMM 的 Windows/Linux 产品运行验收。

## 每轮结果与修订

每轮都重新执行当前模板与当轮候选，不复用基线回答。原输入、评分标准、执行器与模型配置不变。

| 轮次 | 当前模板：回答通过 / 检查得分 | 候选：回答通过 / 检查得分 | 结论 |
| --- | --- | --- | --- |
| [v1](comparison-v1.md) | 3/18 · 48/75 | 11/18 · 65/75 | 环境与关键状态未完整绑定；旧 CLI 参数信息也不充分。 |
| [v2](comparison-v2.md) | 3/18 · 48/75 | 17/18 · 74/75 | 状态绑定与输入取得途径已补齐，但一次遗漏客户端新路径的平台证据。 |
| v3 | 3/18 · 48/75 | 18/18 · 75/75 | 在固定样本上消除剩余组件/入口覆盖缺口，未出现对照误报或旧用例失败。 |

75 是 25 个检查点各重复三次，不是 75 个独立场景。全项通过计数严格要求一份回答满足
该样本全部条件；当前版 3/18 不表示其他回答的全部功能内容错误。样本刻意围绕已知遗漏和
控制误报构造，不能将该比例当成当前模板对所有任务的成功率。

## 最后一轮逐样本对照

| 样本 | 当前模板 | 候选 v3 | 主要观察 |
| --- | --- | --- | --- |
| 01 多平台来源同步 | 0/3 | 3/3 | 各平台 Hub 的服务身份、外部依赖、凭据和重启后完整结果，以及客户端新查询/读取路径都有必要执行证据约定。 |
| 02 静态帮助文案 | 0/3 | 3/3 | 保留三平台支持，依据共享文本和不变的输出机制接受当前环境验证，不强制三平台部署服务。 |
| 03 共用纯排序逻辑 | 0/3 | 3/3 | 明确跨平台行为契约及共用逻辑证据适用性，不宣称其他系统已实际运行。 |
| 04 仅 Linux Hub | 0/3 | 3/3 | 实际 Linux systemd 的启动、重启与失败恢复得到覆盖，不扩大到未支持的 Hub 平台或未改动客户端。 |
| 05 环境信息不足 | 3/3 | 3/3 | 保留影响交付和验收的待确认决定，不从开发机或 Python 要求猜测支持范围。 |
| 06 旧 CLI 帮助回归 | 0/3 | 3/3 | 两个入口、用途及参数意义/取得途径完整，保留命令、参数、退出与无写入行为。 |

当前模板主要遗漏 H3/H4/H5/H7、T2、L2、S3 及旧 R3/R4，而非完全无法识别平台。
v3 未通过机械增加测试数量得分：低风险对照仍接受有依据的当前环境验证，
组件未变或不受影响时不扩大必验范围，信息不足时也允许 SPEC 草稿保留待确认项。

## 候选修改的通用性

完整文本见 [candidate-spec-v3.md](templates/candidate-spec-v3.md)，
对正式模板的提案差异见 [candidate-v3.patch](candidate-v3.patch)。没有应用该 patch。

候选在原四节模板上补充四类要求：

1. 从项目已有承诺确定相关组件的交付环境，必要决定缺失时标明待确认。
2. 根据需求、设计和已知差异判断风险，在 SPEC 约定必要平台及通过证据。
3. 将环境、动作前状态、操作和完整结果明确对应；按受影响组件与入口覆盖新增路径。
4. 必要输入说明含义、适用范围和取得/确认途径，同时允许有依据地复用共用逻辑证据。

机器、命令、具体测试步骤和 CI 仍留给 PLAN。候选没有写入 SMM/VibeInsight、固定操作系统名单、
`psql`、CLI 查询命令或评分 ID。[v1](candidate-v1-notes.md)、[v2](candidate-v2-notes.md)、
[v3](candidate-v3-notes.md)分别保留修改原因，避免用后续版本掩盖先前失败。

新增组件检查确实改变了第三次主样本的义务。例如
[case-01-candidate-3.md](runs/2026-11-17-v3/case-01-candidate-3.md)写明：

> 以下行为须在 Windows、Linux、macOS 上分别通过本次发行的本机端及 CLI/MCP 实际入口验证。

并将当前项目身份、VibeInsight 检索与命中引用读取列入该范围；不再只列归属补传和旧引用兼容。
另两次回答同样明确各平台经两个入口检索并读取原文，可共用已验证 Hub，未要求三乘三系统组合。

## 执行、评分与复核

- 三轮合计 **108 次独立生成、18 组匿名模型评分**，全部成功，无技术失败或观察到的工具调用。
- 生成和评分实际配置均为 `gpt-6.1-sol`、reasoning effort `none`、CLI `0.166.0-alpha.5.1`。
  两版没有模型或推理覆盖；每次使用新空目录、忽略用户配置/规则、禁用项目指令读取、只读临时会话。
- 每轮在任何生成前冻结模板、材料、顺序、评分与执行器。评分者接收匿名回答，没有版本标签、
  生成次序或本次聊天；同一模型在不同上下文评分，不是跨模型验证。
- 主 Agent 重点复核失败项及 H4/H5 的修订证据，并校验全部请求、配置、回答哈希、检查 ID、
  标签和摘录。v2/v3 原始摘录全部逐字匹配；v1 一处引文核正单独留痕，未改变任何分值。
- [verify_results.py](verify_results.py)不调用模型，可重建请求、验证引文与记录的核正，并从原始评分
  重算汇总。语义判断仍来自匿名模型评分及所记录的主 Agent 审计，不由哈希校验自动证明。
