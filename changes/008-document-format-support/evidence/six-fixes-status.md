## 原因调查与平台方法

200 次真实自有进程退出采样复现 macOS 命令行读取的退出竞态：内核返回 EINVAL，psutil 可映射成 AccessDenied，而进程状态尚未来得及报告僵尸。存活对照全部成功。该采样刻意紧追退出，200/200 不是日常故障率；历史现场没有同瞬间内核跟踪，不能逐条还原原 PID 的内核分支。本次使用内核退出确证，活进程真正拒绝访问仍保留失败保护。

Ubuntu 后来另一次失败发生在测试故障注入之前：完整旧资料核对先耗尽了夹具准备门，看守已正常退出，之后当然不能确认注入。原 13 过/1 失败不改判。新版只在完整核对之间发送任务认证进度来续测试 idle 门，保留全部核对、原故障观察及五秒判据、产品 300 秒/1GiB/256MiB预算；最终 Hub 实跑完整通过。Windows 换行及自有 JSON 就绪读取问题也各自保留原失败和修订依据。

统一的启动/退出身份、UTF-8/原始字节、Windows argv、就绪文件、准备进度、批次边界及原件回收约定见[验收指南](../../../scripts/acceptance/README.md)。这些约定减少测试自身的系统差异；内核、权限、服务身份和文件系统语义仍需逐平台实测，不能保证单平台通过就自动覆盖其他系统。
