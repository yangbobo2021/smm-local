# 意图：检索和理解 Word、Excel、PDF、图片中的项目资料

状态：草稿，待维护者确认。

父意图：[项目知识检索与内容上传控制](../004-project-knowledge/intent.md)。扩展[本机文档](../006-local-document-search/intent.md)和[Hub 文档](../007-hub-document-search/intent.md)，为[飞书关联内容理解](../010-feishu-context-understanding/intent.md)提供通用内容处理能力。进度见[父目录导航](../004-project-knowledge/README.md)。

## 现有问题

用户需要查找的项目资料还包括 Word 规格、Excel 表格、PDF 说明和图片。SMM 现有公开来源与检索路径缺少这些文件的专门内容接入和定位方式；006、007 若先支持基础文本，也仍无法覆盖这些常用格式。

不同格式的有效内容可能位于段落、表格、工作表、单元格、页面或图像区域。只知道文件名或某段提取文字，不能让用户判断相关内容是否已被完整纳入、结果实际来自哪里。

## 受影响的用户

希望检索上述格式资料的本机使用者、Hub 维护者，以及需要根据文件内容取得原始依据的 Agent。也包括后续从飞书附件或图片中查找信息的使用者。

## 期望结果

- 在已确认的格式和内容范围内，用户可按内容找到相关 Word、Excel、PDF、图片，并读取对应原内容。
- 命中能保留适合该格式的定位信息，例如文档段落或表格、工作表与单元格、PDF 页面、图片中的对应区域。
- 用户能区分已处理、部分支持、需要其他条件和处理失败，知道实际可检索的内容范围。
- 本机端和 Hub 对同类资料的处理范围、来源说明和原文定位具有一致含义；具体图片理解层次仍待确认。
- 后续飞书场景取得的同类文件和图片，可沿用这些内容处理能力与限制。

## 范围与约束

- 本项增加格式与内容支持，依托 006、007 已明确的文档纳入、检索和原文读取路径；文档归属及上传选择仍由对应子意图确定。
- 覆盖 Word、Excel、PDF、图片四类目标，具体扩展名、扫描件、图片和表格内容范围见待确认问题。
- 源文件保持原样。处理后的文字、解释与来源定位应能区分，不能把推断出的含义标为文件中的原句。
- 同一文件或图片通过文档入口及飞书场景纳入时，应适用一致的内容范围和原文说明；飞书资源的取得及消息关系由 010 负责。
- 受支持格式及组件的平台范围在本项 SPEC 中分别明确，不能只凭本机能打开样本声称 Hub 服务身份或其他系统也能处理。
- 内容理解的处理位置及外部模型使用问题见[父意图](../004-project-knowledge/intent.md#待确认问题)，本意图不预定解析器、模型或安装方案。

## 待确认问题

1. Word、Excel 首版覆盖哪些扩展名：只含 docx、xlsx，还是也包括 doc、xls 等格式？该选择影响兼容范围和运行依赖。
2. PDF 首版是否包含扫描件？图片支持到文字识别，还是还要理解截图、图表、流程图的含义？该选择改变可检索内容与理解效果的目标。
3. Excel 需要覆盖单元格显示值、公式、图表和隐藏区域中的哪些内容，是否需要重新计算公式？该选择决定本项是读取哪些已有内容，以及是否增加计算能力。
4. 首版是否需要读取受密码保护的文件，还是只覆盖无需额外解密的可读文件？该选择影响文件支持范围及额外凭据的使用；具体失败提示留给 SPEC。
