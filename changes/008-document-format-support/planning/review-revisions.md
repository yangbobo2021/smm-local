# PLAN 六项审查修订记录

状态：维护者已确认PLAN修订版与准备范围，授权提交/创建/合并PLAN PR，合并后直接进入实现与验证；组件研究仍不等于正式产品验收。研究源码在[probes](probes/)；私有原件位于当前工作树.acceptance-local/008-plan-probe。

| 审查项 | 修订 | 核对结果与剩余条件 |
|---|---|---|
| R1 前置验证时机 | 分为确认前G0-P与合并后G0-I，先组件/环境可行性再请求确认，不把准备债务推到实现 | 本机依赖/OCR/语言身份/34包离线重装已探测；Linux/Windows当前能力已观察。本轮免macOS权限预检；其他OS最小组件/字体/材料由G0-I准备，原件回收独立追踪，不统一作为PLAN合并阻塞 |
| R2 reprocess预算域 | refresh只核当次来源批次；合法CID单文件重处理只核授权/版本/单文件及任务/暂存限额，不重新计旧来源 | 补127MiB→129MiB合法重处理、真实refresh超限与共享版本负控设计；不修改SPEC |
| R3 PDF增量预算 | worker构造parser前受控stream工厂、逐滤镜有界sink、页/全局/共享对象计数；PDFium只读已验证中间材料 | Flate单流/同页多流/全局等于及+1已原型验证；非Flate/预测器/共享对象归属及安全中间路径进入实现TDD，不要求PLAN预先完整实现，不宣称RSS监督等于解压限额 |
| R4 空白文档 | 新增TC-008-empty-original，覆盖三格式合法空内容、列表引用、各入口原件、重启及OCR失败负控 | 属于待实施用例；没有运行SMM新格式验收 |
| R5 旧网页 | 新增TC-008-stale-web，两端真实浏览器冻结所见P/CID/AID，另一入口推进后旧页提交；核原始请求/拒绝/完整状态及刷新正控 | 不以手工API负控代替Web；待实施 |
| R6 证据回收 | 区分runner结束与持久材料删除，按artifact ID回收/核SHA/解密打开后写回收回执，回执前不形成正式通过 | 增加下载/解密失败、过期及成功回执小样设计；本轮实际下载网络失败明确保留缺口，不从摘要重造原件或passed |

OCR研究保留四版：v1探针误把普通文字输出作为TSV，不能作为识别质量结论；v2改显式TSV后第二份表格CER约8.33%；v3改PSM3但同一语言顺序仍失败；v4采用chi_sim+eng/PSM3，两份逐格一致、CER=0。同一份OCR输入PNG在四版间SHA一致，未改真值或换输入追通过。该结果只支持本机两份清晰单页样本的候选profile，不是完整SPEC质量或三平台通过。

研究采用系统Arial Unicode字体，不将字体文件提交或作为正式CI分发依赖；正式可分发字体和固定样本由G0-I准备。Tesseract两种语言顺序都仍是允许配置，产品不得自动改用户配置；候选profile随本PLAN确认；实际使用仍记录配置及质量边界。
