# 规格：在汇总端同步 VibeInsight 对话，并按关联项目检索

依据 [PR #18](https://github.com/yangbobo2021/smm-local/pull/18) 合并的[意图](intent.md)。当前汇总端已经能跨电脑搜索，但汇总检索请求未携带当前项目范围。此次变更让汇总端按当前项目及其关联项目筛选两类来源的对话。

## 预期行为

### VibeInsight 同步

- 汇总端维护者通过汇总端 CLI 配置 VibeInsight 来源的连接、只读凭据和同步周期。验证连接和读取权限通过后，汇总端保存配置及凭据。已启用的同步在汇总端服务重启后自动继续，维护者无需再次输入凭据。更换凭据时，新凭据验证通过后才替换已保存的凭据。
- 同步状态显示最近一次成功时间及最近一次失败原因。查看配置和状态时，凭据以脱敏形式显示。
- 启用同步后，汇总端自动拉取该连接可读取的全部 VibeInsight 项目的历史对话，随后定期同步新会话和已有会话新追加的轮次。首次发现的项目会自动补拉历史，即使这些历史早于其他项目的同步进度。已完成的导入进度在汇总端重启后仍有效。
- 重复拉取同一个会话或消息时按来源标识去重。同步完成后，新增会话和已同步的新增轮次都可搜索和读取。
- 已归档的会话在 VibeInsight 新增对话轮次时，汇总端更新原有会话。用户可以在同一个汇总会话中按来源顺序读到原有轮次和新增轮次。
- 上游不可用或某批拉取失败时，用户仍可搜索之前成功归档的对话。汇总端报告失败，恢复后从上次成功进度继续。未成功归档的记录仍会被重试。

### 汇总端项目关联

- 汇总端维护者通过汇总端 CLI 列出两类项目、查看已有的直接关联、建立或解除关联。项目列表标明来源及可区分同名项目的信息，包括上传项目的来源电脑、VibeInsight 项目的来源身份。项目改名后仍能识别同一个项目及其关联。
- 同一台汇总端可记录电脑上传的项目之间的关联，以及电脑上传的项目与 VibeInsight 项目之间的关联。一个项目可以直接关联多个项目，关联双向生效。重复建立同一条关联时，关联列表只有一条。两台电脑连接同一汇总端后，使用汇总端保存的关联。
- 本机同步项目归属后，汇总端可以识别检索请求中的当前项目，并区分不同电脑上传的同名项目。功能上线前已上传的历史在设备补齐对应的项目归属后，也能出现在项目检索中。

### 搜索与读取

- 在 CLI 或 MCP 发起汇总端项目检索时，结果标明由汇总端执行以及实际检索的项目。按项目 A 检索时，候选范围为 A 及其在汇总端直接关联的项目。例如 A 关联 B、C，B 另关联 D，从 A 检索纳入 A、B、C。解除 A 与 C 的关联后，从 A 检索的范围为 A、B。
- 全局汇总检索涵盖两类来源中可供检索的对话。命中项标明来源、所属项目、原始会话标识和消息位置，并可通过现有读取入口打开该条消息的原文。
- 汇总端不可用时，CLI 和 MCP 沿用现有回退行为，搜索本机所有项目，并返回本机来源和回退原因。显式选择本机检索时按本机档案和本机项目关系执行。

## 边界与约束

- 访问沿用汇总端现有的单用户模式。汇总端使用只读凭据拉取 VibeInsight，对话保存于汇总档案。
- 首版的增量依据是 VibeInsight 新写入的对话事件。若 VibeInsight 原地改写历史消息，且未写入新增事件，首版不负责发现该改写或刷新汇总档案中的对应消息。已归档的历史仍可按原内容检索和读取。
- 项目关联影响项目检索范围。解除关联后，对话仍归属原项目，并可在相应的项目范围或全局范围中找到。
- 项目身份以可持续标识为准。同名项目可分别配置关联。尚缺项目归属的历史记录可通过全局检索找到，待设备补齐项目归属后进入相应的项目范围。
- 旧客户端发出的无项目范围请求沿用全局检索行为。

## 设计决策

- **凭据保存在汇总端。** 沿用汇总端现有的独立凭据文件方式。连接地址、同步周期和启用状态保存在配置中，秘密值写入汇总服务状态目录内的专用凭据文件，由操作系统文件权限限制访问。汇总服务以自己的运行账号读取该文件，命令输出、日志和对话数据库不保存凭据原值。
- **同步进度保存在汇总数据库。** 每个 VibeInsight 来源持久记录已成功归档的上游位置。一次同步先确定本轮上界，再分批按新增事件识别新会话和已有会话的新增轮次。归档结果和对应的进度一起提交。重启时读取已提交的位置继续，失败的批次会重新处理。更换同一来源的凭据沿用该来源的进度。
- **PostgreSQL 事件流的续跑依据。** 可沿用 Living KB 的服务器入库时间 `created_at` 和事件 `id` 作为组合位置。同一时间的多个事件通过 `id` 区分。每轮回看最近一段入库记录，覆盖常见的延迟提交。重复读取时按来源会话和消息标识去重。

## 验收条件

1. **自动拉取全部可读取项目。** 配置一个可读取两个项目的 VibeInsight 连接并启用同步。两项目的历史均可从 SMM 搜到并读回原文。随后让该连接可以读取第三个项目，该项目早于已保存同步进度的历史也会自动导入。查看配置和状态，确认看不到凭据原值。
2. **凭据持久和旧会话续写。** 配置并成功同步一段有 3 轮的会话后停止汇总端。在停机期间向该会话追加 2 轮，并创建另一段新会话。重启服务，无需再次输入凭据即可自动同步。原会话仍使用同一个汇总会话标识，按来源顺序读回全部 5 轮，两轮新增内容均可检索。新会话可独立搜索。再次同步后，原会话仍为 5 轮。尝试用无效凭据替换时，原配置仍可继续使用。
3. **跨设备和跨来源关联。** 电脑甲上传 A，电脑乙上传 B，VibeInsight 提供 C、D。建立 A 与 B、A 与 C、B 与 D 的关联。每个项目都包含同一关键词及独有证据。电脑甲按 A 发起汇总检索，范围为 A、B、C。电脑乙按 B 检索，范围为 B、A、D。解除 A 与 C 的关联后，按 A 只覆盖 A、B，全局仍能找到 C。
4. **同名、改名和已有历史。** 两台电脑上传同名项目，只选择其中一个建立关联。按关联起点检索能区分两套对话。目标项目改名后关联有效。升级前已上传的对话在设备补齐项目归属后可按项目找到，在此之前可通过全局检索找到。
5. **检索入口与引用可追溯。** 从 CLI 和 MCP 分别发起同一项目的汇总端检索，核对实际项目范围一致。对设备上传记录和 VibeInsight 记录各核对一条命中，确认来源、所属项目、会话标识和消息位置齐备，按命中引用读回的原文一致。
6. **回退和兼容。** 停止汇总端后，CLI 和 MCP 的项目检索按现有方式搜索本机所有项目，响应标明本机来源和回退原因。旧客户端的全局请求仍能搜索汇总档案。
7. **失败批次与重读去重。** 让一批记录在归档完成前失败，查看错误状态并确认之前成功归档的对话仍可读取。恢复后，失败批次中的记录最终都可检索，包括回看时间内延迟提交的事件。重复执行同步后，每个来源会话仍只有一个有效版本。
