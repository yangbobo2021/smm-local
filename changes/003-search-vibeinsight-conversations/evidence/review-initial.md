## 审查发现

### [P2] 通用答案复核步骤仍将 Hub 用户导向本机 Web

- **性质与依据：** 这是受本次远端来源扩展影响的文档路径缺口，并非 SPEC 要求增加 Hub Web 功能。`TRIAL_GUIDE.md:36` 写“答案应能在 Web『检索测试』中复核”，`:50` 写“在 Web 读取原文”。但 `src/smm_local/api.py:258–264` 的搜索/读取直接调用本机 `db.search` / `db.read`，`src/smm_local/static/index.html:51` 明示“检索本机对话”，搜索表单也使用本机 API。
- **影响：** 按指南对 Hub 的 VibeInsight 或其他设备命中做复核时，该记录可能从未进入这台电脑的本机档案，因而不会在 Web 中出现。用户可能误判同步、关联或引用失效。它不阻断已提供的 Agent 检索与读取路径，也不否定 R1–R7 功能证据。
- **现有可用路径：** `skills/smm-search/SKILL.md:42` 已要求保留返回的 `hub_id`，并用 `read_conversation` 或 launcher `read --hub-id` 读取，支持 `hub_message_id` 精确定位；指南:111 也说明 VibeInsight 可从同一读取入口取原文。
- **适度建议与通过条件：** 将通用复核说明限定到实际档案范围，并让 Hub 命中沿已有 CLI/MCP 原文读取路径确认即可。通过条件是：只拿到一个本机没有的 Hub 命中时，读者能从通用提问/故障复核步骤判断该去哪里读取，以及保留哪类返回引用；无需新增 Web 产品行为。该项属于规格未细化的用户确认路径，请维护者决定纳入本次文档返修。

未发现其他有实际影响的确认缺口；无 P0/P1 产品发现。
