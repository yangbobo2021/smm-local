# 起草 intent.md

根据用户的原始反馈、现有项目资料和 Intent 模板，起草一份供维护者确认的意图。

1. 记录用户直接观察到的现象，判断用户当时想完成什么。
   如果目标来自推断，在草稿里标明它仍待确认。
2. 沿用户实际接触的入口做只读核对。从出现问题的那一步继续往下走，
   看用户下一步要作什么判断、需要哪些信息、在哪里可能卡住。
   优先检查最贴近用户目标的路径。
3. 把期望结果写成用户能完成的任务。根据已知资料写清本次范围和约束。
   如果发现的后续卡点会扩大范围，把它写成一个具体的待确认问题，
   并说明不同答案会改变哪些入口或结果。已明确的事项直接写入意图。
4. 按模板输出 `intent.md` 草稿。将接口细节和验收条件留给规格阶段，
   将改动位置和实施步骤留给计划阶段。
