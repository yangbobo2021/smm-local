## 3. 共用后端方案

### 3.1 本机存储与项目职责

新文档模块在Local档案初始化独立的来源、来源项目绑定、文档当前快照、来源文件成员及FTS表，不把文档写入conversations/messages或对话上传来源。文档唯一身份依据规范路径，显示路径与用于比较的规范键分开；Windows大小写规范化，macOS显式路径别名与目录实际名称一致处理，不合并不同路径的硬链接或猜测移动身份。

每个来源保存根路径/类型、递归/排除配置、配置版本、最近刷新身份/状态/时间及计数。文件级快照保存不重用的ID、内容版本、原始字节SHA、规范化文本、字符长度、最后采集时间/来源及最后发布序号。成员保存相对路径、就绪/失败/缺失状态和连续资格代次；来源根和失败明细可诊断，正文只在快照中一份。

普通项目创建不写路径映射/对话/关联。显示名修改不动文档绑定；合并在同一项目事务中转移来源项目键并去重，使配置/资格引用按实际改变失效，内容无需重扫即可在目标项目查询。已有上传选择确认保护保留；如项目预览摘要会受文档绑定改变影响，把相关绑定纳入摘要并展示影响，不静默省略新材料。条件查询sqlite_master后再执行文档绑定迁移，core不导入documents模块，避免独立Hub包vendored core缺模块。

### 3.2 扫描、预算与原子发布

添加/设置只验证路径、项目与排除语法并保存配置；不读正文。刷新先在短事务中分配全局递增请求序号与来源刷新身份，再于数据库写锁之外枚举/读取。配置版本与本轮身份在发布事务再次核对；来源已删、配置被改或同源新刷新取代时拒绝旧结果，不能复活来源。不同来源竞争同一路径时，较早请求不得覆盖较新已发布序号；成员仍引用唯一文件级当前快照。

先按明确范围得到候选及大小，计算1000候选/16MiB集合；单文件超过2MiB或无法取大小仍计候选，但不计累计字节。全局失败优先且不发布部分“完整”结果。预检为每候选固定文件身份/大小/修改时间，不把计费元信息与实际读取割裂。通过预算后逐文件打开时先核对fstat与预检身份/大小/修改时间一致，再有界读取最多2MiB+1字节；读取后再核对fd元信息、实际字节数及路径仍指向同一文件。枚举计费后、打开前发生大小/身份/修改时间变化也判文件failed，拒绝该候选、不自动按新大小绕过本轮来源预算；下一次明确刷新重新预检。屏障用例先建立成功快照，再在预算后把单个文件从小内容增到2MiB+1、或把多个小文件增为累计超过16MiB的稳定文件；按本方案这些变化者逐文件failed、旧资格撤销、不发布新正文，未改变的正控仍可用。下一轮重新预检时按新的单文件/来源预算得到确定失败或恢复结果，断言实际发布集合、资格和旧ref，而不只检查错误字符串。逐文件严格解码，检查打开的常规文件及读取前后身份/大小/修改时间一致；不跟随符号链接/junction，不接受半份正文。源文件仅读，归一化只作用于采集副本。

配置pending、终态来源failed或文件failed/missing均撤销相应查询资格；刷新中只暂时不可用，正常无变化成功保留连续资格。失败/缺失后重新纳入必须换资格代次，即使配置和字节相同也不复活旧引用。没有有效成员的快照清理可用正文/索引，保留诊断身份；仍有其他有效成员时保留全局当前版本，不回退较早来源的正文。下次明确刷新可替代持久的refreshing状态，流程不依赖旧进程仍存在。

### 3.3 检索与签名读取

采用现有core.tokens中英文分词语义，在独立FTS中索引规范化全文并按文件排序，避免仅切分索引造成普通查询词跨片段边界漏召回。按文件去重、相关性排序后以路径/身份稳定平局；从完整文本选取命中附近最多2000码点窗口，长行同样可读。全文FTS与前端窗口分开，不为排名传输本机候选。

查询在一个SQLite读快照中取得本机直接一层项目集合、有效成员与文件版本，避免分多次重展开范围。没有Hub依赖；显式文档调用不经federation搜索/上传。引用复用当前档案的持久签名材料，使用与对话不同的kind，绑定文档ID/内容版本/候选窗口与当次有效来源的配置版本及资格代次。签名材料在读事务外就绪，避免嵌套写锁。

读取只查采集快照，至少一个原资格仍有效才返回；不替换档案、不重新展开项目关联、不访问当前源文件。Unicode码点坐标由后端统一计算，Web直接渲染返回文本，不用JavaScript UTF-16 slice解释Python偏移。扩读同一采集版本、最大16000码点及换行端点按B6核对；当前版本更换及资格中断后旧引用失败。
