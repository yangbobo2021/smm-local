# 意图：把指定的本机文档纳入项目检索，并读取准确的原文

状态：维护者于2026-11-22授权代理自主完成SPEC、PLAN、实现与验证，并逐阶段PR合并。本意图的未决范围据该授权在本轮定稿，具体可观察行为见[规格](spec.md)；不声称维护者逐项亲自确认。

父意图：[项目知识检索与内容上传控制](../004-project-knowledge/intent.md)。后续相关子项：[Hub 文档](../007-hub-document-search/intent.md)、[常用格式](../008-document-format-support/intent.md)。进度见[父目录导航](../004-project-knowledge/README.md)。

## 现有问题

用户处理项目问题时，会同时参考 README、规格、设计记录和其他文档。SMM 0.4.0 的公开检索与原文读取入口以已归档对话为对象，缺少直接指定文档或目录、维护其内容更新并按文档位置读取原文的路径。

用户即使搜到了讨论某份文档的对话，也仍需另行找到文档，确认它实际写了什么以及是否已经更新。

## 受影响的用户

希望通过 SMM 检索本机项目文档的使用者，以及需要取得文档原始依据来回答项目问题的 Agent。

## 期望结果

- 用户能够明确选择纳入的本机文档或目录，并了解哪些内容已经可检索、哪些尚未处理或无法处理。
- 用户可以在项目范围内查找已纳入的文档，区分文档命中与对话命中，读取支撑结果的原内容。
- 结果能够说明文件来源、内容位置及对应版本或采集状态，避免把旧内容当作当前文件的内容。
- 文件发生修改、移动或移出纳入范围时，用户能理解检索结果和既有引用的状态。
- 本机文档检索可独立使用；是否连接 Hub 不影响这一基本能力。

## 范围与约束

- 本项首先覆盖用户明确指定、当前本机账户可读取的文件。文档进入 Hub 的能力由 007 承接。
- 首版以Markdown、UTF-8纯文本完成基本文档路径，Word、Excel、PDF、图片由008扩展。
- 文档保留自身的来源和原文定位方式，现有对话的检索及原文读取继续可用。
- 文档来源可绑定零个、一个或多个本机普通/全局项目；未绑定资料仅参加全部本机文档查询。共享资料本身不自动建立项目之间的关联。
- 源文件保持原样。首版采用明确手动刷新和最近成功采集快照；更新/删除/移出后旧引用明确失效，不提供历史版本读取。具体约束见SPEC，不在意图预定解析器、索引或存储结构。
- 共用入口与资料组织问题见[父意图](../004-project-knowledge/intent.md#待确认问题)。

## 待确认问题

本轮授权下已自主定稿，无006范围内必须等待维护者醒来才能继续的决定：

1. 首批格式为Markdown/UTF-8纯文本，其余格式保留008。
2. 目录默认递归，支持明确排除和非递归；不跟随链接，范围有界。
3. 用户通过CLI/Web明确添加和刷新，不新增后台watcher；MCP提供只读发现/查询/读取。
4. 只保存最近可用采集版本，旧版本明确失效；修改前的原文不被新内容静默替代，源文件不改写。
5. 提供独立“仅本机文档”查询，沿用本机项目直接一层关联；零/多项目归属按上述边界处理，既有对话联合检索不变。
6. 普通账户实际验收macOS、Ubuntu、Windows新入口；不新增Hub服务或管理员认证要求。文件位置、来源状态、原文字符及行号和版本边界由SPEC定义。

以上是为独立交付006而作的范围决定，不代替007–010各自的后续确认，也不授权文档内容进入Hub/外部模型。
