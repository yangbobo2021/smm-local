# 计划：通过 CLI 查找较早的导入批次 ID

依据[已确认的规格](spec.md)。

## 修改位置

- `src/smm_local/cli.py` 为 `source batches` 接收并校验 `--before`，补全批次查询和清理批次的两处帮助。
- `src/smm_local/importers/registry.py` 中的批次查询接收可选的批次 ID 上界，按指定来源和 `id < before` 查询，沿用原有排序、每页上限和返回字段。
- `tests/test_cli_help.py` 覆盖翻页指引和查看帮助时的档案状态。`tests/test_source_plugins.py` 覆盖实际 CLI 查询、参数错误和清理回归。

## 实施顺序

1. 准备临时档案夹具。一组为 101 批，复现原问题；另一组让主来源至少有 205 批，并穿插第二来源的批次，验证连续翻页和来源隔离。用于清理回归的较早批次包含可核对的导入记录。
2. 实现查询上界和 CLI 参数校验。先核对默认查询，再覆盖第二页、末尾空页和无效输入。
3. 更新两处简体中文帮助。清理帮助保留停用命令，并指向较早批次的查询方法。查询帮助说明来源 ID 的查法、翻页所需的 `id`、如何辨认目标批次，以及 `[]` 的含义。
4. 从帮助出发走一遍用户路径，执行下列验收和回归测试。

## 验证方法与通过条件

| SPEC 验收项 | 怎么验证 | 通过条件 |
|---|---|---|
| 1. 默认查询兼容 | 在含 101 批的同一档案上，分别用基线和实现版本运行 `smm source batches <来源ID>`，比较解析后的 JSON。 | 返回相同的最近 100 批，按 `id` 降序排列，`id`、`revision`、`imported_at`、`messages` 的值和类型一致。 |
| 2. 查到第 101 批 | 不预填目标 ID。运行默认查询，取末条记录的 `id` 传给 `--before`，再用第二页的末条 `id` 查一次。 | 第二页恰好返回原先列表之外的最早一批，上一页的末条不会重复。第三次查询以 `0` 退出并返回 `[]`。 |
| 3. 多次翻页完整且来源隔离 | 在两来源 ID 交错的夹具中，始终使用每页末条 `id` 翻页。将拼接结果与夹具预先记录的主来源完整 ID 序列比较。 | 每页最多 100 条，拼接结果与预期降序序列完全一致，无遗漏、重复或其他来源记录。 |
| 4. 从帮助取得目标 ID | 从 `smm source purge-batch --help` 出发，只根据帮助查来源 ID、打开批次查询帮助、翻页，并按已知导入时间找到目标批次。走查前只提供目标来源和导入时间。 | 两处帮助以简体中文给出必要指引，用户能判断从哪条记录取翻页值、何时到末尾、如何取得目标 `id`，以及清理前须停用哪个来源。 |
| 5. 无效输入与清理规则 | 分别传入缺值、非整数、`0` 和负数，记录退出码及错误。用第 4 项查得的 ID，在来源仍启用时尝试清理，再停用并重试。 | 无效输入以非零状态码退出并指出 `--before` 参数错误。来源启用时拒绝清理，停用后只删除目标批次的导入记录，其他批次的记录仍可查到。 |

另外，对比查看帮助和查询前后的批次、导入记录与来源启用状态，确认这些状态保持一致。运行 `pytest -q tests/test_cli_help.py tests/test_source_plugins.py`。

实现 PR 按五条验收条件记录通过、失败或未验证，并附两处帮助的完整输出、翻页结果、无效输入的错误与退出码、清理前后对比和 `pytest` 摘要。交维护者审查前，按仓库的 [Review Prompt](../_templates/pr-review.prompt.md) 做独立审查，将结论和依据写入 PR。
