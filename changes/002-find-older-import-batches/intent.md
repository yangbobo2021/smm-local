# 意图：让用户通过 CLI 找到较早的导入批次 ID

## 现有问题

清理批次的帮助指引用户运行 `smm source batches <来源ID>`，再从目标批次记录中取得 `id`。
这个命令只返回该插件来源最近的 100 个批次。目标批次早于这 100 批时，用户按帮助操作会卡在查找 ID 这一步。

在一个包含 101 个批次的临时档案中，列表只返回了 ID 101 到 2。最早一批仍在档案里，
停用来源后，已知 ID 1 的用户仍可清理它。[PR #7 Review 实测](https://github.com/yangbobo2021/smm-local/pull/7)

## 受影响的用户

通过终端维护 SMM 本机档案，需要清理某个插件来源的较早导入批次，但事先不知道批次 ID 的用户。

## 期望结果

用户能从 CLI 帮助找到查询较早批次的方法，在同一插件来源的导入历史中确认目标批次，
取得可用于现有清理命令的批次 ID，即使目标批次早于最近 100 批。

## 范围与约束

- 改动范围限于 SMM 本机端 CLI 的批次查询与相关帮助。
- 沿用现有清理行为。清理前仍须先停用对应的插件来源，清理只删除目标批次已导入本机档案的记录。

## 待确认问题

无。
