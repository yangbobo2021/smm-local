# 规格：通过 CLI 查找较早的导入批次 ID

依据[已确认的意图](intent.md)。

## 预期行为

- `smm source batches <来源ID>` 继续按批次 ID 从大到小返回该来源最近的最多 100 个批次。输出仍为 JSON 数组，每条记录包含 `id`、`revision`、`imported_at` 和 `messages`。
- `smm source batches <来源ID> --before <批次ID>` 返回同一来源中 ID 严格小于指定值的最多 100 条记录，顺序和输出格式与首次查询一致。用户可取当前页最后一条记录的 `id` 再查。没有更早的记录时，命令以状态码 `0` 退出并返回 `[]`。
- `smm source purge-batch --help` 在 `batch` 的说明中提示，批次列表默认只显示最近 100 批，可用 `--before` 继续查找更早的批次。
- `smm source batches --help` 用简体中文说明 `source_id` 的含义与查法、`--before` 应填当前页最后一条记录的 `id`，以及空数组表示已查到末尾。用户可根据记录中的导入时间、版本和消息数辨认目标批次，再取其 `id`。

## 边界与约束

- 批次查询只返回指定插件来源的记录。批次 ID 可以不连续，翻页时直接使用列表返回的 `id`。
- `--before` 接受正整数批次 ID。缺少值或值无效时，命令指出参数错误并以非零状态码退出。
- 查询与查看帮助不改变批次、已导入记录或来源的启用状态。执行清理仍须先停用目标批次所属的插件来源，清理只删除该批次已导入本机档案的记录。

## 验收条件

1. **默认查询兼容。** 对一个超过 100 批的来源，不带 `--before` 时仍返回最近 100 批，记录顺序、JSON 格式和字段与现有行为一致。
2. **可查到更早的批次。** 对一个有 101 批的来源，取第一页最后一条的 `id` 作为 `--before`，第二页返回原本看不到的最早一批。继续查询返回 `[]`，退出码为 `0`。
3. **多次翻页无漏项或重复。** 对同一来源反复使用每页最后一条的 `id`，能遍历该来源的全部批次。即使批次 ID 有间隔，并与其他来源的 ID 交错，结果仍无重复、无遗漏，也不会混入其他来源的记录。
4. **只看帮助就能取得目标 ID。** 从 `smm source purge-batch --help` 出发，事先不知道目标 ID 的用户能找到较早批次的查询方法，知道每次翻页该填哪个值、查到何时结束，并能从目标记录取得 `id`。两处帮助均保留清理前须停用对应来源的信息或入口。
5. **异常输入有明确反馈，清理规则继续有效。** 向 `--before` 传入缺失或无效的值时，CLI 报参数错误。使用翻页找到的 ID 清理临时档案时，来源仍启用则拒绝清理，停用后只删除目标批次的导入记录。
