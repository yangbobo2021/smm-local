## 需修订项

### 1. 给 Hub 管理写入补齐 HID/epoch 绑定方案与拒绝断言

依据：SPEC B8 `spec.md:122` 要求 Hub 网页/远程管理写请求（包括项目创建、上传、更新、移除）绑定显示的 HID、适用稳定项目身份及文档控制 epoch；换 Hub/恢复后的旧请求拒绝且不误写另一端，CLI 在所取得 HID/epoch 未变时原子执行。A10 `spec.md:152` 单独要求错误/切换 Hub 与旧 epoch 的验证。

当前 PLAN `plan.md:24` 只安排认证响应取得 HID/document_epoch，`plan.md:38` 的 epoch 是引用/恢复，`plan.md:41`、`:52`、`:69` 的旧页面/目标/代次及两个真实故障组合验证的是 Local 同步选择 KEY/HID/G。SC10 `plan.md:70`–`:72` 安排了创建端、Doc version/source revision 和身份伪造，却没有把上述 Hub 管理请求绑定与错误 HID/旧 epoch 分配给具体 TC；E1/E2 正常网页写入也不会触发它们。于是一个正确执行同步 CAS、创建端隔离和引用失效，但恢复后仍接受旧管理请求的实现，可以通过所列检查。

最小修订：在 Hub 管理 API/共享管理副本方案及接入步骤明确管理写入绑定与同事务核验；把正确当前状态正控、错误 HID、切到另一 Hub 后的旧请求、recover 后旧 epoch 请求，分配到现有 `TC-007-project-ownership`/`TC-007-library-update`。覆盖项目创建及适用的上传/更新/移除，逐项断言拒绝、目标档案/副本/其他资料不变，并核验 CLI HID/epoch 的原子边界。浏览器设计需保留当时显示绑定值的实际请求，不能以提交前重新取得新 epoch 掩盖旧页问题；无需三系统重复所有故障组合。

通过条件：从 B8/A10 可追到这些检查的稳定 TC、输入状态、独立预期及不变状态断言；Local 策略 generation 的测试不能代领文档管理 epoch 的覆盖。

### 2. 给 Hub 浏览器凭据生命周期安排可复核验证

依据：SPEC B8 `spec.md:110` 与 A10 `spec.md:152` 明确要求 token 仅页面内存/同源 Authorization，不进 URL 或持久浏览器存储，刷新后重新选择；未认证/错误凭据不可读写且地址/文件来源可发现。

PLAN `plan.md:24`、`:41` 已安排仅内存实现；`plan.md:72` 已验证缺失/错误凭据和匿名空壳，`:69` 验证前置发现。但验证表没有安排检查真实网页使用 token 的位置、刷新清空认证及持久存储为空。一个把 token 同时保存到 localStorage、刷新自动恢复的实现，仍可通过当前列出的匿名初始页、错误凭据、有效会话及正常 E1/E2 检查。

最小修订：在现有 `TC-007-user-discovery` 的真实浏览器步骤分配认证生命周期检查（可配 `TC-007-project-ownership` 的接口检查）：有效凭据后实际数据请求仅使用同源认证头，URL 无 token；检查持久浏览器存储没有凭据，刷新后回空连接页、未重新选文件前请求不能读写。保留脱敏请求/观察及关键画面，敏感原件只在私有证据中。

通过条件：已有人工项明确上述操作、独立预期和证据，不用“实现写明仅内存”代替运行观察；无需新增 TC。
