## 已闭环 R1：首次 Hub 管理操作所需的文档控制 epoch 取得路径

定位：`spec.md:110–122`，特别是 B8 最后一段；对应 A10 的旧 epoch 拒绝要求（152行）。

B8 已要求 Hub **所有**写操作（包括空库首次创建项目）绑定 HID、适用稳定项目身份及文档控制 epoch，但尚未说明用户/网页在首次写入之前从哪个只读操作取得当前 epoch，或它在何处与当前 HID 一起呈现。网页地址和凭据取得路径已有；B6 的列表给出稳定项目身份；B8 上传成功响应则列身份、版本和可检索状态。这些均未承诺返回文档控制 epoch。B5 的 recovery-status 返回的是确认恢复影响的 `state`，不能默认它就是正文管理 epoch；也不能要求先成功上传后才能取得首次创建所需值。

已有代码不能补出这项承诺：Hub `/v1/info` 当前只返回 protocol/HID/capabilities（`src/smm_hub/hub.py:198–200`），`hub status` 提供地址、凭据文件、运行身份等（`src/smm_hub/hub_admin.py:172–190`），没有007文档 epoch。005 的对话上传控制 epoch 属于另一控制域，B4/B5 又明确不得借007改变005协议，不能把它暗中当成007文档值。
