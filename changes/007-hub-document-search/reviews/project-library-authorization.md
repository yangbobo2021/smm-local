# 项目文档库补充的直接依据

来源：2026-11-23当前用户消息及异步答复。以下为原话，按先后记录；补充之前的意图/SPEC/PLAN及审查保留历史，不追改原意见。

> 文档处理的核心是验证检索确实可以检索到对应文档。文档也需要按项目来组织，所以对应也就需要新建项目，上传文档等。
>
> 这个是补充信息，避免对文档检索理解有误。对话项目与文档项目可以相互关联。

针对网页直接选择/拖入文件还是仅路径纳入的澄清，用户答复：

> 两种方式都支持。HUB在远程电脑，适合网页上传文档。本地适合明确本地目录，也可以网页上传。

其后用户明确同步选择的单位：

> 本机的文档项目是否同步，那是项目的选择，可以同步，也可以不同步。

这替换原先“按来源开关”的代理建议。文档项目的选择独立于对话上传；默认关闭、暂停保留/失效撤回、设备身份等未被撤销边界继续保留。

最后用户明确统一项目概念和创建端管理边界：

> 文档项目与对话项目，在项目概念上是一致的。
> 文档项目在本机创建，同步到HUB后，文档的管理（添加/删除/更新）只能在本机完成，不能在HUB上执行。
> 在HUB上创建的项目，也只能通过HUB来进行文档的管理，本机只能检索查询读取。

代理据此起草对应端Web、项目级同步、创建端写校验、公共Hub项目根及验收契约；具体接口/阈值细节仍属代理设计，不称为用户逐项亲自决定。补充SPEC经独立审查/PR合并，再修PLAN并经PR合并，之后才继续产品实现与验证。
