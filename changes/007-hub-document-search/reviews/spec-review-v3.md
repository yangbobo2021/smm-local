## 必要输入和前后状态

B2的 `smm documents upload <source_id> --enabled yes|no --expected-hub-id HID --expected-generation N` 现已明确必需HID和N，二者均来自upload-status刚显示的目标Hub身份及该来源generation；来源ID仍来自sources。Web直接绑定页面显示值，用户不需自行推算Hub身份。B5恢复后重选继续使用B2这条完整命令，因此其简述“取得generation后重新明确允许”不会取消必需的HID核对。

B2还明确：“提交同时绑定页面显示的Hub身份和generation；目标已切换或代次过期均拒绝”，CLI同样不能因新目标恰好同generation而接纳旧提交。故先查看H1/g0、切换H2/g0后提交旧H1/g0，两个入口均拒绝，不改H2选择。该结果具体落实B1的“选择作用于某个已绑定Hub身份……不自动转给新Hub”，没有新增无依据的授权范围。

同一已绑定、身份已知的目标网络离线，与目标未知是不同状态。B2表格仍明确“离线仍保存并显示未确认”，保存前核对的是所展示HID及本机generation，不要求以网络成功伪装为Hub确认；连接恢复后仍受B4每次请求核对Hub身份及代次规则约束。B2“未连接或尚未确认Hub身份时不允许将正文授权到未知目标”的对象是未知目标，不能据此取消表格对已知同目标离线保存的明确要求。因此已知H1离线可以保存待确认，未绑定/未知HID及切换到H2时不能借旧H1提交授权，前后契约一致。

A1已加入“目标切换且generation恰好相同”的动作前状态，并要求CLI/Web按B2拒绝或保存，区别本机保存与Hub确认。该条与B2明确结果结合可独立判定，不会只测普通代次过期而漏掉跨Hub碰撞。
