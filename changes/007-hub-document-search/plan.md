# 实施计划：Hub 文档同步与联合检索

依据：[SPEC](spec.md)及[用户项目文档库补充](reviews/project-library-authorization.md)（[PR #37](https://github.com/yangbobo2021/smm-local/pull/37) 已合并，merge `719ee9606e503bad4f8cda1fc8367a108c484173`）。原意图/SPEC/PLAN #34–36保留历史。本版落实B1–B8/A1–A10：统一项目、项目级文档同步、两端独立Web与创建端管理，替换原尚未实施的来源级开关。每阶段PR合并再进入下一阶段，不以缺环境缩减SPEC。

## 交付与停止点

本PLAN独立审查、提交PR并确认实际合并后，才修改测试/产品。实现阶段完成TDD、同版正式验收、独立需求判定及干净上下文PR Review；将代码、使用说明、脱敏证据和原样独立意见提交实现PR，等待其最终head CI通过、合并并读回MERGED后停止。不发布、不升级日常SMM，不纳入008–010，不连接真实VibeInsight/日常Hub或真实用户文档。

原工作区有未提交内容，所有修改在独立007 worktree；不重置或暂存原工作区。所有资料、token/证书、档案及服务均使用本任务独有目录/身份。独立Reviewer只写本轮意见，主Agent实施；保留失败/需修订及旧版本证据，不覆盖成passed。

## 实施顺序与阶段门

1. **建立需求与设计。** PLAN PR合并后创建/读回`AT-SMM-007`，冻结R007最新SPEC及SC1–SC10业务判据，逐原文核范围；保存自然语言TC设计、输入/动作前状态/完整期望及断言分配。运行条件探测绑定产品、公共夹具及启动/构建入口。正式业务开始前更新原生PLAN。
2. **先实现测试并取得红灯。** 新测试走现有可调用的CLI/API。新增能力TC逐项运行`tdd-red`；现有对话兼容另取`tdd-baseline`，不是预期失败。独立设计Reviewer同时核场景/设计/实际断言和红灯，仅业务缺失授expected_failure。错误预期/环境/测试故障先修订并重新取得原产品红灯，再改产品。
3. **实现共享存储与Hub发布。** 先完成纯协议、创建端归属、管理副本安全纳入/更新/删除、Hub命名空间和原子暂存/清单发布、原生来源与项目、epoch引用/保护/恢复；校验身份、摘要、来源/版本和完整清单。项目授权代次、项目/来源发布顺序与文件版本分开，较老文件不覆盖较新文件。Hub恢复先使旧引用/资格失效，再允许显式建立新资格。
4. **实现Local控制与同步。** 完成每目标/项目的默认关闭、稳定project_key+HID+generation CAS、保护文件、曾获准成员账本及适用回执；选择先落盘再尝试网络。来源移除保留撤回任务。暂停只保留/撤销已知成员，不发送新文件名单或正文；显式重新允许后补当前全量。网络期间不持数据库/控制锁，旧回执不确认新任务。
5. **接入联合查询与原文。** 扩展005签名共同范围支持显式Hub根，复用项目最小登记，精确映射本机集合；两端各取limit片段，在本机统一BM25/稳定身份排序。相同身份/版本双摘要合并引用，不同版本并列；原文沿精确引用核验并按实际端标注，不能换同号ID。覆盖/能力/错误独立，不假报0条为已查完。
6. **接入CLI/Web/MCP与后台。** 本机Web/CLI及独立Hub Web/API分别实现创建端管理，Hub网页凭据只在内存，另一端在后端拒绝写；同档案接入只读工具；旧页面绑定稳定项目、目标和代次，源变更/项目迁移记录待确认效果，自动周期只重试采集库。写好README/指南/Skill/维护复跑入口。保留明确local及006旧引用，旧对话行为不变。
7. **取得同版绿灯、回归和包。** 每TC沿用原红灯测试取得`tdd-green`及适用旧引用/资格回归，由另一独立Reviewer核对。执行完整pytest、双包构建/分环境安装。若有有效失败，先修产品，再重取受影响版本/场景；不为剩余时间跳过必要验证。
8. **提交候选并执行正式验收。** 先提交可追溯候选代码/测试/方法调整，创建实现草稿PR；按最终候选同版完成20自动TC及7人工TC、真实三平台/E2服务与跨机器。安装模块摘要必须等于候选源码；探针也冻结版本，失败重跑用新输出目录。正式执行由不同于准备阶段的Reviewer核对，逐就绪意见原样登记。
9. **完成独立交付审查与合并。** 新上下文Reviewer逐R007核完整SPEC、当前原件和场景结果；另在干净上下文使用当前`changes/_templates/pr-review.prompt.md`回放普通用户、Agent、Hub维护者入口并写结论/依据到PR。真实缺口返修后重验；通过后实际finish，提交脱敏副本/双SHA/覆盖索引和原样意见，等待最终head的三系统CI全部通过，合并实现PR并读回MERGED。此后停止。

## 用例设计与A1–A10验证对应

下列为27个独立TC的设计目标，具体输入和检查分配在原生case-design落盘；保留原24个TC身份，另增SC10三项；每个TC的各适用目标/动作前状态分别断言，不以只检查第一个文件或“两个错误结果相等”代替独立预期。

| 场景 / SPEC | 稳定TC（种类） | 怎样验证、什么算通过 |
|---|---|---|
| SC1 / A1 | `TC-007-policy-choice`（自动） | 两个新旧本机项目（各有多个来源/文件、分别成功与pending）及不同对话模式均默认文档off。公共CLI/API选择正确稳定KEY/HID/G后落盘/重启；旧G、换Hub同G、删除后数字ID复用、未知Hub和并发请求拒绝且新状态完整不变。共享源P允许/Q不允许只传P资格，未绑定不传；新资料继承已允许P；改名保留、合并不转移允许给目标。真实Web另由用户路径项实际提交过期页面，验证页面绑定值而非提交前重新抓取的新值。 |
| SC2 / A2 | `TC-007-sync-publication`（自动） | 两来源各多文件、不同项目/正文/换行；逐文件暂存中查询和read均不可得，完整提交后按独立全集核每份正文/长度/双SHA/版本/出处/项目；任一成员缺失/摘要不符不发布半份，其余来源仍可用。 |
| SC2 / A2 | `TC-007-sync-retry`（自动） | 请求已接收但客户端丢回执、重复文件/清单、重建客户端/Hub对象及进程中断后补齐；逐身份验证唯一文件、相同回执/版本/连续资格，不能仅比总数量。 |
| SC2 / A2 | `TC-007-sync-boundaries`（自动） | 实际2MiB规范化文本及+1、16MiB编码请求体及+1（合法JSON可用尾部空白填充到边界）、非法类型/摘要/未知或重复冲突成员逐一验证拒绝和不变状态；多份正常文件完整，不静默截断。006原始字节/1000候选/16MiB来源预算保留原测试，并走Hub原生适用入口。 |

| SC3 / A3 | `TC-007-overlap-publication`（自动） | S1/P/v1→S2/Q/v2，再S2暂停/撤回、S1继续更新/退出；在P/Q/all逐完整结果和同旧ref核当前版本/连续资格及历史采集者；既有另一连续来源可保留，最后来源退出无查询/read，不回退旧正文。 |
| SC4 / A4 | `TC-007-origin-identity`（自动） | 两设备同名/同路径/同字节独立；同设备重叠同文件去重；另一合法身份与非法域值分别验证，正负控并存；同身份同版本异文/同提交异载荷拒绝且状态不改。 |
| SC4 / A4 | `TC-007-ordering-concurrency`（自动） | 用真实线程/事务屏障让旧授权、旧清单、旧文件版本及旧回执在新配置/暂停/撤回之后晚到；逐正文/项目/代次/任务完整快照验证旧操作被拒绝或不覆盖，且正常新操作成功。 |
| SC4 / A4 | `TC-007-recovery-controls`（自动） | 独立DB备份与控制保护形成真实回退/缺失/损坏，分别核Local不发正文、Hub不发布/查询/read；recovery-status取得state，过期state不得复位新状态；明确recover后旧Hubref永拒绝、自有pending、设备旧允许不自动生效；显式refresh/重新选择后新资格和准确文本恢复。对话/005数据前后不变。 |
| SC5 / A5 | `TC-007-hub-native`（自动） | 通过实际Hub CLI在同state-dir新建来源、pending/refresh/set/失败/排除/remove，两个来源各独立原文及负控；列表区分导入/自有，对导入ID误refresh/remove明确拒绝且不访问设备路径。单测证明不隐式读源，真实平台再取原生文件结果。 |
| SC5 / A5,A6 | `TC-007-project-scope`（自动） | Hub普通/全局独立创建、零/多绑定、同名项目、A-B/B-C一层与共享不建关联；Local和Hub各从全新仅文档D起步，关联仅对话C，从C真实文档工具命中D逐文件原文，从D对话工具命中C准确会话/轮次；未关联/第二层负控排除。本机改名/合并/路径映射后按独立完整范围及每份命中资格核对，旧项目绑定不扩大查询。 |
