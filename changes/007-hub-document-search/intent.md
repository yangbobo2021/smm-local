# 意图：在汇总端检索和同步文档，供多台电脑读取相关原文

状态：2026-11-23 维护者确认首版范围及下列四项边界，并授权按阶段 PR 推进 SPEC、PLAN、实现与验收。技术细节由代理起草、独立审查及阶段 PR 记录，不写成维护者逐项亲自决定。

父意图：[项目知识检索与内容上传控制](../004-project-knowledge/intent.md)。承接[本机文档检索](../006-local-document-search/intent.md)，与[对话上传选择](../005-selective-conversation-upload/intent.md)协调内容上传边界，由[常用格式](../008-document-format-support/intent.md)扩展格式范围。进度见[父目录导航](../004-project-knowledge/README.md)。

## 现有问题

Hub 已提供多台设备和 VibeInsight 对话的汇总检索，但公开使用路径尚未覆盖文档。用户在另一台电脑上处理项目时，无法通过现有文档入口取得已获准汇总的文件内容和原文位置。

即使先按 006 提供本机文档能力，也仍需明确哪些文档可以进入 Hub、文档更新后其他设备何时可查，以及停止同步后汇总副本如何处理。

## 受影响的用户

希望跨设备检索项目文档的本机使用者，以及负责 Hub 内容来源、项目关系和同步状态的维护者。

## 期望结果

- 用户能创建项目、纳入或网页上传文档，按项目检索到正确文件并读回原文；本机项目可选择同步后由其他电脑读取。文档与对话使用相同项目概念，可双向关联并从任一根检索相关资料。
- 结果能够区分文档来自哪台设备或哪个汇总端来源，并说明所属项目、内容位置及版本或采集状态。
- 获准同步的文档更新后，Hub 中的结果与原文能够保持可理解的一致状态；断线恢复或重复同步不会让用户误读重复副本或错误版本。
- 用户能够理解文档尚未进入 Hub、同步失败、停止继续同步及已有副本保留等不同状态。
- Hub 维护者也能明确纳入 Hub 所在电脑上的文件或目录，并让已连接的其他电脑检索和读回采集原文。

## 范围与约束

- 承接 006 的文档来源表示和原文定位能力，在明确的格式范围内扩展到 Hub；008 后续增加格式支持。
- 文档的上传选择需明确表达，不能直接把 005 中对话是否上传的选择当作文档的默认授权。
- 文档与项目的归属及 Hub 的直接关联检索分别说明。跨设备读取仍应遵守实际生效的项目范围，并保留现有对话查询和 Hub 不可用时的使用路径。
- 文档已上传到 Hub 时，原文读取所需内容的保存范围和失效行为必须明确，不能仅给出另一台电脑无法访问的本机路径。
- 资料由使用者或维护者明确纳入，沿用当前单用户使用方式；本项不新增成员权限体系。
- 共用入口及资料组织问题见[父意图](../004-project-knowledge/intent.md#待确认问题)。

## 已确认的首版边界

1. 同时支持本机明确选择的文档上传和 Hub 自己管理的文件/目录；只承接 006 的 Markdown、严格 UTF-8 文本，不增加外部资料抓取或其他文件格式。
2. 上传按本机文档项目单独开关，默认关闭，不继承对话上传授权。因此项目对话不上传时，用户仍能明确选择同步该项目的文档资料；连接 Hub 本身不授权上传文档正文或文件清单。
3. 暂停上传保留 Hub 已有采集快照并继续可查；暂停不代表撤回。移除来源，或明确刷新发现文件删除/失效时，撤回该来源对材料的 Hub 检索及原文资格。离线时明确显示撤回待 Hub 确认；其他有效重叠来源不受影响。恢复上传后补齐当前应有内容，断线与重试不复活已经撤回的旧资格。
4. 不同设备的同名或相同内容文件保留独立身份及版本，不能凭路径或字节相同自动视为同一文档。同一设备中重叠来源按 006 的文件身份合并，保留各来源资格；来自本机和 Hub 的同源副本与不同版本必须可区分。

5. 本机支持明确本地目录和网页文件上传，Hub支持网页文件上传及维护者纳入本端路径。资料保存在对应创建端的项目文档库。
6. 项目创建端拥有文档添加/删除/更新权：本机创建项目仅在本机管理，Hub同步投影只读；Hub创建项目仅在Hub管理，本机只检索/读取。关联不转移管理权。最新补充原话见[记录](reviews/project-library-authorization.md)。
