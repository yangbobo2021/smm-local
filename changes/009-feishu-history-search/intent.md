# 意图：在本机检索获授权的飞书聊天历史，并读取消息原文

状态：草稿，待维护者确认。

父意图：[项目知识检索与内容上传控制](../004-project-knowledge/intent.md)。与[本机文档检索](../006-local-document-search/intent.md)协调新增内容的检索路径，为[飞书长对话与关联内容理解](../010-feishu-context-understanding/intent.md)提供聊天记录。进度见[父目录导航](../004-project-knowledge/README.md)。

## 现有问题

用户希望把飞书中已有的项目沟通纳入 SMM，检索讨论内容并回到对应消息。SMM 0.4.0 的公开来源配置没有现成的飞书聊天接入路径，用户仍需到飞书另行寻找历史。

飞书聊天具有会话、发送者、时间和回复关系。历史可能跨越较长时间，能否读取哪些会话及多早的记录还取决于实际读取方式和授权范围，尚需调研确认。

## 受影响的用户

希望在本机检索本人获授权读取的飞书聊天的使用者，以及通过 SMM 获取项目沟通原始依据的 Agent。

## 期望结果

- 用户能明确选择读取方式允许纳入的会话和历史范围，了解实际可读取、已获取及尚未完成的范围。
- 已纳入的消息可在本机检索，结果能识别所属会话、发送者、时间和原消息，保留基本回复关系。
- 再次更新能够取得范围内的新消息；重复获取和中断续跑不会造成用户以为历史完整、实际却遗漏或重复的结果。
- 命中消息能够读回原文及基本关联上下文，并可按后续确认的归属方式进入项目检索。
- 用户能理解采集状态、授权失效，以及消息编辑或撤回后本机记录的含义和处理边界。

## 范围与约束

- 本项覆盖本机端飞书聊天的取得、归档、检索和原消息读取。会话类型及历史可读范围以真实调研后确认的范围为准。
- 完整取得已承诺历史范围所需的分页、去重和中断继续属于本项，不推迟到长对话理解阶段。
- 长讨论的进一步上下文组织，以及附件、图片、消息中飞书文档的内容处理由 010 承接。现阶段结果须如实说明这些内容是否已纳入。
- 本项可独立推进，不以通用文档能力全部交付为前提；新增检索入口与其他来源的关系需协调一致。
- 飞书内容首先留在本机归档和检索，本子意图不增加飞书聊天进入 Hub 的目标。现有 Agent 对话归档、检索及同步行为继续可用。
- 共用入口及资料组织问题见[父意图](../004-project-knowledge/intent.md#待确认问题)。读取协议、凭据保管、同步边界及具体验收条件留给 SPEC。

## 待确认问题

1. 首版使用哪种获授权的读取方式，实际能覆盖哪些单聊、群聊或话题，以及多早的历史？须先以真实条件调研，结果决定承诺范围；不能由“能够登录飞书”推断可获取全部历史。
2. 首版更新由用户明确触发，还是需要后台持续同步？该选择影响运行方式、授权续期和状态展示。
3. 消息编辑、撤回或会话读取权限失效后，已保存原文是否保留，如何提示其采集时间及当前状态？该选择影响历史保留与引用。
4. 会话与项目的归属先按整个会话配置，还是首版就需要按话题、时间范围或选定消息配置？该选择影响跨项目群聊的检索范围。
