# 意图：理解飞书长对话及其附件、图片和文档，并定位原始依据

状态：草稿，待维护者确认。

父意图：[项目知识检索与内容上传控制](../004-project-knowledge/intent.md)。承接[飞书聊天历史检索](../009-feishu-history-search/intent.md)及[常用文档格式支持](../008-document-format-support/intent.md)。进度见[父目录导航](../004-project-knowledge/README.md)。

## 现有问题

009 的目标是让用户取得并检索飞书聊天消息。用户进一步理解长期讨论时，相关依据可能分布在多个时段和回复中，也可能保存在聊天附件、图片或消息引用的飞书文档里。只读一条命中消息，仍不足以回答“为何这样决定”“这张图说明什么”或“附件中的约定是什么”。

这些内容与原消息存在关系，且读取授权、内容版本和处理状态可能不同。需要让用户知道哪些材料已被理解，哪些只有链接或仍不可读取。

## 受影响的用户

希望从飞书长讨论和相关材料中获得完整背景的本机使用者，以及需要组织上下文、解释图片或文件并引用依据的 Agent。

## 期望结果

- 从一个检索命中出发，用户能够找到与问题相关的前后讨论和回复，按需展开原文，保留发送者、时间和讨论关系。
- 在获准且可读取的范围内，聊天附件的内容可被检索和理解，并能追溯到发送该附件的消息与文件来源。
- 图片中的相关内容可以按已确认的理解范围参与检索和说明，并保留原图及所属消息，便于核对。
- 消息引用的飞书文档在获准读取后，可提供与讨论相关的内容及文档位置，并说明读取到的版本或采集状态。
- 用户能区分原消息、原文件内容及据此生成的解释；部分材料不可读取或处理失败时，仍能判断本次依据是否充分。

## 范围与约束

- 本项覆盖本机飞书场景，依赖 009 的消息获取、稳定引用及基本回复关系，复用 008 已确认的通用文件和图片内容支持。
- 长对话处理关注检索后的上下文获取、阅读与理解；009 对其承诺历史范围的完整获取仍由 009 负责。
- 文件和通用图片处理范围在 008 中维护；本项增加飞书资源获取、消息关联及上下文使用。需要扩展通用能力时，应同步确认受影响子意图的范围。
- 能读取聊天消息，不代表相关文件或文档已被读取。资源是否获准、是否取得内容、是否完整处理需分别可理解。
- 跨时段讨论和派生说明保留到原始依据的定位关系，不能把生成的解释或缺失的材料当作原文。
- 共用处理位置、资料归属和入口问题见[父意图](../004-project-knowledge/intent.md#待确认问题)。本意图不预定长对话切分方式、摘要策略、模型或云文档接口。

## 待确认问题

1. 长对话首版需要达到怎样的帮助程度：按需展开相关消息和回复，还是还需要跨时段归纳、讨论脉络或摘要？后者增加派生内容与质量判断的范围。
2. 附件是否只处理被明确选择或当前问题涉及的文件，还是自动纳入所选会话范围内的全部可读附件？该选择影响读取范围、历史回填和资源消耗。
3. 图片需要覆盖文字、截图、图表或流程图中的哪些信息？应与 008 确认的通用能力对齐，避免两个入口对同类图片作出不同承诺。
4. 消息中的飞书文档首版覆盖哪些文档类型、是否跟随其更新、是否继续读取文档内引用的其他资源？该选择影响授权范围、资料边界和原文版本定位。
