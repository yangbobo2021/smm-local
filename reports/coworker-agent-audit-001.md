# 新 Codex 会话实答的事后污染审计

审计日期：2026-10-29。原始事件日志保留在开发机 `/tmp/smm-coworker-codex-L1.jsonl`、`L2.jsonl`、`L3.jsonl`；其中包含个人历史对话，不上传。原题和期望来源在 [冻结用例](coworker-live-cases.json) 中。此审计保留原有 3 次实答，不删除或改写日志。

| 用例 | 最终答案与原文 | 实际检索路径 | 能证明什么 |
| --- | --- | --- | --- |
| L1 删除源会话 | 正确引用原用户消息 `205:79585` | 项目范围的 3 次 `search_conversations` 都没有返回 205；返回的旧测试对话 3432 的助手消息已明确写出 `205:79585` 和答案；随后 `read_conversation(205,79585,79585)` | 能按已知位置读取、核对原文；不能证明独立找回目标会话 |
| L2 项目关联 | 正确区分用户原话 `205:79530/79544` 与后续助手提案 | 先前旧测试对话 3432 已披露 `205:79544`；后续全局搜索虽返回 205，但展示的命中消息位置不是 79544；随后读取 `205:79500–79600` | 能核对原文；检索路径受旧答案污染，不能作为独立召回成功 |
| L3 Claude 来源标记 | 正确引用 Claude 原消息 `3460:278` | 首个 `limit=100` 请求超出服务上限而失败；调整为 `limit=50` 后，`MEM_` 搜索把 3460 排第 1，随后读取原文 | 证明跨来源检索与读取能完成这个精确标记任务；题目是合成标记，不能代表一般工作问题 |

三题均在问题里明确要求“查过去原始对话”，因此没有验证自然任务中 Agent 是否会主动调用 SMM。L1/L2 的依据都来自同一段原始大对话 205，题目覆盖面很窄；也没有不使用 SMM 的对照组。更准确的结论是：**三题最终回答正确，原文读取链路有效；检索独立性、常态主动使用和第三方收益未被证明。**

还发现搜索结果展示过大：事件日志中 SMM 工具的 `content` 文本约 L1 2.98 万、L2 200.7 万、L3 65.1 万字符；L2 调用了 10 次搜索和 1 次读取。当前 `search` 对每个命中对话返回最多 3 条**完整**消息，长消息和重复搜索使上下文成本很高。`turn.completed` 分别报告 171,886、378,468、207,445 个输入 token（其中大量为缓存 token）；这不是 SMM 的独立服务费用，但属于 Agent 使用这套工具时的实际上下文负担。

后续独立验收需要从未被测试总结提及的原始对话抽题，隔离或排除先前测试会话，冻结问题与证据后运行；每题分别记录目标是否进入候选、Agent 是否打开原文、答案是否正确、工具输出字符数和 token。另设不提示工具的自然任务及无 SMM 对照。正式对外效果数字须来自这样的测试和同事自己的问题。
