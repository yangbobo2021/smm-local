# 搜索预览收缩：一次可回退的验证

## 结论

SMM 的过大输出主要来自搜索卡片。将每条命中消息限制为 600 字预览，在冻结的 205 次真实搜索请求上**没有改变会话排序、BM25 分数或命中消息位置**，序列化返回量从 130.4 MB 降到 6.52 MB。完整原文仍由 `read_conversation` 按位置读取。

这项节流尚不适合默认开启。在一轮 10 道由真实历史材料构造的问题的 Agent 对照中，3 题存在题意、时序或评分要点问题；其余 7 题包含 5 道有据题和 2 道无据题，完整展示分别答对 4/5、2/2，600 字预览分别答对 3/5、2/2。差的一题是预览组回答了价值展示和入门路径，却漏说测试集应如何简述。该题的关键用户消息只有 224 字，**短预览未截断，Agent 也读取了完整原文**；相关的短 AI 回复同样未截断。两条较早的长 AI 回复被截短，但现有证据不能把漏答归因于它们。单次模型输出也可能波动；本轮不能证明回答质量不受影响。因此默认继续返回完整搜索消息；使用者可在 MCP 服务进程设置 `SMM_SEARCH_PREVIEW_CHARS=600` 试用短预览，设置 `0` 恢复完整展示。

## 固定输入与验证

| 检查 | 完整展示 | 600 字预览 |
|---|---:|---:|
| 205 次历史搜索请求的排序、分数、位置 | 基准 | 全部相同 |
| 205 次序列化返回量 | 130,448,317 字节 | 6,519,796 字节 |
| 10 道 Agent 题中可判定题完整答对 | 6/7 | 5/7 |
| 其中未在先前无效试跑完成过、可判定的题 | 5/6 | 4/6 |
| 两道无依据题正确停下 | 2/2 | 2/2 |
| 10 题工具返回字符总量 | 51,242,816 | 2,833,272 |
| 10 题输入 Token（含缓存） | 3,807,741 | 2,775,300 |
| 10 题中位耗时 | 47.03 秒 | 41.59 秒 |

同一份隔离档案包含 89 段真实历史会话、3070 条可见消息。题目、原始消息哈希、模型 GPT-6 Luna／high、提示词、运行顺序和评分口径在正式调用前固定。两组各运行一次、无服务错误；检查了 20 个回执、模型档位、工具参数、来源哈希和原始文件读取行为。模型实际搜索次数不同（完整组 104 次，预览组 89 次），因此耗时与 Token 差异是**整条 Agent 路径的观察值**，不能当成单次检索的性能收益。10 道题中有 8 道有据题和 2 道无据题；有据题集中于少数历史会话，不能代表其他用户。

先前试跑发现 MCP 工具允许 Agent 自行把预览长度设为零，导致两组输入失去隔离。该试跑留在本机，不进入上表。正式版移除了 Agent 可调用的长度参数，由服务端配置固定；上述“未在先前无效试跑完成过”的 6 题不含该试跑前三题。人工复核把 3 题单列：一题后来更新了覆盖率问题的事实，一题后来真的完成了此前暂缓的安装验证，一题冻结要点要求复述题干前提而题目只问是否执行用例。没有改写原始金标准或按结果重跑。

本机留存 `preview-001/` 的冻结题目、两版协议、无效试跑收据、20 次完整输入／输出、逐题审阅、确定性回放和机械核验。历史内容可能含个人及项目资料，未上传公开仓库。该对照由一名审阅者判定，不是盲审；结果仅支持保守地保留默认完整展示，并继续研究更可靠的短卡片形式。
