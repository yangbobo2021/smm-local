# 文档对照检查范围

以下在生成前固定，仅供比较者使用，不提供给生成模型。比较对象为 PR #21 当前规格与一次真实资料生成的新草稿。

1. 是否明确 Hub 与本机端各自的操作系统支持范围，区分组件而非只出现操作系统名称。
2. Hub 的 Windows LocalService、Linux systemd 用户服务、macOS launchd 服务是否分别有实际运行验收要求。
   macOS 是系统级 launchd 注册，但服务按配置的普通管理员用户运行，不能误说以 root 运行。
3. 来源访问是否由实际 Hub 服务身份调用外部 `psql`，凭据可读及受限访问是否对应各平台，而非只看交互式 CLI 成功。
4. 保存配置后重启、原会话追加、归档/进度保留、失败恢复及去重等结果是否明确归属相应运行环境。
5. Windows/Linux/macOS 本机端是否分别覆盖 CLI 与 MCP 新的项目查询和命中引用读取，不能仅列补传或旧兼容。
6. 是否区分必要平台集成证据与可复用共用逻辑证据，避免要求所有系统组合及全部算法测试机械重复。
7. 是否在 SPEC 确定覆盖和充分性，将机器、命令、具体步骤留给 PLAN；不以“未验证”代替必需证据。
8. 原七项功能条件及后来确认的仓库身份边界是否保留，是否无意增加功能或验收承诺；新增决定须列为草稿变化供确认。

本检查只判断规格文本写了什么，不宣称任何平台的产品已经运行通过。
输入含对已确认需求和设计的整理，且这是历史文档对照，不将差异归因为严格控制其他变量后的模板单一因果效果。
