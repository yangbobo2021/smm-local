# SMM 参考信息效用对照验收计划

制定日期：2026-10-29。状态：**方案已定义，尚未执行；不能据此宣称 SMM 提高了回答质量或优于同类工具。**

## 要回答的两个问题

1. 同一个 Agent 面对同一历史信息任务，启用 SMM 后，是否比不启用 SMM 更容易给出有正确历史依据的答案？
2. 面对同一批来源、任务、模型和资源限制，SMM 与可本地运行的同类对话检索工具相比，找依据、帮助回答、耗时及上下文成本有什么差异？

这两项是产品效用验收，不能由安装成功、MCP 已连接、搜索返回结果或三题演示代替。

## 测试资料与冻结

- 从至少三位真实使用者的 Codex/Claude Code 历史中，按项目和时间抽取不少于 60 道**未用于开发调参**的题；每人至少 15 道。分层包含单段对话、多段对话合并、较新信息推翻旧信息、跨 Agent 来源、查无依据五类。报告逐类分母，不只报总均值。
- 出题人先固定问题、任务发生时点、可接受答案、所有必要原文位置和证据充分条件，再运行任何方案。另一人抽查标签；有歧义的题保留并单列，不按系统成绩修改标签。
- 实验档案隔离开发测试会话、答案总结、题目文本和旧实验日志。每种方案只导入同一时间截点以前的原始来源。正式运行前检查题目与答案是否已在索引里泄露；发现泄露则整题隔离，并记录原因。
- 保留不可公开的原文与完整调用记录在使用者本机；可共享的记录仅含脱敏题目、来源哈希/位置、判定与统计。未取得使用者授权不上传历史对话。

## 对照一：不用 SMM 与使用 SMM

同一题在独立新会话各运行一次；固定 Agent、模型版本、思考档位、提示词、工作目录、可用时长和上下文预算，并随机化两种条件的执行顺序。两组都允许 Agent 使用其**默认内置的历史能力与本地文件工具**；实验组额外安装 SMM，基线组不安装 SMM。自然任务提示不点名 SMM，也不提供目标会话 ID、关键词或答案。另做一组显式要求“查过去记录”的诊断题，结果分开报告。

每题按同一条链路核查：Agent 是否尝试找历史 → 必需来源是否进入候选 → 是否打开相应原文 → 最终答案是否正确且被原文支持。没有足够证据时，明确报告“不知道”优于编造；但在有证据的题上过早放弃计为失败。盲审人员只看匿名化的答案和引用，先判断答案，后揭示组别和工具轨迹。

主指标是**有证据支持的正确回答率**，以题为分母。并报配对胜/负/平（SMM 正确而基线错误、反之、两者相同），至少一个必要来源命中率、全部必要来源取齐率、错误引用率、主动调用率、总耗时、模型 token、工具输出字符数。置信区间用以使用者为聚类单位的配对 bootstrap；只有个别题的分数不外推为普遍效果。

试用价值门槛：在冻结的有效题上，SMM 的配对胜题数必须多于负题数，有证据正确率必须高于无 SMM 基线；任何严重的错误引用或跨项目泄露均逐例复核并阻断对外效果宣称。若样本不足以排除偶然波动，只能宣称“观察到改善”，不能宣称稳定提升。

## 对照二：SMM 与同类工具

首个直接对照选 [Crispy Recall](https://github.com/TheSylvester/crispy-recall)：它同样索引本地 Codex/Claude Code 原始会话，提供关键词/语义搜索和按 ID 读取。第二个候选是 [agent-session-search](https://github.com/benvenker/agent-session-search)，在核对当前版本能否导入同一来源、按同一任务给 Agent 读取后纳入。抽取型记忆产品应另列类别，不能以“没返回整段原文”直接判其失败。冻结具体 Git commit、安装配置、索引参数与导入成功数；不能把同一产品的不同版本混在结果里。

每种工具使用相同原始会话副本、项目范围和时间截点，均按官方推荐方式建索引并接入同一 Agent/模型。允许各工具自身的正常索引、查询改写和二次读取能力，不要求它们输出相同字段；限制相同的总耗时和模型上下文预算。若某工具无法覆盖同一资料，先报告导入覆盖率和不可比原因，不把未导入文档记成检索错误，也不从比较中悄悄删除难题。

结果分两层：① 固定问题的工具检索层，报告 Top1/5/10 中至少一个及全部必要原文来源的命中、错误候选、索引耗时和存储量；② Agent 端到端层，按与对照一相同的有证据正确率、误引、放弃、耗时和 token 统计。工具输出样式和 Agent 自主选查询策略都是产品的一部分，端到端结果不能被单独的 Top5 替代。逐题公布匿名化的胜负与失败原因，不能只比较平均分。

试用竞争门槛：至少完成一个直接同类工具的同条件对照，SMM 不应在有证据正确率或严重误引上出现未解释的明显劣势。若对手更好，报告具体差距和适用情境；可以仍作为研究版试用，但不能宣称效果相当或更好。

## 执行与报告边界

先用每类各一题做**流程校验**，确认数据、引用、盲审和日志可复核；流程题不计入正式结果。随后冻结正式题集并一次跑完，失败收据保留，不按成绩重抽题或改提示词。两个 Agent 若都能运行，按 Agent 分层报告；当前 Claude Code 模型鉴权未通过，不以 Codex 结果替代 Claude Code 结论。

最终报告应提供每题两组/多组的匿名答案、引用原文位置、判断理由、检索及读取轨迹、模型与工具版本、资源消耗、未解决错误和总体置信区间。报告明确区分“检索命中”“Agent 读了证据”“回答正确”，并写明对照是否足以支持交付及第三方效果主张。
