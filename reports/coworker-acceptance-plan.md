# SMM 同事试用版验收计划

制定日期：2026-10-29。目的：交付**可发给公司同事自行试用**的本地版本。验收对象是产品与分发包，不是当前开发者电脑上已有的安装。先冻结本计划，再执行和记录每项结果。

## 交付口径

同事获取代码或发行包后，在一台已安装 Python 3.11+、Codex CLI 或 Claude Code CLI 的 macOS 电脑上，按照一页说明完成安装，打开本地页面，看到 Codex 与 Claude Code 历史导入进度，随后在任一 Agent 的新会话中检索两种来源并读到引用原文。只安装其中一种 Agent 的电脑也能使用已安装的来源。卸载服务和 Skill 不删除历史档案。

“对同事有帮助”采用可观察的代理指标：给 Agent 一个需要过去对话才能回答的问题，它应主动检索、引用正确来源和消息位置、回答与原文一致；找不到时应明确说明。真实同事的长期收益需要小范围试用反馈，不能由开发者的样本代替。

## 验收矩阵

| ID | 场景与输入 | 必须通过的标准 | 证据 |
| --- | --- | --- | --- |
| A01 | 在**干净用户目录**从发行包安装，且包位于任意绝对路径 | 一条安装命令完成虚拟环境、Skill、可用 Agent 的 MCP 注册与本地服务；诊断显示每一项实际状态，无开发者路径；重复安装幂等 | 完整命令、退出码、安装清单、诊断 JSON、服务健康响应 |
| A02 | 同一知识库导入 Codex 与 Claude Code 样本 | 两种来源均保留 `source/session/cwd/time/role/text/position`，不混淆同名会话；Claude 的工具结果和思考不成为可检索对话 | 隔离 JSONL 样本、数据库查询断言、来源计数 |
| A03 | 两种来源分别追加、重复同步、出现半行、删除来源 | 只加入完整新消息、无重复；半行暂缓并可恢复；删除后仍能读取和搜索原始可见文本 | 每次同步回执、原文哈希与前后计数 |
| A04 | 同一项目含两种 Agent 对话，另有直接关联项目与无关项目 | 项目范围只含本项目及一跳关联；全局可见全部；结果保留来源身份与命中位置 | 冻结的期望 ID、Top5 列表、项目范围与读取回执 |
| A05 | Web 页面从空库到导入完成，操作项目、搜索和原文 | 新用户看得懂下一步；导入进度、来源错误、项目范围和原文均可见；配置和错误可操作 | 实际浏览器关键状态截图与 HTTP 回执 |
| A06 | **新 Codex 会话**问 3 个需历史信息的问题 | 自动或显式调用 Skill/MCP；每题能找到需要的原文并给出正确引用；无来源时不编造；无审批死路 | 会话事件摘要、工具状态、人工核对的答案与来源 |
| A07 | **新 Claude Code 会话**问相同类型的 3 题，包括一题引用 Codex 来源 | Skill/MCP 可用；每题能找到原文并给正确引用；无来源时不编造 | 新会话事件摘要、工具状态、人工核对 |
| A08 | 把安装包迁移到另一绝对路径，并执行诊断/重新安装 | 安装配置指向新路径；Skill 不含开发者个人路径；两种 Agent 的 MCP 命令正确，能查询同一档案 | 移动前后路径、配置摘要和查询回执 |
| A09 | 安装包和本机服务隐私检查 | 发行包不含对话、数据库、密钥；服务仅监听 `127.0.0.1`；卸载不删除数据库，明确说明数据位置 | 文件清单与凭证扫描、监听地址、卸载前后档案哈希 |

## 冻结的判断规则

- A02–A04 使用程序构造但贴近真实格式的对话，判断规则在执行前写入测试；不能按检索结果修改预期。
- A06–A07 使用已知原文位置的真实历史问题；在 Agent 执行前冻结题目与期望证据；原文中的用户陈述和助手猜测分开判断。每题记录“Skill 是否加载 → MCP 是否调用 → 来源是否找到 → 答案是否正确”，不能用最后一句正确掩盖前面的失败。
- 同事试用版的门槛是 A01–A09 都有执行证据，核心功能没有未解决的阻断；失败可修复后重跑，但原失败记录必须保留。单机通过仍只表示**可供试用**，不表示已证明各种历史问题的普遍召回率。
- 真实同事试用应让至少两位非开发者按说明独立安装，各完成一个自身历史问题和一个跨 Agent 检索任务，再记录卡点与价值反馈。此项需要同事参与，不能由本机自动验收冒充。
