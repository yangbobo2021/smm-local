## 固定验收

- 实际来源的第二页才返回未授权会话时，固定入口拒绝注册，来源未登记且服务未启动。已注册受限来源的后续批次若包含越界会话，整批拒绝，去掉越界记录可从原进度继续。
- ZCode 固定 SQLite 样本覆盖仅带语义标记的系统事件、仅模型可见记录、首条用户原文的授权判定、同一行从空回复变为完成以及重复轮询。回归候选故意卡在系统行、越过未写完回复、错误按后续前缀授权或只对实际库放开过滤时，固定验收分别拒绝。
- 已登记且未带授权配置的旧版本可继续使用，若要启用本轮新增的范围检查，须用独立授权样本重新验收并注册。范围检查约束提交给档案的消息，生成的脚本仍使用本机账户的执行权限。

三个隔离档案均只包含授权种子会话和前缀命中的测试对话，样本与授权文件的摘要通过前后核对。三端的最终新对话均由两个后台批次导入提问和回复，并由独立 ZCode 搜索任务读回。全程没有手动同步。

Windows 先自行修正了 SQLite 调用、会话游标、空回复前的进度提交和真实快照的可选字段。首次注册命令省略隔离档案，测试方拒绝，随后仅向 ZCode 重申原先的隔离档案路径。续接任务注册的是同一份候选，摘要与首轮成功验收相同。一个可能回退到默认档案的可选状态命令也被拒绝，服务就绪、保活、原文由隔离档案实测核对。

Ubuntu 第一次的适配器从消息 JSON 取 ID，真实新会话只在 SQLite 列中存 ID，导致它没有取得首条用户原文。当前固定样本的消息 JSON 带有内嵌 ID，因此首次验收未发现这处差异。ZCode 收到未入档这一结果后自行定位并修正。Ubuntu 验收使用官方 app-server，桌面界面未覆盖。

macOS 自行从 Python 隔离参数和样本输出目录用法的失败中恢复。Windows 自行从 Windows 命令行的语法差异中恢复。Windows 和 Ubuntu 的搜索任务都曾给 `read` 加上不受支持的 `--local`，收到错误后自行重试成功。

本机回归 19 项通过，1 项 Windows 专用用例跳过。Windows 服务启动回归 2 项通过。`spex lint` 无错误，保留两条已有警告。
